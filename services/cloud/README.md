# blockcolc 账户服务

Node 24 LTS，使用内置 HTTPS、密码派生和 SQLite。领域验证直接构建自本仓库的 TS 领域模块。Android 的同步适配器位于 `apps/native-android/platform-cloud`；页面与计时业务仍通过现有原生写入队列保存。

## 本地验证

在本目录执行 `npm test`。测试使用临时目录、合成账号和模拟转发目标，退出后清理。HTTP 工厂仅供回环测试；生产入口要求明确的数据目录、TLS 证书和密钥。

`node tools/build.mjs` 生成可重建的 `build/domain.mjs`。`python tools/deploy.py` 部署独立 systemd 服务及带 IP SAN 的 HTTPS 证书，不占用现有 443。私钥和部署包在工作区的忽略目录中，公开源码只包含客户端使用的 CA 公钥。

当前部署使用 8443。服务器安全组还需允许该端口；服务内部 HTTPS 成功不能代替公网可达性。`tools/test-proxy.py` 是只监听电脑回环地址的实验桥，需要独立 SSH 转发；不随 App 打包，也不跳过 TLS 校验。

## 数据与恢复

- `/var/lib/blockcolc-cloud`：按账号隔离的 SQLite 与蓝图内容块。服务身份独占写入；登录令牌只存哈希。
- 实时工作区保存逐项版本；更新携带原值摘要、工作区代次与稳定请求 ID。不同项可以合并，同项冲突保持显式选择。
- 一个账号只有一个计划执行设备。查看端不能提交计时结果；接管换代，离线旧端重新连接后必须处理冲突。
- 每日根和实时工作区分开。每日根先校验再事务换入，内容块去重，稳定时只留一份；主动恢复更换工作区代次，不恢复本机提醒或自动继续许可。
- 导入蓝图可同步；材质包和音频原件、登录凭据、天气配置、位置及派生缓存不上传。缺失素材的本机回退不改变共享选择。
- 好友需邀请确认。状态、任务名、起止时间及每日时长分别授权，服务端只返回获准投影。

Android 的网络队列与本地保存分开。每次请求除连接／读超时外，还有 120 秒总期限，连续少量返回也不会无限占住同步队列；失败保留本地内容及上一完整云恢复点。网络较慢时可能需要重试，本版未加入单内容块内续传或并行上传。

运维级磁盘备份另需保存整个私有数据目录和部署 CA；单用户的每日根不能代替服务器灾难恢复。服务更新保留旧 release 目录及上一份转发配置，可切回旧 release 后重启同一服务。

## 旧好友服务交接

旧好友转发只为指定的 Dieight 账号维护，不是账户页面上的选项。实际用户注册后，运维将其固定 UUID 绑定至受保护的目标配置；不按用户自己填写的名称开放绑定接口。目标配置包括 `url`、`token`、`enrolledDate`；交接时另填 `sourceEpoch`、`previousSourceEpoch` 及可选的一次性 `initialHistoryCount`，不写入 Git，不通过命令行传令牌。

先用 `python tools/bind-forwarding.py --account <UUID> --configuration <私有 JSON 路径>` 检查，再加 `--apply` 保存已获用户授权的绑定。工具保留上一份配置并重启本服务，绑定按默认个人转发处理；公开只读兼容账号不能用作上传者。交接时核对完整资料、保留原日统计并切换来源代次，防止旧客户端继续覆盖。个人目标转发原有五字段和日统计，不借用普通好友的披露开关。

配置与实现需同时升级时，加 `--defer-restart` 只暂存配置，再部署对应实现并重启。`awaiting-history` 表示完整历史尚未就绪，不发送来源切换或较旧日统计；就绪标记持久化后，正常删除历史不再触发这项一次性检查。代次切换回复丢失时重试原来的一对代次，成功后才发实时状态与日统计。

不能让正式旧客户端和新服务同时向同一身份上传。协议、状态清空、版本递增及重试先用合成目标验证，真实接替单独核对。日统计不发送早于旧服务 `enrolledDate` 的日期；错误范围的旧队列须生成新版本再重发，不能改写已发送版本的正文。每账号保留最近一份投递状态码、失败部分和成功时间，排错不记录正文或凭据。外部故障由独立有界队列重试，不阻塞本机保存、云同步或每日备份。

发送成功后仍持久记录实时状态的到期时间；设备离线、撤销分享／执行权或恢复旧工作区时，排队清空已发布的实时投影。服务重启不会令最后一条成功状态永久残留。

## Mutsumi Focus 只读来源

`external-focus.mjs` 只访问 `https://platform.arcol.site` 的访客入口和公开看板。使用独立、仅在内存保留的 Cookie；不需要上报 key，不调用专注、打卡或计划的写接口。配置里的 `username` 可指定要读取的账户，首次接入时应固定该值，避免以后站点所有者变化时读错人。相同来源 ID 不允许改绑另一外部账户。

服务每 30 秒读取一次，失败后等待 60 秒；实时投影最长保留 90 秒有效期。失败立即停止展示旧数据，保留最后一次成功回执供诊断。只保存当前专注、暂停状态、事项名称、真实开始时间和最多 366 天的日时长；对方没有提供确定结束时刻时留空。不保存整个看板，不把成绩、打卡、私有计划或外部会话写入本项目的任务和专注历史。

每个来源分配一个不能登录的只读账号，账号和好友码持久化。用户启用好友后主动添加其好友码即可查看，不需要模拟对方确认，也不会向对方披露本机内容。普通用户之间仍需邀请确认及独立的分享授权。移除来源配置后停止展示，保留已有好友关系；不自动给所有用户添加这个好友。

用 `node tools/probe-external.mjs <配置文件>` 在隔离数据库中核对真实接口，只输出状态和数量。配置格式见 `external-focus.example.json`。通过后执行 `python tools/configure-external.py --configuration <私有配置路径> --apply`：先校验，备份数据库和旧配置，再更新独立配置并重启本服务。生产服务从 `/etc/blockcolc-cloud/external-focus.json` 读取，访客 Cookie 不写入配置或日志。
