## 已有实验怎么用

| 内容 | 处理 |
| --- | --- |
| 正式 TS 命令／排程 Oracle 与反例 | 保留生成器和源码指纹校验，P2 扩充，不另写“容易通过”的预期 |
| Kotlin 的计时规则、代次、原子保存失败用例 | 逐件迁入并审查；不照搬实验存档格式或秒数上限 |
| 备份严格 JSON、摘要规范化、只读转换和回滚反例 | 作为兼容起点；完整语义、旧 schema 和正式写回仍未完成 |
| 自启动广播证据与受限 UI 工具 | 作为后台约束和本机设置恢复方法，不变成应用保活逻辑 |
| GLB、展开／共享普通节点、逐帧 PixelCopy | 只作旧对照；不进入原生正式资源或玻璃默认路径 |
| Surface 呈现采样、前台／包摘要保护 | 按新的预览包和 Surface 复用；不把回调或提交当显示帧 |

## 接口与存储决定

业务、可恢复授权、展示投影与世界派生数据继续分开。业务命令只能有一个写入入口；后续 Room／SQLite 的事务需覆盖相关事实与授权，但具体表结构在 P2 实施前审查。外部文件先完整落盘校验再提交引用，孤件可回收，已提交数据不得指向半文件。

P1 世界契约使用稳定所有者、完整材质／几何身份、空间批次和独立实例缓冲；替换某栋建筑时只替换该所有者及其明确依赖。材质身份包括贴图内容和采样／混合状态；可变天气／腐败状态不得误合并。输入有总量、有限数值、索引、边界和段长度校验，拒绝不支持的表示，不静默丢弃。

核对发现存储文档备份段残留 schema 14 的旧称，而领域／生日和当前代码已为 15，本轮已校准文档。旧 schema 是兼容输入，不代表当前写出格式。P0 不改变领域格式、数据库版本或 UI 计划恢复规则。

## 基线边界

源输入由新目录内的 `source-inputs.json` 持有路径、长度和 SHA-256；暂定 /100 后续源码，不是用户已验收候选。P1 两侧用同一份生产世界输入验证表示与渲染，P2 集成收益必须再包含真实数据读取、生成、缓存和 UI，不把预导出省掉的工作算作提速。

P0 只读既有源码／内置资产。MC JAR 仍为用户本地测试素材，不封入包；不读取天气密钥、私有凭据或手机正式数据。未通过 P1 不接 P2，P2 未取得整条流程的实际收益不接 P3。
