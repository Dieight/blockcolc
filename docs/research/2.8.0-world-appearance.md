# v2.8.0 世界外观审计与实验

2026-10-16。状态：首轮地表实验完成，候选未接入 App。接续[地形性能实验](2.8.0-terrain-chunks.md)，本轮不再追求构网提速，也不出包或操作手机。

后续：用户已批准采用有效方向，正式取舍与验证见[外观整合](2.8.0-appearance-integration.md)；下文保留本轮实验原始结论。

## 范围与基线

先沿现行 V4 的采样、封面、材质、景观和渲染路径审计，再查资料，最后在实际渲染器里做单变量与组合对照。重点是近远景交接、地表立面、海岸和装饰的观感。天空、天气与倒影只核对共用入口和地表在日落／夜晚／雪天的表现，不宣称已经完成整套天气、云与光照的重新设计。

基线是当前 2.8.0 /96 工作树，含此前已经采用的性能优化，不是 v2.7.0 正式 APK，也不是手机里尚未更新的 /96 包。全部任务为合成数据。生产 voxel 源码的完整文件指纹在各轮实验前后相同；世界种子、任务位置、备份和现有缓存没有改写。

## 审计发现

| 现象／问题 | 现行实现与判断 | 本轮处理 |
| --- | --- | --- |
| 立面像过重的黑线，雪地和冰岸侧边尤其突兀 | `renderer.ts:addTerrain` 对两种立面统一乘 `0.4`，源于早期白边补偿；`terrain.ts:addRegionalCellSide` 又仅按高度选 dirt／stone，雪、沙和陶土的顶面身份没有传给立面 | 分离额外暗色、真实投影与表土材质。只调亮改善有限，不以关阴影作为方案 |
| MC 地形纹理远看有高频噪点，草地发灰 | 地形已裁出独立小图，仍禁用 mipmap、各向异性为 1；`packTileMaterial` 统一用白色，没有采用已有草地染色。原版草顶本来是待染色的近灰纹理 | 七纹理最小试件分别测试 mipmap，以及已有 temperate palette 的染色；不改整个资源包图集的安全 mip 规则 |
| LOD 边界有实在的高度台阶，不只是“看见裂缝” | 近／中景分别用 2／4 格中心采样；当前过渡只作用于精细／粗远景。两格共享边的位置相同，不代表采样高度相同 | 先测真实边界，再在隔离采样回调中试 16 格过渡带。保留原封边，不添加挡缝裙边 |
| 远景扩大细节后仍像层层刻线 | 高程先取整，近／中／远分档采样；不同空间频率与立面材质共同影响。细远景也不等于所有层级共用连续滤波契约 | 保留粗、细两个现行路径的对照。后续要改采样，而不是继续无条件扩大细节面积 |
| 海岸各区有大分区感，扩建后背景会重排 | `mosaic-terrain` 的九区构图满足既定布局，但高度也直接叠加各气候 mask；`spacing=max(116,coreRadius+84)` 同时控制群系与礁床范围，固定 seed 不代表地貌坐标独立于建筑扩张 | 作为后续生成规则议题，不偷偷改变旧世界形状。需要把构图约束、地质高度和表层身份分开讨论 |
| 珊瑚床外缘还显得像一大片规则铺面 | 当前已经是统一世界坐标 `reefCoverage` 和跨 tile halo，不是独立小团簇；40 格 tile 只负责组织与裁剪。海水、暖海权重、海床和浅滩仍分别取样 | 不把“更多珊瑚”当修复。下一轮单独对照海底等深线、礁缘破碎度和沙道，确认块状边缘来自哪一层后再改 |
| 村落、树林的分布仍有可见的规则感 | 候选多来自地表单元中心；村庄复用五个模块，预算上限三个；远树、花园用面积预算。真实支撑与保护区已有，不应退回随机散点 | 需要比较地表无关的候选点、局部坡度与群落密度；保留原保护区、无安全地面就省略的规则。本轮没有重新铺景观 |
| 仍有旧装饰导出，是否在正常世界叠画？ | `naturalDecorationPlacementsForScene` 只被历史几何测试调用；正常主世界走 `planWorldScenery`。没有因为搜到旧函数就认定它在重复绘制 | 不把删除未走的分支冒充视觉修复；未改历史测试 |

桌面软件 WebGL 的另一个重要条件：渲染器检测到 SwiftShader 等会自动关闭精细远景。此前截图有参考价值，但不能直接代表手机的精细路径。实验服务可显式选择现有两条路径，报告逐项记录；没有修改 App 的降档策略。

## 资料核对

只参考官方或作者资料，未引入上游代码或分发 MC 素材。

- [Three.js 纹理手册](https://threejs.org/manual/pages/textures.html)、本机同版 r178 的 [Texture](https://github.com/mrdoob/three.js/blob/r178/src/textures/Texture.js) 与 [WebGLTextures](https://github.com/mrdoob/three.js/blob/r178/src/renderers/webgl/WebGLTextures.js)：缩小采样需要适合的 mip 层；各向异性改善斜视采样但不是越高越好。本项目地形 tile 已有独立像素源，不能再直接沿用整幅图集串色的解释。本轮只证明试件方向，不把它扩展成所有透明／动画纹理可统一开启自动 mip 的结论。
- [NVIDIA Geometry Clipmaps](https://developer.nvidia.com/gpugems/gpugems2/part-i-geometric-complexity/chapter-2-terrain-rendering-using-gpu-based-geometry)：连续地形的层级过渡须匹配相邻层的实际高程。我们保留方块台阶与水面，不把整套平滑 GPU 高度场直接搬来；借用的是过渡带和统一采样基准。
- [Transvoxel 作者说明](https://transvoxel.org/)针对不同分辨率的等值面连接。本项目主要是显式高度台阶，并非等值面体素场，当前也已有封边；单纯换一个“补缝算法”不会解决采样高度、材质与过重立面的全部问题。
- [Mojang Java 1.18 世界生成说明](https://www.minecraft.net/en-us/article/caves---cliffs--part-ii-out-today-java)与[官方生成概览](https://learn.microsoft.com/en-us/minecraft/creator/documents/world-generation?view=minecraft-bedrock-stable)：高度、气候／群系、地表、特征和结构是相关但不同的职责。后者是 Bedrock 说明，只作为职责参考，不声称为 Java 26.3 的精确算法。
- 本机用户提供的 `26.3.jar` 内部版本确认为 `26.3`；另核对到 `overworld` 的大陆、侵蚀、脊线、温度／植被等路由和暖海特征。这里只读数据结构和七张地形纹理，不反编译或复制生成实现。JAR 与试件纹理散列见[来源清单](../../artifacts/visuals/v2.8.0-world-appearance-20261016/reference-manifest.json)。

## 隔离方式

[实验目录](../../spikes/world-appearance/README.md)直接调用现有 `createVoxelRenderer`，不启动 App、不读取正式 IndexedDB、不请求位置。实际世界画面为 960×640；世界为 24 栋小工坊，空岛为 7 栋，seed 固定 `world-default`，V4、balanced、精细远景、晴天 15:00。海岸另固定日落、夜晚和雪天。减少动态用于冻结环境动画，不测动画帧率。

立面暗色只改原有材质。表土原型从同一原始几何划分草、沙、雪、冰、陶土的表层，再用现有合面器输出；不把这份只用于绘制的表层表写回地表查询。原始地形、建筑和水面未动。独立覆盖 oracle 忽略有意改变的材质，核对所有方向的面覆盖、洞和重叠次数，不只比面积。

近中景原型由独立 Vite 服务包装 `sampleCellAt`，2 格边缘匹配真实 4 格邻格中心；河湖、地基与受保护的邻格不参与抹平。隔离服务给派生输入另加实验名字空间，防止同一进程里拿旧候选缓存当新结果；关闭后回到现行算法。没有改写生产源文件或缓存格式。

MC 试件只含七张地形图与自编最小方块模型，不含完整方块路由或全部群系。草地染色采用已有固定温带回退色 `#91bd59`，没有据此决定新世界的各群系颜色。临时纹理放在忽略的 artifacts，不封装到 App。

## 实验结果

### 立面与表土

只把立面额外暗色 `0.4→0.65`，山谷和海岸的改善有限；关闭投影后重线仍存在，说明不能再次以删除建筑阴影处理它。表土层让雪／冰的短边和陶土层更连贯，但几何版原型代价明显：

| 场景 | 现状紧凑网格 | 表土原型 | 取舍 |
| --- | ---: | ---: | --- |
| 山谷 24 栋 | 175202 三角形 | 252916 | 增加约 44%，不直接采用 |
| 海岸 24 栋 | 93136 | 125712 | 增加约 35%；外观方向有价值 |
| 海岛 24 栋 | 11322 | 15212 | 改善幅度较小，不值得全地形增加面 |
| 空岛 7 栋 | 1782 | 3150 | 增加约 77%，更不适合直接照搬 |

下一步若采用外观方向，优先试原面上的表土深度／材质属性或局部 shader，而不是把这批新增面直接接回已经优化过的构网路径。雪山仍应有裸岩，不把整座山刷白；表土的厚度和裸岩比例还需要调。

### 近中景交接

以下只比较 `x/z=±128` 的近／中景边界。沿边每两格取样，剔除缺地表或水域的点；不是所有山坡的落差，也不是整个世界的误差指标。

| 24 栋场景 | 有效边界点 | 高差 P95：现状→原型 | 最大高差：现状→原型 | 紧凑三角形：现状→原型 |
| --- | ---: | ---: | ---: | ---: |
| 山谷 | 474 | 5→0 格 | 11→1 格 | 175202→173772 |
| 海岸 | 394 | 3→0 格 | 5→1 格 | 93136→91372 |

任务变换完全相同，地形轮廓的改变局限于实验中的边缘过渡。数值方向成立，但固定宽度的带仍可能露出平滑痕迹；未测试两种子、大蓝图、60 栋、所有角度和其他远景边界，也没有检查新地形的持久化迁移。因此原型保留，不马上成为新世界默认。后续应对同一高程场做分辨率相关的预滤波，并按投屏误差／坡度调整过渡，不再叠加一条固定挡墙。

### 纹理和草地染色

恢复独立 tile 的三线性 mipmap、受能力限制的 4×各向异性后，细碎噪点减少；顶点、索引与建筑变换完全相同。对同一世界转动 `0/.002/.004/.006 rad` 的四帧，固定像素的平均亮度帧差约为 `11.6→9.9 /255`。这是未经运动补偿的辅助量，包含正确的几何与光照变化，不是“摩尔纹降低百分比”、视觉质量分或手机帧率。

现状草顶材质颜色为白色，启用已有草地染色后改为 `#91bd59`；纹理和几何未替换。草地由灰恢复绿色，说明染色应在地形材质入口补齐，不靠整体饱和度掩盖。是否采用仍需完整资源包、近景纹理锐度、斜角、雪／冰透明与 Android GPU 对照；本轮没有拿七纹理试件当全包兼容验收。

## 后续顺序

1. 先补地形 tint 与独立贴图采样，再把表土外观移到不增加大批三角形的路径，保留投影、雪岩比例和近景方块感。
2. 扩大近中景匹配试验，之后再审精细／粗远景。先验证边界、水系、地基与大世界，不以一次 P95 改善直接改变旧地形。
3. 独立做海底／礁缘与景观密度对照：坡度、等深线、林缘与村落朝向。保留九区构图与任务保护；涉及世界扩建时背景是否固定，需要在新生成规则中说明。
4. 天空／云群、昼夜和天气一体化的下一轮实验另外开记录，不能把本轮地表在几种光照下可见等同于完整天气验收。
