# v2.8.0 地形生成审计与实验

日期：2026-10-16。状态：审计与实验完成，局部索引／网格优化已采用到源码，尚未出包。
关联需求：[世界管线后续](../versions/2.8.0-development.md#世界生成与地形后续)。本轮按“审计 → 调研 → 同输入实验”进行，不构建、安装或发布。

## 审计结论

上一轮解决的是同快照 mesh 重建和部分持久缓冲；本轮关注缓存未命中后的地形生成与紧凑网格准备。不能把二者的收益相加，或直接当作 Android 冷启动节省的秒数。

| 查到的问题 | 实际影响 | 本轮处理 |
| --- | --- | --- |
| `sampleSupport` 原先每次遍历全部地基矩形，道路取高又重复扫描固定地基 | 水文、近远景采样反复付费，世界扩大后更明显 | 地基按影响半径建空间索引；保持输入顺序及等权时后项优先；道路取高在单次生成内记忆 |
| 补缝按侧面扫描整条 x/z 坐标线上的角点 | 已有拓扑正确，但候选范围过大 | 角点排序后二分到实际线段；保留原补缝条件和结果 |
| 海岛封边扫描整条线上的所有邻格 | 岛屿精细补丁与 4/32 格背景混用时，查询量增大 | 区间索引只找重叠段，再按原输入顺序出面；支持嵌套、负坐标、分数边缘 |
| 紧凑网格把每个四边形复制成多组坐标数组和字符串角点集合 | 大量临时对象和 GC；旧资料里泛称“已有合面”掩盖了这一步的 CPU 成本 | 直接读索引顶点，用四角位掩码校验；合面规则、材质、朝向和输出次序不变 |
| `refinedFar` 默认值与显式 `false` 都写成 `false` | 自动细节与关闭细节可能误用同一地形缓存 | 改为三态键；空世界 V4 默认 70,080 格、关闭 56,976 格，确实不是同一结果 |
| 空岛地表又套一遍已经做过的地基最大值计算 | 旧共用 helper 留下的重复扫描 | 地表直接用共用取高；道路 API 仍保留自身的基础取高逻辑 |
| 多个使用方把原始网格再次解回地表矩形 | 降水、奖励支撑、海床、景观和阴影范围各有调用 | 本轮记录缺口，未新增一份无限期持有的矩形／采样器缓存 |

定位入口是 `terrain.ts`、`terrain-render-mesh.ts` 与 `renderer.ts` 的 `rebuildSteps`。CPU 采样也落在地基查询、角点补缝、海岛封边和网格矩形识别上，不是仅按代码行数猜测热点。采样包含 warm-up、散列等诊断成本，只用于找函数，不作前后计时成绩。

当前 renderer 通常显式传入远景布尔值，因此三态键修复针对的是底层默认参数的正确性，不据此宣称它已造成用户日常启动的误命中。

### 旧代码的边界

初读函数名容易误判：原来的 `createOceanIslandTerrainDataV1` 实际生成当前海岛，`createNaturalTerrainDataV2` 则共用 V2–V4。正常 App 的 `WorldSettings` 早已只接受 V4，领域迁移把旧版本转换到 V4；V1–V3 不应都解释成当前线上旧世界的必要路径。

用户本轮明确同意删除 V1–V3 旧世界兼容后：

- 删除旧自然高度场、V2 水文和河道寻路、V3 参数分支、V1 背景平面。当前仍使用的地基、水文与 LOD helper 改成不带旧版本号的名字，不删除它们的现行算法。
- 生成入口和派生缓存只接受 V4。保留业务记录／备份升级到 V4 的数据迁移，不清数据库或改变任务、种子、建筑位置。
- 删除仅扫描 V1 的测试；旧版对比用例归档，当前山体、水系、支撑、接缝和大世界预算断言保留。当前景观的固定哈希不更新以迁就实现。
- 原生成函数已冻结为实验对照；删除／调整前的测试另存于[历史归档](../../artifacts/performance/v2.8.0-terrain-20261016/legacy/)。可恢复查证，不再作为现行测试入口。

旧的散点道具规划、缩放几何导出目前仍只由历史几何测试调用；本轮没有把它们当成运行时热点，也没有扩大到删除所有历史装饰 API。

## 方案取舍

本轮先采用不改地貌结果的局部索引和分配优化。Voxy 式按块更新值得继续做，但有两个本项目特有的前提：

1. 建筑扩张会改变核心半径；海岛主岛半径、海岸气候坐标和 LOD 档位都引用它。只按 seed 和区块坐标命中，会复用错误的海岸、山体或材质。必须纳入完整全局 profile；要让地形不随扩张变化，则属于另一个生成规则决定。
2. 山谷水文依赖全局保护区与排水网络，不能只重建新建筑脚下的一块。需要分清局部脏区、邻格边界与全局依赖，再比较分块后的合面损失、存储与调度成本。

因此暂不改地形版本、减少细节或迁移 Rust/WASM，也不把“删除旧分支”单独说成已证明的提速来源。

## 实验办法

[实验脚本](../../packages/voxel/tools/terrain-audit.ts)使用合成数据，不读用户数据库。冻结的旧生成函数与候选函数在同一 Node 进程交替 AB/BA；每条路径先热身，随后五次取样。完整结果散列在计时之外比较，含所有顶点、索引、材质、树、边界与水文统计；紧凑网格也作全结果对照，不只比较面数。

范围：四环境的 1／24／60 栋、两个种子，以及自动／关闭远景细节与 60×60 足迹；共 32 个输入。24 栋默认细节的第一种子另作五次紧凑网格 A/B，其余网格只核对一次，不能拿单次值写 P95。

复用时在仓库根目录设置新的 `BLOCKCOLC_TERRAIN_AUDIT_OUTPUT`，先运行 `npx vite-node packages/voxel/tools/terrain-audit.ts --snapshot --snapshot-mesh --snapshot-only` 冻结改前函数，修改后运行同脚本的 `--compare --compare-mesh`。再次测量另设 `BLOCKCOLC_TERRAIN_AUDIT_TAG`，脚本拒绝覆盖旧对照和报告。布局、基础网格发射与 V4 profile 是本轮两路径共用的依赖；本轮 profile 收口的 V4 参数未变，并与清理前的完整哈希交叉核对。若后续改这些共同依赖，应另冻结它们，不能称作同一旧实现对照。

初步四输入结果保留在 `support-comparison.json`、`support-corners-comparison.json`、`indexed-comparison.json` 和 `indexed-mesh-comparison.json`。最终扩大矩阵与定点结果完成后在下节记录，不用初步较好数字代替最终结果。

## 扩大后的 CPU 对照

32 个输入全部完成，每组五次生成 A/B 的完整输出一致，进程退出 0。删去 V1–V3 分支后，又与此前四输入报告的地形、网格、地表矩形、景观哈希交叉核对，四组全部相同；没有借精简兼容改掉 V4 地貌。

以下只列 24 栋、`world-default`、精细远景下五次的中位数，单位毫秒。生成和紧凑网格是独立测量，不相加冒充启动时间。

| 环境 | 地形生成：旧 → 新 | 紧凑网格：旧 → 新 |
| --- | ---: | ---: |
| 空岛 | 116 → 112 | 110 → 22 |
| 山谷 | 2024 → 1642 | 1396 → 616 |
| 海岛 | 832 → 531 | 228 → 61 |
| 海岸 | 1416 → 1000 | 690 → 338 |

空岛生成差值很小，不声称有明显收益；海岛生成约减少 36%、海岸约 29%。紧凑网格约减少 51%–80%，面数、坐标、朝向和材质没有减少或更换。其余世界规模、种子、粗远景及大足迹的全部样本保留，不能只凭这四行概括所有设备。

原始证据：[完整对照](../../artifacts/performance/v2.8.0-terrain-20261016/v4-final-comparison.json)、[退出记录](../../artifacts/performance/v2.8.0-terrain-20261016/v4-comparison.log)、[摘要与交叉核对](../../artifacts/performance/v2.8.0-terrain-20261016/summary.json)。完整记录含源文件指纹；散列与规范化比较不计入生成计时。实验在本机 Node、热 JIT 下运行，没有同时跑浏览器／其他重测试；没有锁定系统频率或测量原生内存峰值。

## 后续顺序

第一步已接续完成共享消费表和查询索引，记录见[共享地表实验](2.8.0-terrain-surfaces.md)；下列顺序保留本轮原计划，不代表后面的分块或 Worker 已实现。

1. 先做共享地形单元表，让降水、支撑、海床、景观和网格不再各自从三角形恢复同一地表；比较生成、恢复、临时分配和总驻留内存。
2. 再试分块 mesh／缓存，键纳入全局 profile 和水文依赖，保留跨块边界外延。若改变核心半径与群系的关系，需要单独确认地貌变化，不夹在性能改造里。
3. 对紧凑单元与类型化缓冲实验 Worker 转移；同时记录主线程响应和复制／上传成本，不能只报 Worker 内计算耗时。

本轮没有 Android 实验，不从桌面生成时间推断 OnePlus 的实际冷启、旋转帧率或峰值内存收益。手机仍是上一轮 /96 无探针私人测试包；正式发布仍为 v2.7.0 /84。这份源码实验不代表已安装包已变化。
