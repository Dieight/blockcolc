# 原生备份读取与替换恢复实验

日期：2026-10-19。承接[计时规则局部移植](2.9.0-native-focus-port.md)。仍使用隔离包 `com.blockcolc.experiments.ui`，没有迁移正式数据库或私有同步。

## 审计后的边界

正式备份保留兼容标识 `tomato-clock-backup`：封套 1 直接保存领域对象，封套 2 对已知位置的蓝图引用和方块属性去重。校验和对未签名封套进行排序规范化后计算，不是对文件原字节计算。当前领域 schema 为 15；正式导入上限仍为 100 MiB，展开预算仍为 512 MiB。

备份不包含界面的多轮计划、展示偏好或自动续轮授权。正式仓库替换时，在同一事务保存回滚点与 `last-domain-replacement` 代次；协调器依此作废旧授权。因此不能读出历史后猜测剩余轮次，也不能把恢复旧数据当作允许后台继续运行。

本轮没有一次移植所有领域校验和旧 schema 迁移。新入口 `.NativeBackupActivity` 只开放随包携带的合成样本，没有正式数据入口或文件选择器。导入事实只读，原始 JSON 完整留存；便签、奖励、世界、蓝图和完整性等暂未迁入业务执行器的内容不会被丢掉，也不会被这个局部执行器写回正式备份。预览检查不等于完整语义校验。

## 实现

- `export-backup-contracts.ts` 直接用当前正式领域命令、备份工厂、压缩工具和解析器生成样本及答案，不访问用户备份。当前为 22 份输入，其中 6 份原生可读取样本；另有 13 组数字与 Unicode 规范化对照。Oracle 带正式源码与导出脚本摘要，Gradle 测试前检查是否过期。
- `BackupJson` 在平台 JSON 入口前做严格语法、重复键、UTF-8、遍历深度和数量检查。数字使用固定的上游 ECMAScript 格式化实现。拒绝无配对代理项和模糊 JSON，而不是替换字符或接受平台解析器的宽松语法。
- `NativeBackupReader` 校验封套及摘要，只在四类已知蓝图位置展开引用，检查索引、调色板坐标覆盖、未引用数据和展开预算。只读取当前 schema 15，提取计时投影和概要，完整展开内容与正式答案逐字段对照。旧 schema 明确拒绝，不静默填默认值。
- `NativeBackupRepository` 将当前实验事实、原始备份、上一份回滚点、revision 和替换代次放在一个 `AtomicFile` 中。替换前检查版本，成功后才发布；失败不更改任一部分。回滚也视为替换，恢复的原生计划撤销自动授权和排队的开始时间。
- 读取和保存运行在跨 Activity 共用的 IO 队列。导入状态有只读写入守卫；单纯重开不会从备份创建计划或完成活动会话。这里只验证隔离存储规则，没有调度原生后台服务或取消真实 OEM 事件。

为控制这个实验的输入和内存，读取预算暂为 8 MiB、展开 32 MiB，内部单文件预算 52 MiB；保留一份隔离回滚点。这些是样机约束，**不修改正式 App 的容量或回滚保留规则**。超过预算会报错并保留原文件，不截断。当前不是 100 MiB／512 MiB 压力或兼容性验收。

## 对照和过程

[样本及 Oracle](../../artifacts/experiments/v2.9.0/native-backup-contracts-first/backup-oracle.json)包含普通、压缩、换序美化、活动会话、较大蓝图和空状态；反例涵盖摘要改动、非法时间、未知字段／版本、重复键、失效引用、调色板越界／覆盖、未使用蓝图和引用放大。旧领域 schema 14 在正式解析器中能迁移，而原生端暂不支持，记录为范围差异，不算正式格式损坏。

六份成功样本都检查原始字节摘要、完整展开内容、概要与计时事实，不只比较任务数量。数字测试覆盖科学计数阈值、负零、最小／最大有限双精度数、中文、emoji 与 UTF-16 键排序。

第一轮 JVM 和构建通过，[构建记录](../../artifacts/experiments/v2.9.0/native-backup-build-first.log)。OnePlus 上 14 项设备测试及三次进程重启通过，见[首轮结果](../../artifacts/experiments/v2.9.0/native-backup-device-first/result.json)。随后审计补了隔离存档损坏 UTF-8 的反例，并把整个读取链改为单次严格解析和直接规范化遍历；首轮 APK 与原报告保留，不混入新包结果。

## 读取成本

首轮 1,409,930 字节的压缩样本展开为 2,901,914 字节，三次预热后读取中位数约 2,891ms。初版反复经过对象→字符串→解析树，且每个方块都序列化再解析属性。改为一次严格解析、直接规范化现有树，以及复制属性而不重新解析字符串；仍保留相同摘要和完整内容对照。没有通过删校验、跳过字段或关闭展开预算换取速度。

最终同机复核如下。输入字节及展开内容不变，每组均先预热、再测三次，取中位数：

| 合成样本 | 文件字节 | 展开字节 | 初版读取 | 直接遍历版读取 |
| --- | ---: | ---: | ---: | ---: |
| 普通封套 | 10,041 | 9,862 | 10.84ms | 4.54ms |
| 小压缩封套 | 6,956 | 9,862 | 9.80ms | 6.48ms |
| 较大压缩封套 | 1,409,930 | 2,901,914 | 2,890.61ms | 1,013.65ms |

较大样本在本轮下降约 65%，仍需继续优化，不能据此判断当前格式适合几百 MiB 的原生存储。此处只量样本读取，不含磁盘、UI 绘制、生产完整语义校验或正式冷启动；没有同温度锁频和长时功耗对照，不能把它当作 TS／Kotlin 的语言排名。原生化本身没有消除重复对象和整树遍历成本。

首／末版 APK 身份、逐次数据与最终源文件摘要见[汇总](../../artifacts/experiments/v2.9.0/native-backup-summary-final/report.json)。只复用初版读取基线，没有为本次改动重跑世界渲染对照。

## 最终设备验证

- 17 项 JVM 测试通过：包括本轮 22 份备份输入、13 组规范化矩阵与严格 JSON 反例，以及原有计时／计划测试。[最终构建](../../artifacts/experiments/v2.9.0/native-backup-build-direct.log)与[冻结 XML](../../artifacts/experiments/v2.9.0/native-backup-device-final/jvm-results/TEST-com.blockcolc.experiments.ui.NativeBackupOracleTest.xml)保留。
- 15 项 Android 测试通过，含原有九项及六项备份检查：Android JSON 运行时对照、实际预览／导入／Activity 重建／撤回、提交前 IO 故障、旧版本替换拒绝与只读守卫、独立进程恢复种子、损坏 UTF-8 不重置。[原输出](../../artifacts/experiments/v2.9.0/native-backup-device-final/device-tests.log)。
- OnePlus 上连续三次只终止并重新打开隔离包。每次真实界面显示已保存的替换代次与只读状态，原始备份摘要、计时事实和活动会话保持不变，没有凭空计划。已实际审看[最终恢复截图](../../artifacts/experiments/v2.9.0/native-backup-device-final/restore-3.png)。这不是后台按时执行、通知持续显示或真实旧授权事件撤销的验收。
- [最终结果](../../artifacts/experiments/v2.9.0/native-backup-device-final/result.json)记录手机、本地 APK 与安装摘要相同。隔离包为 `0.5-backup-readonly / 5`，SHA-256 `534681e2a9e206d8bc65b13a51a75efedf84a77b8854837f350fdfa826fadb06`。[APK](../../artifacts/experiments/v2.9.0/native-backup-device-final/blockcolc-native-backup-lab.apk)只供复现，约 500MB 的主体仍是上轮冻结世界输入，不是正式原生资源方案。
- 隔离实验进程已停止，没有操作正式 App 或全局电源／息屏设置。新增许可声明随隔离 APK 打包，未进入正式 App。

## 尚未完成

正式全量 schema 校验、旧版本迁移、正式备份写回、生产数据库转换和大容量压力测试仍未做；后台计时／通知、导入后事件代次检查也需要单独的原生服务实验。本轮先证明资料能保留、替换能回退、旧授权不会从隔离存档复活，不批准整套存储切换。

后续的后台服务与真实事件代次检查另记在[原生后台实验](2.9.0-native-background.md)，不替换以上只读阶段的结果与边界。

没有跑发布全量，没有重建正式或私人 App，也没有上传或发布。正式 /100 与现有数据保持不变。
