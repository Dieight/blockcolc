## 样本是否真的跑完

用户提醒安装会经过安全扫描。安装耗时不作为启动时间；主报告采用后补前台保护的重采：渲染失焦就清空当前采样并重新预热，计算等待前台并记录中途失焦。三后端各三轮、两份计算报告共 11 份完整输出，全部前台保护有效、零失焦；另逐一核对结束截图，实际显示实验世界或计算结果，不是扫描页。原始首轮、失败构建和重采均保留。

## 1. 相同冻结世界的三个后端

同一 SHA-256 `98859f0b96f8f3fcc718dccbc96811fb55a7db35987ef8716feeef0d1a44c7a6`，1,333,992 顶点；720×960 绘制缓冲、相同相机、60 次预热回调后固定旋转 300 次。每轮轮换后端次序。

| 后端 | 三轮 CPU 提交中位数（ms） | 帧回调 P95（ms） | 实际提交 |
| --- | --- | --- | --- |
| WebView WebGL | 0.40 / 0.40 / 0.30 | 约 16.70 | 每轮 300 次 render 调用；未冒充 GPU 完成数 |
| Filament GLES | 0.57 / 0.79 / 0.76 | 约 16.67 | 299 / 300 / 300 帧 |
| Filament Vulkan | 0.40 / 0.78 / 0.48 | 约 16.67 | 299 / 300 / 300 帧 |

结论是此机能实际运行 Filament Vulkan，而非仅编译成功；这个简化控制场景下没有稳定帧率优势。CPU 提交、rAF 和 Choreographer 间隔都不是 GPU 时间。第一轮设备刷新节奏曾变化，不能把前后两轮刷新率变化算作后端收益。

这里没有贴图、阴影、水面、云或动物，且原生颜色响应、共面边缘与 Web 仍有差异；GLES 截图的部分岛底有高对比杂点，属于后续视觉移植需排查项。不能据此宣称画面等价。两侧首帧计时边界也不同，原生含实验运行时材质编译，Web 含本地读取与摘要计算，不拿它们推断正式 App 冷启动收益。

## 2. 同一表面计算内核

三组输入与 TypeScript 参考的五组输出缓冲都逐字节相同，包含位置、法线、UV、索引和体素归属。各预热 3 次、记录 7 次：

| 建筑数 | WebView TS 中位数 | Android ART 中位数 |
| --- | ---: | ---: |
| 1 | 1.0ms | 8.24ms |
| 7 | 5.6ms | 3.60ms |
| 25 | 23.5ms | 10.14ms |

原始 Java 逐个 `ByteBuffer.putFloat` 的版本并不快，25 栋约 41.75ms。改成批量小端 typed-buffer 传输后才得到上表，原报告没有覆盖。这说明数据组织和跨边界编码与语言同样重要，不能把约 2.3 倍的大样本内核差异当作整个 App 提速。小样本还受 ART 热身影响；此处为独立 debug 样机，不是原生正式构筑或完整地形基准。

## 3. 原生页面和输入

Compose 样机两项设备测试通过：在中文正文中间插入文本、改变选区继续输入、切换主题后保留内容；以及切页、普通／极简、英语、展开收起和 Activity 重建。输入测试通过 Android 的 Compose 测试输入通道注入文字与选区，不能冒充已人工覆盖 OnePlus 拼音候选输入。样机另外保存了 300 帧与六次切页的回调记录，但不作为前述前台重采中的性能结论。

背景仍是冻结图片，不是实时 Filament Surface。跨 Surface 的液态玻璃、正式领域规则、恢复、备份、通知和全部交互尚未迁移；也未完成所有 OEM 输入法、系统大字号和进程被杀后的输入恢复验收。

## 接下来怎么选

继续保留 Kotlin／Compose 页面与 Filament 世界的候选路线，Vulkan 可用但不预设比 GLES 快。优先评估紧凑数据、批量传输和离线材质，再逐项增加透明、阴影、动物和实时玻璃后比较。C++／Rust 仍需自己的实测；没有必要只为了“换语言”增加桥接。

实验 APK 和代码都留在 `spikes/native-*` 与 `artifacts/experiments/v2.9.0/`，不进入本轮测试包。正式 App 继续使用现有技术栈和原有用户数据库。
