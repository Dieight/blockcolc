# v3.0.0 P3 界面审计回看

日期：2026-11-15。状态：用户已批准，正在实施与定点验证。
关联：[P3 工作包](../versions/3.0.0-p3.md)、[原版对照与返修](3.0.0-ui-parity.md)。

## 这轮核对什么

用户体验统一预览 /10 后，要求回看 P3 中途对 Opus 5.5 三次审计的讨论：哪些已经实现，哪些在按原版还原时一起带回来了，哪些仍值得调整。初次回看只读源码并整理建议；用户已批准表内调整，另增加左右滑动切页、页面状态保留、后台恢复视口修复。

审计最初针对公开 v2.8.0 Web 界面；当前是 Compose 原生界面。原 CSS 的颜色数量、字号数量和对比度测量不能直接作为当前版本的结论。以下“代码确认”与“待画面验证”分别记录。

## 已确认的决定仍然保留

| 当时的决定 | 当前核对 |
| --- | --- |
| 结束专注仍用双击空白，通过教程教会用户 | `NativeFocusExitControl` 保留双击、键盘和辅助操作；`NativeApp` 教程有实际练习，不改为常驻结束按钮 |
| 去独立品牌页头，普通计时保留状态栏，沉浸隐藏系统栏 | `NativeTheme` 的系统栏策略及当前页面结构保留了这个区别；不再扩大为所有页面全屏 |
| 蓝图、材质留在设置，重新细分设置并提供搜索 | `NativeSettingsPage` 与 `SettingsCatalog` 保留七组和搜索；后来明确删除的目录树没有恢复 |
| 提供像素、系统和混合字体 | `NativeTheme` 已接三种模式；混合以像素显示数字／短标签，正文与任务名称走系统字体 |
| 开关方块化，两种复位保留 | `NativeToggle` 已是阶梯开关；教程分别解释两个复位，不合并图标 |
| 成就弹窗、彩纸及室内摆设奖励 | `NativeRewards` 已显示解锁摆设，室内采用固定自动摆放；这部分不再作为尚未开发的新功能 |
| 保留玻璃并改善阅读，不把阅读页统一改成另一套视觉 | 主计时玻璃已走同帧 GPU；`NativeGlass` 覆盖前景文字为黑／白，颜色和方角有共用入口。仍需实景检验，不沿用旧 Web 对比度数值 |

纪念建筑的新展示形式当时没有定案。当前不建议因此加独栋 3D 橱窗、2D 缩略图或新的收藏页；历史记录、投入归属和现有入口先保留。

## 已批准的调整

| 项目 | 当前代码确认的情况 | 建议及优先级 |
| --- | --- | --- |
| 字级与字体分工 | `NativeTheme` 有统一 typography，但 `FormalText` 仍直接覆盖字号。主要页面保留 11、12、13、14、15、17、21 等相邻值；纯像素模式固定 normal 且禁用合成字重 | **优先。** 收成少数明确的数字、标题、正文、辅助字级，三种字体分别定映射。纯像素不靠虚构的粗体区分层级；不直接采用“所有文字都设为 12 的倍数”作为跨设备保证 |
| 普通计时的主次 | `NativeTimerPage` 的项目名称与当前小任务仍同为 21sp，计划摘要、标签各占位置 | **优先。** 保持现有计时操作及世界比例，弱化项目名称，突出当前小任务、时间和开始操作；不另添选择器或第二个计划按钮 |
| 任务页的层级 | `NativeTasksPage` 仍依次出现“任务与施工”“当前大任务”、项目名称、“施工清单”、完成计数、“当前”和行内状态 | **优先。** 保留项目标题、进度、编辑入口和清单；“当前”只在对应行表达一次，合并重复的分类文字。普通／习惯任务各自业务和已完成收纳不变 |
| 页面标题与固定标语 | 任务、统计、设置仍经过 `NativeHeading` 输出大标题和固定说明。去品牌头没有消除这部分留白 | 建议改为紧凑页标题，固定标语留给空状态或教程。不是把所有标题都删掉，搜索与主要操作仍需清楚定位 |
| 按压反馈和按钮层级 | 主按钮与图标按钮已有按入和图标动效；`NativeSettingLink` 没有按压状态，`FormalTextAction` 主要在点击后播放图标动效 | 补齐这些遗漏入口的轻微按入反馈，并检查主操作／次操作／危险确认的区别；不重加玻璃上的灰色水波纹或选中框。并列选项已共用 `NativeSegments`，不再把它算成五套待重写组件 |
| 进度的视觉语言 | 今日目标、项目、习惯建筑与成就已经复用 `FormalProgress`，但高度分别为 14、5、10 等值，另有不同分段数 | 中等优先。整理块形、间距和前景／底色，让相同意义的进度看起来一致；轮次数可以影响分段数，不把热力图和投入团簇硬改成进度条 |
| 设置与新账户入口 | 七个原分组已落实；新账户在组标题和行标题重复出现。“账户／好友／云备份”也尚未进入原七组的搜索索引 | **优先。** 补同一搜索索引与定位，减少重复标题。原有蓝图／材质位置、设置间距和已采用层级保留，只调整确有重复的部分 |
| 教程与新行为 | 双击和复位已有演示；室内页仍写“物品可放在预设的位置”，与自动摆放容易混淆；结尾只讲本机记录，没有账户云同步及披露控制 | 更新这几处说明，解释摆设自动获得、账户可选、同步与好友披露不同。继续以教程提高隐蔽操作的可发现性 |

可以另行讨论一项：在成就列表中也标出对应室内摆设，方便日后回看。当前解锁弹窗已经说明摆设，不需要重做领取流程。它属于补充建议，不是此前明确决定却漏做的功能。

## 需要实际画面确认的部分

玻璃在浅色沙地、明亮屋顶、深色夜景以及高通透度下的文字对比；最小像素文字在 Android 密度和系统字号变化后的阅读；新的标题层级在真实长任务名与英语下是否合适。这些不能单靠组件名称或代码中的黑白色值判为通过，也不能引用原 Web 的 1.6:1／2.1:1 作为当前数值。

如果批准调整，先修改共用字级和少数明确重复的层级，再按普通／习惯、四种计时状态、中英／浅深／三种字体核对同尺寸画面。业务数据、任务归属和保存结果继续按现有流程；只在有实际改动后执行受影响定点。

## 本轮决定

用户批准表内调整及成就列表的摆设提示。实施同步更新 `DESIGN.md` 与 `ARCHITECTURE.md`；定点结果和交付摘要记在 [P3 工作包](../versions/3.0.0-p3.md)，不将旧 Web 审计数字当成当前原生结论。
