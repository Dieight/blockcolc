# v2.6.0 启动与卡顿审查

2026-10-07，针对构建 56 后的工作树。先审查并建立基线，再按测量安排修改。本记录不代替发布门禁。

## 审查范围和现有保护

核对了原生 Activity / WebView、入口 bundle、bootstrap、领域读取与恢复、蓝图目录、资源包仓库及图集、常驻世界初始化、地形和装饰、绘帧与相机、玻璃、隐藏页面、每日备份、提交和模式转场。

已有的正确做法保留：绝对结束时间与持久化恢复、CAS 保存、按 revision 缓存投影、世界常驻、资源包轻量选择身份、地形/地面采样缓存、主线程外的 GPU 降水运动、加载阶段准备真实光照和天气、两个实际预热帧。不能为了减少等待删除保存、校验、阴影或装饰，也不能用动画时长替代加载成本。

## 这次 Web 基线

优化的 test-mode 构建，Chromium / SwiftShader，412 × 915，DPR 1。每组 3 次新文档启动，日期固定但 `performance.now()` 与 rAF 原生；合成 IndexedDB 数据，没有读取手机任务。它不是 Android 进程冷启动，也不是硬件 GPU 帧率。

| 场景 | 世界就绪中位数 | 单次世界重建 | 装饰几何阶段 | 地形生成 | shader 准备 | 含两帧的呈现准备 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 栋 / 海岛 / 普通 | 1.94s | 0.62s | 0.26s | 0.23s | 27ms | 0.93s |
| 24 栋 / 海岛 / 普通 | 3.84s | 1.88s | 0.92s | 0.43s | 29ms | 1.54s |
| 24 栋 / 海岸 / 极简 | 8.31s | 4.77s | 2.92s | 0.55s | 44ms | 3.16s |

海岸最长主线程任务中位数约 4.81s。世界就绪后的前三秒仍有明显帧间隔，软件 GPU 下海岸最大间隔中位数约 2.62s。因此「撤下加载页」目前不能代表开场和最初操作已经顺畅。呈现准备含 CPU 提交及软件 GL 等待，不可直接称为 GPU 执行时间。

原报告：[9 次观察](../../artifacts/performance/v2.6.0-audit/web-observations.json)，可重跑的[隔离测量脚本](../../artifacts/performance/v2.6.0-audit/web-audit.mjs)。没有把这些值外推成 OnePlus 提速比例。

此前的 `submission-performance.diagnostic.spec.ts --grep "real ordinary report"` 两例未通过：旧用例在世界尚未就绪时等待标题，5 秒即失败。原输出可在本次会话查证，但旧 report 目录随后被 runner 覆盖，不能把后来拷贝的通过目录称作失败原件。定点已经改用现有实际准备帧边界，没有改变业务断言或等待预算。

## 按收益与风险排优先级

| 优先级 | 代码证据 | 后续修改方向 | 必须保留的边界 |
| --- | --- | --- | --- |
| P0 | `renderer.rebuild()` 清空建筑和装饰批次；即使地形命中缓存，仍重建道路、所有建筑及装饰 | 分离静态景观与施工层，只更新真正改变的建筑；稳定景观复用 GPU 网格 | 新布局、奖励、群系、材质、腐败正确失效，阴影不丢失，提交仍只在持久化后生效 |
| P0 | 地形、装饰规划与几何构造是同步大任务，海岸装饰占主要 CPU 阶段 | 先消除重复工作，再把纯规划/数组构建转移或拆成有取消的批次；GPU 采用仍由主渲染器负责 | 同 seed 内容不变，旧代不采用，失败仍能恢复；不是把所有工作拖到加载页消失以后 |
| P0 | `prepareInitialPresentation()` 预热远景/近景，但开场逐帧 culling、LOD、阴影/玻璃和首次上传仍可能昂贵 | 真机拆 CPU 提交、GPU 计时及显示帧；补齐实际使用路线，避免重复强制刷新 | 不删开场动画，不降低用户选择的画质当作优化 |
| P1 | `blueprint.ts` eager 导入全部本地建筑/奖励，且目录组合重复校验；构建 chunk 约 4.07 MB | 元数据、核心建筑、奖励和具体本地蓝图分开，只载当前世界与用户所选内容；合法 ID 保持 | 工作区资产仍完整封包，不依赖外部素材目录，不丢已有蓝图或奖励 |
| P1 | `App` 同时预载并挂载任务、统计和设置，隐藏统计仍做多轮历史投影，隐藏 BackupPanel 仍列备份 | 首屏必要工作优先，非当前页面计算按需要执行；访问后保持缓存 | 首次导航及时反馈，草稿与页面状态保留，统计/成就不会重复授予 |
| P1 | 大聚合经过领域复制、仓库复制/严格校验和 IndexedDB 复制；蓝图随任务快照重复进入状态 | 测真实数据后减少多余拷贝，合理共用不可变内容；更大存储结构调整另留迁移方案 | CAS、回滚与验证不弱化，任务数据仍可独立恢复 |
| P1 | 选中资源包严格读会复制整份 archive 和 manifest；每个 renderer 再建图集/mipmap | 分开原件与已验证运行时内容，对图集做版本/摘要/GPU 能力有界缓存；评估只解码被使用内容 | 导入和采用都不跳过验证，分层材质、动画及模型对应不退化 |
| P1 | 世界模块与天气已并行，但 renderer、资源读取和几何仍等待首次天气/天文再开始 | 独立内容准备与网络并行，在显示前采用最新环境；明确离线预算和缓存有效期 | 首帧真实光照正确，不重新出现先开场后变天的跳变 |
| P2 | 相机更新和绘帧大量写 dataset、生成 culling 数组/签名；每 32ms 环境泵与其他任务可能重叠 | 诊断与业务必要指标分离，按实际变化更新；复用可见集合与工作缓冲 | 无探针时不改变输入/渲染逻辑；相机、降水、远景阴影仍正确 |
| P2 | 日备份空闲回调只推迟开始，后续校验和分块仍可长时间占主线程 | 单独测定成本，改成可让出并有总预算的调度，不抢开场/手势 | 每日合并根、跨日补档和删除/导入回滚继续保留 |

先不换语言。重复重建、过早挂载和多次拷贝，不会因为换成 Rust 自行消失。只有测到剩余的纯计算确为瓶颈，再比较 Worker 和 Wasm；GPU、DOM 与原生桥接分别测量。

## OnePlus 测量安排

已识别 PJX110，安装版本 2.6.0 (56)，USB 连接、解锁，系统息屏为 30 分钟。只对本应用使用临时保持亮屏，停止/后台/超时释放，不改全局息屏设置。[Android 官方保持亮屏说明](https://developer.android.com/develop/background-work/background-tasks/awake/screen-on)。

探针默认关闭，限测量构筑显式启用。记录阶段耗时、数量、帧间隔与错误计数，不记录任务正文、位置、资源包原件、网络响应或密钥。脚本在真正冷启动前确认无活动专注或待恢复计划；读不到这项则停止，不能默认空闲。

分开记录 Android 首个 Activity 帧、Web 读取完成、世界准备完成、开场结束和之后的操作。`am start -W` 不等于世界可操作；采用 [Android TTID / TTFD 区分](https://developer.android.com/topic/performance/issues/launch-time)。rAF、CPU 提交、GPU timer 和 Android gfxinfo 各有自己的口径，不互相冒充。

测量优先为真实数据的冷/热启动、进入后 10 秒、旋转/缩放、首次和再次导航、返回世界；专注/汇报等写业务的性能使用隔离合成数据。聚落、材质和画质切换需要保留并恢复原配置，不擅自把手机的任务改成测试任务。

以上是测量前安排。后续结果如下，性能录制与发布门禁分别记录。

## 实机基线与本轮修改

构建 57 的私人探针包取得三次真实进程冷启动，OnePlus / Android 16、海岸、原创材质、同一用户世界。仅采集数量和数值：14 栋可绘建筑、12 个未删除任务、357 条专注记录。世界准备中位数 20.36s，开场结束 21.92s；重建 16.53s，其中装饰 13.26s、最终光照 1.20s。首次旋转的最大长任务 1.17s，并触发自适应降档。[原报告](../../artifacts/performance/v2.6.0-audit/android-baseline-attempt2.json)。

第一次测量因脚本等待单份样本的 12 秒传输预算短于同步重建而退出，保留[失败报告](../../artifacts/performance/v2.6.0-audit/android-baseline.json)。将采样传输等待改为 90 秒后完成三次；没有改产品准备条件或性能合格阈值。GPU timer 在设备上不可用，CPU 提交和 rAF 不冒充 GPU 耗时。

已实施：隐藏页面按需挂载；环境等待与资源／几何准备并行；遮蔽邻域常量化、数值索引、无数组标量计算和画质强度复用；装饰地表单遍采样、确定性评分只算一次、先用便宜条件排除不可能的花园；同批方块外观身份去重；相同显隐值不再强制刷新。三组海岸全量方块与位置摘要、六组旧布局摘要、遮蔽参考算法均保持一致。[定点](../../artifacts/performance/v2.6.0-audit/pre-probe-voxel.log)。

没有采用跨渲染器 GPU 缓存、异步拆分场景重建、蓝图目录懒加载或存储格式迁移；这些仍为上表中的后续方向，不能记成本轮已实现。

## 优化后的 OnePlus 对照

2026-10-08，构建 58 的私人探针包，三次进程冷启动；同一部 OnePlus / Android 16、同一用户世界、海岸、原创材质，启动时均为精致档、DPR 2。记录数量与基线相同：12 个任务、357 条专注记录、10 个导入蓝图、126 条推进记录。没有操作专注或提交，也没有更改天气、任务或画质设置。测量期间电池温度约 32.2–32.4℃，与基线接近；自然天气和日月时间未人为固定。[原始报告](../../artifacts/performance/v2.6.0-audit/android-optimized-final.json)，脚本退出 0，九份样本均无采集到的应用错误。

| 三次冷启动中位数 | 基线 → 优化后 | 缩短 |
| --- | ---: | ---: |
| 世界就绪 | 20.36 → 14.25s | 30.0% |
| 开场结束 | 21.92 → 15.89s | 27.5% |
| 世界重建 | 16.53 → 10.95s | 33.8% |
| 装饰阶段 | 13.26 → 8.84s | 33.3% |
| 最大主线程长任务 | 16.63 → 10.95s | 34.1% |

准备时间明显减少，但海岸的同步装饰规划仍约 7.3s，冷启动仍有约 11s 的大任务，不能说卡顿已全部解决。新环境等待计时与几何准备并行，包含主线程阻塞，不与其他阶段相加，也不把它解释成 11s 的网络请求。

开场后的三次十秒空闲窗口均无长任务，rAF 的 p95 约 16.7–16.8ms。首次旋转的最大长任务从 1.17s 到 0.57s，后一次旋转窗口无长任务；但两版旋转都触发已有自适应降档，采样结束时档位不完全相同，不以这些值宣称固定画质帧率提升。GPU timer 不可用，rAF 不是硬件绘帧成绩；原生双指缩放和真实任务提交未测。

最终交付关闭诊断开关，排除原生和 Web 采集器；完整门禁后只核对安装身份和摘要，不重复手机体验。

以上对照先于用户追加的冰原旧树、海岸沙条和火焰返修。性能重写保持原装饰摘要；后续地形／树木修复会有意改变海岸布局，不能沿用原摘要，也不能把构建 58 的测量说成最终包再次实测。原始记录保留，最新场景另做几何和实景回归。
