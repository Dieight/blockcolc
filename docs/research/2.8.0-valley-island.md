# v2.8.0 山谷与海岛的地形外观

2026-10-17。状态：隔离对照完成，尚未采用。接续[林缘与礁缘](2.8.0-world-ecotones.md)，按用户追加要求把山谷和海岛一并纳入；本轮不改正式世界、不出包。

后续：用户已批准采用有效方向，正式取舍与验证见[外观整合](2.8.0-appearance-integration.md)；下文保留本轮实验原始结论。

## 审计发现

山谷的建筑支撑区按矩形距离向山体淡出，原高度上限又抬升得很快，容易把建筑围成盆地。近景和中景分别在 2／4 格单元中心采样，同一山坡到边界会出现额外高差。还有一处旧调用问题：`sampleHydrology` 已经返回了干河岸的坡面高度，但上层只接收有水的结果，把干岸丢掉了。本轮在实验包装中接回，正式源码尚未修正。

海岛主丘的半径偏小、高度偏大，遇到建筑支撑影响又直接归零，形状更接近尖锥。外岛也采用偏尖的衰减。低岸实际用了泥土，大段岩岸较平；从俯视角看，容易成为一圈平板。现有水域、海峡和外岛位置不应为改外观重新抽取。

## 调研依据

- [NPS 海岸地貌](https://www.nps.gov/subjects/geology/coastal-landforms.htm)区分侵蚀与堆积地貌，岸线并非等宽沙环。本轮据此区分低湾与暴露岩岬，不声称模拟了侵蚀过程。
- [Red Blob 的岛屿整形实验](https://www.redblobgames.com/maps/terrain-from-noise/islands.html)展示整体形状约束对内部细节的影响。这里借用分开处理大形与局部起伏的思路，没有照搬其中某个函数作为标准答案。
- Minecraft 官方的[沙滩](https://www.minecraft.net/en-us/article/around-block--beach)与[石岸](https://www.minecraft.net/fr-ca/article/around-block--stony-shore)说明可作为沙湾、临山岩岸的外观参考；[世界生成说明](https://www.minecraft.net/en-us/article/new-world-generation-java-available-testing)也区分山形与群系匹配。这些资料不是 MC 26.3 的精确算法清单，本轮未复制其生成代码或素材。

## 原型与取舍

| 分项 | 做法 | 本轮判断 |
| --- | --- | --- |
| 山谷形态 | 支撑区外围改为更宽、带缓慢变化的坡脚；接回干岸结果；复用前轮真实邻格的近／中景衔接 | 坡脚与河岸改善明确，保留方向；盆地感和方块台阶仍在 |
| 山谷表层 | 按邻域坡度重新选择草与裸岩，不移动高度 | 额外采样太贵，画面收益小，暂不采用 |
| 海岛形态 | 主岛尖丘改宽、压低丘顶，柔化支撑淡出；外岛改圆缓丘肩 | 尖锥感减弱，但增加面数；仍需收敛几何成本 |
| 海岛表层 | 低湾用原生沙，保留暴露石岸，内陆延续草地 | 成本较轻，可继续打磨；水域未动，主岛偏圆和宽沙环并未彻底解决 |

`shape`、`surface` 与 `all` 分开比较。组合仅用于观察相互影响，不代表整套都应合并。实验只在独立 Vite 服务包装现行采样，派生输入带实验模式；关闭后核对完整原几何恢复，没有写入正式缓存或改变世界 seed。

## 实际画面

固定晴天 15:00、balanced、精细远景、960×640，使用现行 renderer 和合成任务。两侧统一把额外立面暗色设为 0.65，保留投影，不混入海岸候选、表土几何或 MC 纹理。基线是当前工作树，不是手机上已安装的 /96。

默认种子 24 栋录制四种模式；60 栋和另一种子 24 栋录制基线／组合。每个世界再旋转 90°，共 16 个实际世界、32 张截图。

边界统计只取实际近景范围两侧的陆地邻点，不是全世界最大坡度；24／60 栋的近景边缘分别在 ±128／±168，未用固定半径掩盖扩建结果。海岛默认 24 栋增面约 33%，绝对增加 3722 个三角形，不能据此说手机无性能代价。

各候选的实际任务变换、完整地基采样、水域几何和水位一致；海岛外岛参数不动，三组实景的沉船都保留在完全相同的位置，包括 60 栋世界。生成的村庄等景观可因地形适宜度改变位置，不等于用户建筑移动。额外奖励地基另在独立几何矩阵检查，不冒称实景截图中有这一试件。

已审看两环境默认／旋转、24／60 栋和另一种子：山谷坡脚更连续，但不能说山形已完全自然；海岛低湾与石岸更清楚，圆盘轮廓仍有残留。[比较页](../../spikes/valley-island/review.html)可切分项和视角；局部查看仅放大原截图。

## CPU 代价

另用固定合成任务，在 Node CPU 下每路径预热一次，再做三组交替 AB／BA。生成与紧凑构网分开计时，哈希检查在计时外。这套任务 ID 与实景、额外奖励矩阵不同，不能混用三角形计数，也不是 Android 启动或 GPU 测量。

| 输入与候选 | 生成中位数：基线→候选 | 紧凑构网中位数：基线→候选 |
| --- | ---: | ---: |
| 山谷 24 栋，仅形态 | 1223→1462ms | 366→329ms |
| 山谷 24 栋，组合 | 1100→2242ms | 295→317ms |
| 山谷 60 栋，组合 | 968→2275ms | 283→281ms |
| 海岛 24 栋，组合 | 360→391ms | 27→29ms |
| 海岛 60 栋，组合 | 573→669ms | 40→43ms |

不同分项各有自己的配对基线，受预热、GC 等影响，不跨行比较基线高低。原始时序均保留在[CPU 报告](../../artifacts/visuals/v2.8.0-valley-island-20261017/cpu-benchmark.json)。山谷坡度重着色需要重复邻域采样，是本轮舍弃整套组合的主要原因；保留方向也不能原封不动搬入生产，要把共享高度和岸坡合并到原有采样中。
