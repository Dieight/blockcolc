# v2.9.0：复杂场景与表面内核迁移实验

2026-10-19，接续[首轮设备实验](2.9.0-native-oneplus.md)。用户认为首轮任务过于简单，要求从正式版抽取复杂场景、光影和材质，并尝试其他技术路线。本轮只修改正式夜间亮度／低频路灯及独立实验；没有授权完整迁移或再次发布。

后续实际呈现、共享／合批与生产调用占比已另做[补充实验](2.9.0-native-followup.md)。此页保留原始固定回调的结果，不与后续固定时长数据混合。

## 输入与方法

取生产海岛、海岸，各 25 栋，混入庄园、樱花仓库等补充蓝图。使用当前原创材质、体素模型、地形、装饰和冻结的云；两份输入包含约 165 万／237 万三角形、317／361 张纹理、760／1,346 个材质及大量透明表面。不是首轮一个 draw call 的顶点色模型。后续覆盖复核发现，海岛 GLB 含 `animal-cuboids`，海岸没有；导出结束后的动物就绪诊断不能证明此前已包含动物，不计完整动物负载，见补充记录。

[固定输入](../../artifacts/experiments/v2.9.0/complex-input-corrected/manifest.json)及[代码](../../spikes/native-world-complex/README.md)。Three WebView、Filament GLES、Filament Vulkan 读取同一 glTF 摘要、相同 720×960 缓冲、镜头轨迹、2048 阴影图；每次 120 次前台预热、300 次回调，再单列同步排空样本。不同后端顺序轮换，保存温度、实际提交／跳过、内存和完成截图。只给实验窗口请求 60Hz，不改系统刷新率或电池策略。

GLTF 不携带 Three 自定义着色器。天空、折射／反射、云与动物的运动未等价，PBR 光照和色调映射也有差异；不能据此宣布整个 App 的画面已迁移。输入去实例化，三条控制路线的批次相同，但与正式场景批次不同。同步排空的 `flushAndWait` 与 `gl.finish` 边界不同，包含 CPU／驱动／呈现等待，不作为纯 GPU 时间或直接排名指标。首帧是提交时刻，也不是正式 App 启动就绪时间。

## 计算路线

使用正式混合补充蓝图的 1／7／25 栋，8,813／39,297／120,845 个体素。保留生产占用掩码，以当前 `staticVoxelSurface` 的位置、法线、UV、索引和体素归属五个缓冲为参考。新增紧凑 TS、AssemblyScript 0.28.20→WASM，并继续 ART 对照。WASM 包含进出线性内存的复制；编译／预留内存分开记。各 5 次预热、7 次测量，逐字节比对。

[输入](../../artifacts/experiments/v2.9.0/complex-compute-inputs/manifest.json)、[最终桌面报告](../../artifacts/experiments/v2.9.0/wasm-desktop-no-temporaries/report.json)、[代码](../../spikes/native-kernel-wasm/README.md)。桌面三种路线的全部输出一致；桌面收益不代替手机结果。该内核只覆盖立方表面处理，不包括整套 AO、材质路由或自定义模型。

## 计算结果

OnePlus 三轮全部输出逐字节一致。每轮先预热 5 次，再测 7 次；下表取三轮中位数的中位数，包含该内核解码／构建／编码，WASM 包含进出复制。12 万体素样本：

| 路线 | 三轮中位数（ms） | 汇总（ms） |
| --- | --- | ---: |
| 当前生产 TS 算法 | 444.9 / 378.4 / 433.0 | 433.0 |
| 紧凑 TS 控制，去除逐面临时数组 | 201.0 / 196.0 / 202.8 | 201.0 |
| AssemblyScript → WASM | 121.1 / 116.3 / 114.2 | 116.3 |
| ART，两遍精确分配 | 306.84 / 296.18 / 291.79 | 296.18 |

[六份完整设备报告](../../artifacts/experiments/v2.9.0/complex-kernel-device-two-pass/index.json)。较确定的收益在表面计算：紧凑 TS 已约 2.15 倍，WASM 相比原算法约 3.72 倍、相比紧凑 TS 约 1.73 倍。算法、分配和数据布局同时变化，不能归因于仅换语言；这些也不是整个 App 的提升倍数。输入包含真实蓝图的混合方块，正式渲染另有造型、AO、纹理和缓存路由，这里没有把全部流程都迁入内核。WASM 仍在 WebView 中运行，不代表已实现纯原生 Android 计算或 Rust／C++ 对照。

ART 原先按六个面预分配所有数组，在该手机 256 MiB Java 堆上溢出；未加 `largeHeap`。改为先计数、按实际可见面分配后，同样规模三轮通过。首轮 [OOM 截图](../../artifacts/experiments/v2.9.0/complex-kernel-device-final/kernel-1-art.png)和失败索引保留。

## 渲染结果

四组共 48 份渲染报告完成：默认后处理 18 份、关闭阴影 6 份、关闭原生 FXAA／抖动 12 份，以及补齐实际提交帧 CPU 计时的 12 份。全部零失焦，输入摘要、分辨率及最终 APK 身份均已核对。下表原生采用最后一组，避免把廉价的跳过回调算进 CPU 中位数；Web 本来每次都调用 render。CPU 列取三轮中位数的中位数，实际提交列保留三轮范围。

| 场景 | 后端 | 实际提交时 CPU（ms） | 每 300 次回调的实际提交 |
| --- | --- | ---: | --- |
| 海岛 25 栋 | WebView WebGL | 13.90 | 300 次 render 调用，未测最终呈现数 |
| 海岛 25 栋 | Filament GLES | 7.26 | 192—221 |
| 海岛 25 栋 | Filament Vulkan | 7.39 | 163—186 |
| 海岸 25 栋 | WebView WebGL | 17.40 | 300 次 render 调用，未测最终呈现数 |
| 海岸 25 栋 | Filament GLES | 8.00 | 181—183 |
| 海岸 25 栋 | Filament Vulkan | 9.30 | 149—154 |

Web 的帧回调 P95 在海岛约 16.7ms、海岸约 33.3ms；原生约 16.7ms，但回调并不总能提交。因此原生提交的 CPU 成本较低，不等于已经证明画面更流畅，Vulkan 也没有胜出证据。没有 GPU 时间戳和跨引擎一致的最终呈现计数，不把这些列换算成可直接比较的 FPS。

已审看两种场景、三个后端各一张最终完成截图，以及最终计算完成页。建筑、纹理、地形均有实际显示，不是扫描或空白页；原生光照偏亮、阴影响应及透明／水面表现仍与 Web 不同，不视为视觉验收通过。完整原始记录与设置见[汇总](../../artifacts/experiments/v2.9.0/complex-summary/report.json)、[Web 与默认原生](../../artifacts/experiments/v2.9.0/complex-device-final/index.json)、[最终原生提交计时](../../artifacts/experiments/v2.9.0/complex-device-measured-submissions/index.json)。

这里的冻结 glTF 为了统一几何而展开实例，两份约 190／271 MB；这是实验输入，不是原生正式缓存或将来的包体方案。不要把它们封入正式 App。后续若迁移，应保留实例、复用纹理／材料和紧凑二进制，而不是直接采用这份膨胀的交换格式。

## 本轮取舍

值得先做的是紧凑布局、减少临时分配和批量传输；这是不迁移整个引擎也能获得的收益。WASM 是后续计算模块候选，当前没有接入正式渲染；若转纯原生，还要另外比较 Kotlin／Java 与 C++／Rust，并计入桥接、缓存和维护成本，不能拿本次 WASM 数字替代。

Filament 保留为世界渲染候选。下一轮应保留实例、合批并缩小资产体积，再补水面／玻璃／动态天气与完整画面，而不是按 CPU 提交成本直接换掉 Three。Compose 首轮界面实验仍独立保留，本轮没有重复测它，也没有宣布整套 App 的冷启动或耗电获得提升。

## 原始失败

- 系统默认 JDK 25 不兼容当前实验 Gradle，改用现有 Android Studio JBR；没有升级或更改正式工程。
- 首次加入复杂输入目录与旧目录的 `manifest.json` 重名，改为生成目录白名单，只封装实际输入。
- 首轮导出忽略水面的 `drawRange`，且保留空材质组；图中出现跨地形的三角形和水面覆盖，三次设备试测不用于结论。修正后增加两项导出器反例并重新导出，原输入、截图、试测保留。
- Web 对照曾未更新扩展后的阴影投影矩阵；已修正，并在同镜头实际 GPU 读回中确认开／关阴影改变 30,176 个像素。最初只关闭阴影图更新不能移除已绑定的阴影，验证改为同时移除光源投影标记；原失败保留。
- Filament 默认有 FXAA／时间抖动，而 Web 控制未启用抗锯齿，因此另加明确关闭的原生对照，不把模糊程度差异当作材质移植等价。

正式部分另完成夜间补光下调（半球 1.78→1.58、曝光 1.52→1.43）和稀疏路灯：按道路规模分配，间距至少 24 格、最多 8 盏，避开建筑；不恢复建筑上的自动补灯。只影响表现，不改变日月方向、天气或记录。当前源码接续 /100，尚未另出包。
