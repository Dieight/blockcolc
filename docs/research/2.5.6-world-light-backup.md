# v2.5.6 地形、光照与备份

日期：2026-10-03，实施更新 2026-10-05。状态：方案已采用，检查见开发记录。
关联需求：[本版范围](../versions/2.5.6-development.md)。

## 地形

现有山谷和海岛按近、中、远网格取样，细节区扩大过，但相邻不同尺度的高度及侧面仍可能在边界不一致。先用固定 seed 和旧/新地形建立边界高度诊断；仅扩大近景或加遮雾无法解释高纵向切面。

已定位山谷 V4 的一处明确原因：原规则只给粗格抬高远山，并用圆形距离计算抬高，而 LOD 边界是方形。角落进入粗格时可突然多出二十格高度。现已让远山抬高共用世界坐标规则，并加入 32 格边缘过渡；边界的细格匹配实际粗格，角格单独桥接。保留水系、任务支撑和旧生成版本。

网格定点结果与失败记录见[本版检查](../versions/2.5.6-development.md#检查记录)。河岸天然高差不当作 LOD 墙，统计按完整边界长度计入平接处；只统计非零侧面会把两个自然角落误判为整条墙。海岛和扩张聚落已纳入纯测试，24 栋组合环境已实际绘制；手机构图仍待体验，不以山谷单项代替全部地形验收。

[Voxy](https://github.com/MCRcortex/voxy) 本次核对版本为 `534d58ec8b4aa412ef314b884295552c69d480a6`。其[体素分级](https://github.com/MCRcortex/voxy/blob/534d58ec8b4aa412ef314b884295552c69d480a6/src/main/java/me/cortex/voxy/common/voxelization/WorldVoxilizedSectionMipper.java)从同一体素内容逐级聚合八个子单元；我们应参考“粗细层来自共同内容”的思路，而不是让远景另画一张不相接的高度图。当前[许可](https://github.com/MCRcortex/voxy/blob/534d58ec8b4aa412ef314b884295552c69d480a6/LICENSE.md)为保留权利、不得再分发；不移植其代码、shader 或资源。

本项目的实施方向：连续的地形函数、成对边界取高与接缝闭合，按距离保留阶梯轮廓；装饰仍落在实际表面，不在粗网格上缩成方箱。用面积/群系配额规划云与装饰，新增区域可增加密度总量，但不挤占已有任务保护区。新组合环境先按海陆、温湿度和起伏形成大分区，再放海岸、平原、森林、山谷、雪山/冰川与恶地过渡，不把所有种类随机撒在每个小块。

### 斑驳森林与暖海核对

2026-10-04：斑驳森林不是苍白花园。核对 [26.3 官方更新](https://feedback.minecraft.net/hc/en-us/articles/46861657001101-Minecraft-Java-Edition-26-3-Snapshot-1)，应使用红、橙、黄杨树、倒木和废弃营地的方向，而非苍白橡木。本轮补回成片彩色杨树和相应营地；倒木、层架蘑菇不因此算作已实现。

用户本地 `26.3.jar` 的 SHA-256 为 `4508d006323f24fa02876310c192d739af56516eb259000ac50f0909a68c9a2d`。所查条目为 `data/minecraft/worldgen/biome/dappled_forest.json`、`biome/warm_ocean.json`、`feature/red_poplar.json` 和 `placed_feature/trees_dappled_forest.json`。其中杨树树干基高 7、随机增高 4，斑驳林为三色树叶；暖海水色为 `#43d5ee`。据此调整原创树形、树群、近岸珊瑚和浅水通透度，不复制上游结构 NBT，也不把 JAR 打入 APK。[珊瑚说明](https://www.minecraft.net/en-us/article/block-week--coral)用于核对暖海礁体类型；规则在既有群系及实际水位上应用，不另加假岛。

珊瑚配额先放实际近岸，再补远端；原创材质按管、脑、气泡、火、鹿角五类区分颜色，死珊瑚单用灰色。`fire_coral` 需要先于泛用 fire 规则判断，不应变成发光材质。水下能辨认礁体也需检查真实视野，生成计数不代替外观。

后续用户要求连片礁群，已替换重复的小礁模板：低频噪声决定不规则珊瑚床和颜色片区，沙道穿过其间，再放高低分枝。每列都检查实际暖水与地标保护范围。近景和远景使用同一批实心方块，水草、珊瑚扇和海泡菜保留自己的模型；不拿增加小模板数量冒充大礁群。

## 光照

[NOAA 的曙暮光定义](https://www.weather.gov/fsd/twilight)使用太阳几何中心低于地平线的 6°、12°、18°。蓝调不是固定半小时；根据太阳高度过渡，保留极昼、极夜、天气遮挡与现有折射约定。落日红粉属于表现方案，要和气溶胶/云层色调、昼夜亮度一起算，而不是给每个日落随机切一种颜色。

[NASA 夜空说明](https://science.nasa.gov/skywatching/?os=i)指出银河是在暗天空下可见的微弱带状光；月光、云和暮光应降低可见度。[极光](https://science.nasa.gov/sun/auroras/)由太阳粒子、磁场和大气共同产生，并非下雪导致。新环境的冰雪分区可用艺术化的高纬极光，但在没有空间天气数据时不能标作当地真实极光预报。

天空、云遮挡、星河、流星、极光与水/玻璃反射共用可见性及方向，不分别画互不一致的图层；真实坐标使用现有天文上下文，本地月相也按实际日期计算并走同一渲染路径。当前采用方向场近似倒影，不是全场景物理反射或当地真实星图；隐藏、减少动态及世界重建时正确释放和恢复。

原银河细节按经度、纬度做二维噪声，经度在 ±π 跳变时会产生接缝，水面让这条线更显眼。现改为球面方向上的三维多层噪声，增加尘带、暗隙和细颗粒；极光的经度谐波也改为完整周期。天空和反射继续共用同一个场，不把水面贴图拼起来遮接缝。这是表现改进，不能据此声称手机帧率没有额外成本。

和风公开[月相接口](https://dev.qweather.com/docs/api/astronomy/moon-and-moon-phase/)列出月升月落、月相、照亮比例与图标，未提供日食时段、食分或当地可见性。此次条件项没有可直接接入的数据；不能把新月或近似日月重合当成日食。独立日食模型/数据属于以后另行确定的范围。

## 加载耗时

加载页确实覆盖了当前世界的地形、材质、shader 编译及开场两帧绘制，目的是让撤下遮罩后可以立即操作；不是预先载入所有页面和所有材质包。之前世界模块要等天气的有界等待结束后才载入，现让两者并行。shader 准备期间也不再由云、降水和光照运动反复触发额外绘帧。

世界模块、天气等待、shader 和开场绘帧分别留下实际耗时。离线天气等待仍有 8 秒上限，不取消首帧光照与天气的正确准备。手机各段耗时和最终等待感需要同机实测，软件 WebGL 的总时间不能换算成手机提速比例。

## 备份

现有 `IndexedDbStateRepository` 只保留最近两份自动回滚快照，删除、导入和恢复使用原子事务。它们是操作回滚，不是每天历史版本，不能让日备份挤掉删除/导入快照。

建议升级每日历史，但不采用任意 JSON 逐字段补丁链：任务和蓝图共享体积较大的不可变快照，更适合内容寻址去重、每日清单引用完整的逻辑状态。这样恢复一个日期不依赖连续完整的前序补丁，损坏范围更小；用户导出仍是独立、可校验的完整备份。

最初批准 30 天 / 200 MiB；后续用户改为只保留一份滚动合并档、200 MiB，当前约束见产品与架构文件。仍采用内容块与完整清单，前台到 0 点或第二天启动时补上一日，日期以用户本地日历为准，并标明实际捕获时间。备份失败不阻断专注，也不先写成功日期。保留独立操作快照、校验和、旧封套读取及恢复前备份，不在调研里重复列测试结果。

## 验证办法

地形检查粗细边界、旧 seed、扩张聚落、反向旋转与极限缩放；光照检查晴/阴、日出日落、无月夜、两种来源和反射；备份检查跨日、重复启动、写失败、存储裁剪、缺块和旧包恢复。方案记录不算实现或通过证据。
