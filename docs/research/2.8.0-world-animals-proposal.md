## 我建议的方向

动物作为聚落环境的一部分：数量适中，有成群、停顿和偶发动作，放大看得到身体动作，远看也能辨出轮廓。用户已认可 MC 实体式的方块身体、关节动画和像素贴图，并希望轻点后有小回应。具体比例与动作仍待小样确认。

轻点可让动物转头、短暂停步、抖耳或扑翼，不做每次都逃跑的强反馈；旋转世界的拖动不能误触动物，也不能透过建筑点到被遮挡的动物。

| 场景 | 动物和活动 |
| --- | --- |
| 海岛／海岸 | 银色海鱼、暖海彩鱼等小鱼群；沿岸和礁缘巡游，转弯时队形松散，少量个体偶尔鱼跃；入水有短暂涟漪 |
| 山谷水域 | 河鱼沿实际连通河道游动，在较深的河段停留，偶尔跃出并落回同一水域 |
| 山谷陆地 | 牛羊走动、低头吃草和休息；猪拱地、马慢走或短暂小跑，各自有不同节奏；道路、院落和建筑区内实际可通行的位置也允许进入，按身体大小避开障碍、深水和危险落差 |
| 全部聚落 | 海边以海鸥、林地以小型林鸟、开阔处以燕形鸟为候选；扑翼、滑翔与停栖交替，空岛保留跨岛飞行 |

栖息地只影响活动倾向，不是建筑区外的一圈无形围栏。动物可走遍全图中自身能到达的通路，不强求陆地动物跨越悬崖、海洋或不连通的空岛。鸟群和大型陆生动物不持续挤在建筑中心；鱼跃也不按整齐周期同时发生。日夜、天气只影响活动倾向，例如夜间减少日行鸟、雨天减少远飞，仍需审看实际画面后再定参数。动物声音建议先保持关闭，继续尊重现有白噪音选择。

[Minecraft 官方鲑鱼介绍](https://www.minecraft.net/pt-br/article/mob-menagerie--salmon)可参考鱼群与河流栖息的表现；这里的鱼跃、水花和跨场景行为是项目拟设计的效果，不声称完全沿用 MC AI，也不按该篇旧文章推断 26.3 的完整实体清单。

## 全图活动与世界重建

全图活动不要求重建世界。拟把动物放在独立活动层，与静态地形、建筑、景观共享世界旋转轴；走动只更新位置、关节和实例矩阵，不改地形／景观缓存键，也不逐帧写入任务记录。

需要分清三件事：动物运动会要求绘制新画面；障碍变化可能要求更新寻路数据；实际地形和建筑变化才按现有流程更新世界。不能把这三件事都做成世界重建。提交施工后，碰撞只采用实际已建成且仍完整的部分，不把施工轮廓当成实墙；优先更新受影响的导航分块并让附近动物改道。地形因扩张而整体变化时则重新核对对应通路。

## 高低差、碰撞与寻路

这部分是拟补充的能力，不是现有地表查询已经具备的功能。

- 支撑面来自实际地形和建成方块的统一空间数据，不能另算一套与可见台阶不一致的噪声高度。一个位置可能同时有桥面、桥下地面和楼层，需保留多个可走层及头顶净空，不能只取最高点，否则动物会突然爬上屋顶。
- 身体用简化碰撞体，按动物的宽高检查通道。常用完整方块、半砖、楼梯、栅栏等需要碰撞形状；未知导入模型先保守阻挡。小动物能过的门洞不代表马也能过，不把整栋建筑的包围盒都判成禁区。
- 小台阶走上去，允许的整格落差用短跳通过，陡坡／深坑绕路；跳前检查起点、落点和途中净空。不能只让身体高度跟随终点插值，那会从台阶侧面穿过去。移动采用扫掠碰撞或受限子步，防止掉帧后一步穿墙；脚部轻量贴地，身体转向与步态平滑跟进。
- 先用游荡、吃草、休息、同伴跟随、轻点回应几个行为状态。寻路采用分层通路图：远处先选连通区域，近处用 A* 选具体路径；路径边区分行走、上台阶和跳跃。换目标、被堵住或附近施工时才重新规划，逐帧只执行移动和局部避让。

[Red Blob Games 的 A* 说明](https://www.redblobgames.com/pathfinding/a-star/introduction.html)区分了路径图与实际移动：路线搜索本身不负责穿门、跳跃或碰撞。本项目的通路、净空和移动动作必须另行实现与验证，不能只接入 A* 就视为解决穿模。

## 当前实现带来的约束

这些是正式 App 源码的约束；隔离实验的进展与限制见[实验记录](2.8.0-world-animals-experiment.md)，不代表正式功能已经完成：

- `renderer.ts` 中只有海岸水面启用半透明，海岛和山谷主要使用不透明表面；鱼放在水下会被挡住。需要配套水深、河床／海床和受控的水下可见性，保留天空倒影和近岸颜色，不能只让鱼无视深度画在水面上。
- `scenery.ts` 规划的是静态结构和合批树木，动物需要独立的活动层。静态地形、建筑和景观不应随动物走动而重建，也不应在计时命令中保存动物的每步位置。
- `surface-index.ts` 当前提供单个地表支撑查询，不包含建筑内部的多层通路、净空或实体碰撞；`surfaceSampler` 还会按查询坐标保留结果。动物持续使用小数坐标时不能直接永久复用这个逐点缓存，应增加有界的分块查询，避免运动越久缓存越大。
- 目前已有单槽帧调度、天气自适应运动、前后台和减少动态控制。拟让行为低频更新、姿态按绘帧时间插值，复用可见性与运动控制；视野外休眠，回到前台不追补一长段运动。具体实现和功耗仍须实验，不能预先承诺零开销。
- 动物模型与实体贴图须有自己的资源入口，现有方块材质路由不能自动提供完整动物模型和动作。近景／中景可减少身体细节，过小时平滑淡出，保留可辨识轮廓。

## 先怎么验证

建议在实际世界里分别做鱼群／鱼跃、牛羊活动、飞鸟起落三个短动效小样，先看正常镜头与最大缩放下的比例、活动频率、遮挡和远景，再扩充种类。陆地小样同时验证穿过建筑区的道路与院落、上下台阶、桥下通行、按体型通过门洞、悬崖止步，以及施工后改道；再覆盖水陆边界、相机旋转、普通／极简、前后台、减少动态和恢复。性能另测首帧、稳态旋转、亮屏功耗、长时间缓存增长，以及 24／60 栋建筑规模下的寻路与局部更新。

待讨论：活动和寻路细节、交付版本及首批种类。现有方块羊、碰撞与活动层仅在独立实验中；鱼、鸟及更多动物尚未制作，也未接入正式 App。
