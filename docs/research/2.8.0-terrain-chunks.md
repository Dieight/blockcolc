# v2.8.0 分块网格实验与构网分组优化

2026-10-16。数值分组已采用源码改动；空间分块仍是隔离原型。接续[共享地表实验](2.8.0-terrain-surfaces.md)，基线是上轮已优化的 v2.8.0 工作树，不是正式 v2.7.0 APK。未出包。

## 审计与资料

地形采样依赖全局核心半径、LOD profile、地基和排水。海岸群系间距、海岛主岛形状也随核心半径变化，不能凭 seed 和区块坐标采用旧地形。日常推进已有整块地形／GPU 复用；奖励不改变地形，不能把既有缓存收益算成分块新收益。

- Voxy 固定提交 `534d58ec8b4aa412ef314b884295552c69d480a6` 的 [WorldSection](https://github.com/MCRcortex/voxy/blob/534d58ec8b4aa412ef314b884295552c69d480a6/src/main/java/me/cortex/voxy/common/world/WorldSection.java) 把一个细节层的 32³ 数据、脏状态、引用与缓冲回收放在明确的区块生命周期里。这里借鉴的是职责和失效边界，没有移植其代码或替换现有高度／水文算法。
- 本地 Three.js 是 0.178.0。[同版本 BufferGeometry](https://github.com/mrdoob/three.js/blob/r178/src/core/BufferGeometry.js) 的材质组分别提交绘制。因此，分成许多 mesh 不能只看 JS 构网更快；还要算非空材质组、边界和缓存占用。
- [0 FPS 的网格分析](https://0fps.net/2012/06/30/meshing-in-a-minecraft-game/)同时讨论面数与构网延迟。此次将两项分开记录，不把单次构网时间作为唯一取舍。

## 分块原型做了什么

[原型](../../packages/voxel/tools/terrain-chunk-prototype.ts)只划分**已经完整生成、封边和补缝的几何**。一张面只归一个块，即使跨块边界也不裁断、不补新的竖裙；若以后独立裁剪，各块仍须采用实际几何范围，而非假设面一定在格内。

缓存只留上一份布局。全局 profile 名字空间一致后，还要比较本轮与上一轮块内的真实材质索引和顶点，不能只比块坐标或哈希。所有新输入仍先完成全局生成；这不是增量地形生成。

覆盖校验采用独立的平面扫描线，保留朝向、材质、洞与重叠次数，不只比较总面积。另有反例验证：面积相同但洞或位置不同、重复面、翻面和材质变化必须失败。

四环境的 24 栋／默认种子上试了 64、128、256 格。以 128 格为例：

| 环境 | 整块 → 分块三角形数 | 整块 → 分块非空材质组 | 原型缓存估算 MiB |
| --- | ---: | ---: | ---: |
| 空岛 | 2098 → 2246 | 3 → 12 | 3.65 |
| 山谷 | 175202 → 178146 | 5 → 540 | 43.68 |
| 海岛 | 11322 → 12398 | 6 → 463 | 11.69 |
| 海岸 | 93136 → 94944 | 9 → 318 | 25.34 |

材质组是假设各块单独绘制且尚未裁剪时的统计，不是手机实测 draw calls。若拼回一个 mesh，可维持原材质组数，但须复制并保留拼接结果，也没有独立分块裁剪的收益。上表缓存包括源几何、共享地表／索引、分块索引和块网格，**不含另存一份拼接网格**；不是进程峰值内存。山谷原型不能留在现有 32 MiB 预算内。

24→25 栋的五组成对实验中，海岸 128 格命中 99 块、重做 1 块：旧整块构网中位约 302ms，分块更新**连同每次实际拼接**的中位约 70ms，确有潜力。其他三环境也有结果，但山谷因超预算没有保留上一份块缓存。24→60 栋扩张及换种子的另 24 组实验里，该保守名字空间均失效，不能复用旧块。不能把小幅扩建成绩当作冷启动、全部扩张或日常推进成绩。

原始记录：[首次五方案](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/initial-quick.json)、[24→25 栋](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/initial-transitions.json)、[扩张与换种子](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/global-transitions.json)。这些分块对照使用同一冻结 JSON 分组器来隔离分块本身的影响，不能跨轮扣减下面新分组器的耗时。

[实验驱动](../../packages/voxel/tools/terrain-chunk-audit.ts)与浏览器诊断复跑需使用原冻结目录（可通过 `BLOCKCOLC_CHUNK_AUDIT_OUTPUT` 指定），并用新的输出 tag；它们不是构建依赖。不覆盖旧参考，也不把当前实现重新抓成旧基线。公开的稳定回归另由固定指纹测试承担。

决定：原型保留，暂不改 App 的 mesh 组织、透明面排序、持久化格式或裁剪。后续可继续研究小幅扩建，但不为命中缓存而改地貌和水系。

## 实际采用的改动

构网合并时，每个矩形、每次扫描都生成 JSON 组合键。尝试直接拼字符串反而更慢，未采用。完整四层数值 Map 更快，但海岸离散堆采样由约 47 增至 65 MiB，也没有直接交付这一稿。

最终方案仍用数值查找，不过最末层先存单个范围；确实出现另一个上界时才扩成 Map。另用首次发现的组列表保持原出面次序，不按嵌套 Map 展开，分组结束后清掉临时查找表。排序、两轮合并、坐标、UV 尺度、面数和最终缓冲顺序均不变。

32 输入覆盖四环境、1／24／60 栋、两种子，以及自动／粗远景和 60×60 足迹。完整原地形和最终网格哈希与前轮 32 组逐一一致；不是仅做面积对照或重录外观预期。持久化内容大小不变，缓存 revision 仍为 3。架构归属见 [ARCHITECTURE](../../ARCHITECTURE.md)。

### CPU 对照

四个 24 栋／默认种子／精细远景输入各预热后做五组成对 A/B、B/A；其他输入各做一次等价对照。以下为中位数，单位 ms，只计紧凑构网。原始地形生成、导入模块、散列、存储和 GPU 不在其中：

| 环境 | Node：JSON → 新分组 | 桌面 Chromium：JSON → 新分组 |
| --- | ---: | ---: |
| 空岛 | 18.0 → 9.2 | 16.7 → 10.2 |
| 山谷 | 653.5 → 425.8 | 483.8 → 325.9 |
| 海岛 | 60.3 → 34.0 | 50.7 → 32.5 |
| 海岸 | 278.9 → 190.0 | 227.1 → 159.3 |

Chromium 是隔离同源空页面、移动视口，不加载 App 或数据库，也不创建 WebGL；其模拟 Android 的 UA 不代表 OnePlus 实机。两种运行都没有并行跑其他重测试，没有锁定系统频率，不由五组样本推断 P95。

收益发生在**确实需要构网时**。已有地形／GPU 网格命中而跳过构网的路径不会因此再快一遍；本轮没有测整机冷启动、旋转或专注提交总耗时，不能把表中差值直接叠加到 /96 成绩。

记录：[最终 32 输入](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/final-comparison.json)、[Node 退出日志](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/final-comparison.log)、[浏览器完整数值](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/browser-cpu-values.json)、[采用前核对](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/adoption-review.json)。`adopted-comparison.json` 是四层 Map 的中间稿，不能代替最终报告。

### 临时内存检查

单独的 Node 工具在分组结束和输出完成时取 JS 堆样本，每次运行前及输出后显式 GC；不使用这轮耗时作为 CPU 成绩，也不把采样当严格峰值、分配总量或 Android 内存。

最终候选的五组“相对运行前堆占用增加”的采样中位数：山谷约 190→170 MiB、海岸 47→42 MiB，海岛约 33→33 MiB；没有再次观察到首稿的海岸增加。输出保留量基本相同。离散采样可能漏掉中间峰值，32 MiB 缓存预算也只是数值内容／元数据估算，不等于瞬时 JS 堆上限。

[原始内存记录](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/adaptive-heap.json)与[日志](../../artifacts/performance/v2.8.0-terrain-chunks-20261016/adaptive-heap.log)保留。采用源码与这份候选的去注释编译 token 一致，网格结果也逐一核对；内存采样只在独立工具／生成的参考文件中插桩，没有加入 App 探针。

## 下一步

优先比较派生缓存解码后的类型化缓冲，减少恢复成 JS 数字数组的复制和实际内存占用，尤其是山谷紧凑网格常因预算无法长期保留的情况。再决定是否值得把分块用于小幅扩建；独立分块生成、Worker 构网和 GPU 分块裁剪都还没有实现。
