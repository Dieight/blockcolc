# v3.0.0 账户、好友与云端备份

更新日期 2026-11-17。统一预览已接入公网 8443 账户服务和 Mutsumi Focus 只读好友。个人专注公报已改用自有 VPS 的网页投影，见 [P4 看板交接](../versions/3.0.0-p4.md#看板迁入自有-vps)。App 交付与备份返修见 [P3 记录](../versions/3.0.0-p3.md#2026-11-16备份返修与账户交接)。

## 问题

新增默认关闭、用户可选开启的账户和好友能力。好友能看哪些专注内容、起止时刻及每日总时长由用户选择。同一账号多设备自动同步；每天结束合并云端备份，稳定时每个用户只保留一份可恢复备份。

旧私人同步接收单一来源的当前专注与日总量。新原生预览接入自有账户服务，提供账户隔离、双向合并和云端恢复点。

## 查到的资料

- 主工程 `export-core/FocusExport` 定义现有最小上传投影；本地 `SnapshotStore` 已按内容块去重，并保留单一每日根与独立操作回滚。可复用边界与算法，不能把只读好友投影当完整账户存档。
- [Android 离线优先架构](https://developer.android.com/topic/architecture/data-layer/offline-first)：先使用本地数据；网络写入排队，重新连接时协调版本和冲突。
- [HTTP 条件更新](https://www.rfc-editor.org/rfc/rfc9110.html#name-if-match)：按版本拒绝过期更新，防止多设备意外覆盖。仅有版本拒绝还不能代替业务合并。

## 已采用方案

- 账户默认未登录，未登录可完整离线使用。登录后同步本机已保存内容，好友功能另外开启，登录不自动公开资料。邀请确认后建立好友关系；提供全局分享默认值及单好友覆盖，初始各项均关闭。
- 当前是否专注、任务名、开始／结束时间、每日总量分别授权。服务端按关系和字段权限返回专门投影；开始时间未授权时，同步隐藏可反推出它的已用时间等字段。缩减权限、移除好友后撤销订阅并清理 App 展示缓存；已经被他人看到的内容无法收回。
- 私人模块的状态投影、推送／重连、重试和到期失效可复用。身份认证、账户数据分区、好友关系、权限及双向同步协议另行实现；不沿用单一上传凭据供所有账户共用。
- 多设备先本地保存，再同步变更。专注记录按稳定身份去重；任务、便签的同项编辑保留冲突候选，删除与恢复单列协议，旧设备不得将已删除内容重新写回。统计从合并后的事实重算，不合并设备汇总数。建筑顺序和奖励位置也要处理并发创建。
- 正在进行的同一计划由一台设备执行，其他设备查看或主动接管，接管不产生新轮次。联网时由服务器执行代次控制；离线设备无法立即得知远程接管，重连时保留其记录并拒绝过期执行权造成的重复提交。
- 当前同步状态和每日恢复点承担不同用途。日常增量更新当前状态，每日以账号时区生成最新完整可恢复根，只上传缺失内容块。新根上传并校验完成后原子替换旧根，再清理无引用块；稳定时只有一份每日备份，替换期间允许暂存。
- 服务器在账号日界线整理已同步内容，离线设备回连后补齐并更新完整性标记；不承诺 Android 午夜一定唤醒上传。云端未收到的离线改动不能假称已备份。
- 同步任务、历史、奖励、便签、世界种子、导入蓝图及应用设备偏好。导入的材质包和音频原件不上传；相关选择以内容身份记录，新设备未导入对应原件时按本机缺失处理，不因此抹掉全局偏好。系统权限、登录凭据、天气密钥及位置缓存不是可同步设备偏好。地形／几何缓存不进入云端备份。已有设备启动不等待网络，新设备首次恢复单列加载过程。
- 首次使用提供新建任务（内选普通／习惯）、恢复本地存档、登录账号恢复云端三条入口。登录新账号没有云端工作区时，引导继续创建任务；取消、失败或只有登录成功不算已恢复工作区。已有数据升级不重走首次使用。
- 好友入口放在任务页标题右侧，使用像素图标与短文字，进入独立好友面板；账户／好友未启用时隐藏，设置管理账号和披露权限，底栏保留原四页。随 P3 一并交用户体验。
- 统一客户端只向自有账户服务同步。原看板域名指向自有 VPS 后，直接从已授权的固定账户读取专注投影。原页面的实时状态和日历沿用，账户注册、登录和站主访客记录接入同一身份库。旧转发交接回执保留。
- 首次登录已有本机与云端两份工作区时，先确认采用或合并，不能用空设备覆盖云端。主动恢复每日备份是账号级回滚，要给新同步代次；离线旧端不能再把回滚前状态覆盖回来。本地每日／操作回滚及手动导出继续保留。
- 作为 P3 独立新增工作包。P4 核对多设备、离线冲突、恢复和权限。P5 发布统一客户端。服务器与客户端各留版本和回退记录。

## 验证办法

验证账户隔离、字段权限及撤销，多设备接管和重连，离线冲突与云端恢复，大蓝图去重、缺失素材回退和传输失败重试。看板核对历史汇总、实时状态到期、登录后的读取权限，以及仅站主可查的访问明细和累计排行。账户流程使用隔离数据，真实资料只读核对。

## 决定

- 用户于本轮提出默认关闭的账户／好友系统、可选披露字段、多设备同步，以及稳定时只留一份每日合并云备份，纳入新增范围。
- 用户已确认：同一账号由一台设备执行专注，其他设备查看或接管。
- 用户确认设备偏好可同步，导入材质包及音频不同步；首次使用增加登录云同步入口；客户端合并，通过自有服务器转发到旧好友服务器。其余上轮方案无异议，纳入范围。
- 用户在确认方案后授权开始实施，网络速度暂不处理、端口另行安排。首版采用用户名／密码，HTTPS 独立监听 8443；好友入口与缺失素材回退按上述方案落地，随预览一起审看。
- 2026-11-17 用户确认把原看板和账户系统放在同一台 VPS，改用方块钟账户登录，记录当天访客与累计次数排行。原向好友服务器转发的方案终止。

## 首次服务器只读核对

2026-11-15 使用用户指定 SSH 身份连接成功。Ubuntu 24.04 LTS、x86_64、2 个逻辑 CPU；可见内存约 3.82 GiB、可用 3.42 GiB；根文件系统约 76.45 GiB、可用 73.98 GiB，负载近零。没有安装账户服务、数据库或反向代理。现有 `xray-codex.service` 正在占用 443，部署需另行安排 HTTPS 入口，不能直接抢占现有端口。未更改服务、软件、文件或防火墙。

硬件适合小规模试运行；没有服务级并发／数据库压测，不能承诺具体用户上限。小流量 SSH 检查中 1 MiB 上传含握手耗时 8.247 秒，下载 20 秒未完成。电脑当前路由经过 Meta 虚拟网卡，此结果不是直连 VPS 带宽；HTTP、移动网络和服务器出口尚未测。网络路径是上线前的待核项。原始本地证据位于私有忽略目录 `artifacts/experiments/v3.0.0/account-cloud-server-audit-20261115/`，不把服务端身份或配置放入公开产物。

## 实施与边界

- 服务在 `services/cloud`，使用 Node 24 内置 HTTPS、SQLite、scrypt，校验直接构建自现有领域模块。部署为独立 systemd 身份，数据目录及 TLS 私钥单独保护；内存上限 1 GiB，不改变现有 443 服务。已部署到指定 VPS 的 8443。
- 原生 `platform-cloud`、`state-store/CloudWorkspace` 与 `NativeCloudController` 分别承担传输凭据、记录装配和同步协调。现有串行写入线程仍是采用入口；网络不挡冷启动或本地提交。登录令牌由 Keystore 加密，不进入备份和日志。
- 同步以逐项摘要比较本机和基线；删除显式传空值，同项冲突不自动选胜者。恢复更换工作区代次；接管更换执行代次。服务器验证计划与任务、会话、历史和截止一致。普通备份恢复不恢复本机自动继续许可。
- 材质／音频只共享偏好引用，不传原件。缺失资源保持共享选择，采用本地回退；没有内容变化时，不重复询问或校验全部大蓝图资产。
- 云端保留实时工作区和一个滚动每日根。新根完整验证后事务换入，损坏不会覆盖当前根。超过 16 MiB 的合法 60³ 蓝图另做实际传输及恢复定点，结果集中记在 P3 工作包，不把限额当作容量证据。
- 转发使用独立、持久且有界的队列和递增版本，默认配置为空。运维绑定工具只接受私有文件中的目标凭据；实际用户注册、旧来源停止及交接核对前，不绑定真实旧服务。部署、回退及操作入口见 [服务说明](../../services/cloud/README.md)。

服务器内部 HTTPS 已通过。电脑到公网 8443 暂未连通，已请用户核对供应商入口；实验经 SSH 转发，客户端仍验证正式服务的证书和 IP 主机名，没有关闭 TLS 校验。补查发现 Windows 当前路由经过 Meta/TUN，VPS 网卡只有私网地址；限时包头观测看到请求变成 VPS 向自身公网地址发起连接。随后按 [Windows IP_UNICAST_IF](https://learn.microsoft.com/en-us/windows/win32/winsock/ipproto-ip-socket-options) 将单个测试 socket 绑定实际 WLAN，仍于 TCP 连接阶段超时，未修改系统代理或全局路由。因此仍需核对供应商的端口映射／入站规则及外部路径，尚不能认定唯一原因是安全组。原始记录位于 `artifacts/experiments/v3.0.0/cloud-public-route-check-20261115/`。公开端口、真实旧来源交接、压力容量和跨设备长期体验分别保留边界，不将 P3 定点写成正式上线验收。

## UCloud 控制台资料

用户希望自行研究配置，本轮仅查官方资料，没有更改控制台。尚未核实实际购买的是 UHost、ULHost 或其他网络组合，以下按实际产品选择，不把文档路径当作已看过用户控制台的结果。

- [UHost FAQ](https://docs.ucloud.cn/uhost/faq)：控制台防火墙独立于系统 iptables，因此此前系统 ACCEPT 不能证明云端入口已放行。
- [外网防火墙说明](https://docs.ucloud.cn/unet/introduction/Overview/Firewall)与[外网弹性 IP 官方手册](https://docs.ucloud.cn/unet/mdToPdf/unet.pdf)：控制台路径为全部产品 → 基础网络 UNet → 外网防火墙。手册的“推荐防火墙”“创建防火墙”说明默认 Web 规则包含 80、443、22、3389，未列出的端口默认关闭；默认规则不能直接修改，可复制成自定义规则后添加，并核对[资源绑定](https://docs.ucloud.cn/unet/guide/Firewall/Bind)。当前应核对目标资源绑定的规则是否允许自定义 TCP 8443，保留既有端口。
- 若是 ULHost，官方[防火墙入口示例](https://docs.ucloud.cn/usa/operation/Hermes-Agent)在轻量应用云主机 → 详情 → 防火墙 → 编辑；这里只参考防火墙入口，不执行文章中其他产品操作。
- [NAT 网关简介](https://docs.ucloud.cn/vpc/introduction/natgw)：只有控制台实际采用 NAT 网关转发时，再检查公网 8443 到内网 8443 的端口转发。直接绑定 EIP 与独立 NAT 网关是不同配置，不因操作系统只有私网地址就要求创建新网关。

优先核对外网防火墙是基于官方说明的排查建议，尚未确认是本次超时的实际原因。

### 用户放行后的公网复验（2026-11-15）

用户新增 TCP 8443 后，电脑经公网直接访问 HTTPS `/healthz` 已成功，返回协议 1 与 `ok=true`。使用应用的 CA 验证证书及 IP 主机名，没有 SSH 桥、CONNECT 测试代理或跳过 TLS；既有服务与端口未改。前文超时是放行前的现场记录，保留作为历史，不再列作当前阻点。Android 端直连及后续长期矩阵分别以实际定点结果为准。
