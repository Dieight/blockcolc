# 原生天空接入核对

本记录区分计算、出包和最终画面。实施与验收继续记在 [P3](../versions/3.0.0-p3.md)，不把参数对照当作完整视觉通过。

## 当前采用的计算

- 天文或本地时钟先产生原始太阳／月亮状态，再使用正式 `renderer.ts` 的每日种子选择红／粉暮光。`sky-spectacle.ts` 的暮光混色使用线性光，不能复用原始日夜色板中的 sRGB 字节插值。
- 星空、银河和极光采用 `nightSkyVisibility` 的太阳高度及月光抑制。天空与反射共用强度、方向和运动时钟；反射增益另属材质。流畅／均衡的密度为 0.65，精致为 1。空岛采用全包围夜空和对应银河朝向，海岸开启冷区极光。
- `mosaicColdDirection` 当前返回固定 `[-1,0,0]`，与随机地形种子无关。原生沿用这个输入，不另猜一个极光方向。
- 天空球的三个高度带在顶点处混合。几何只保留混合权重，颜色和天体方向更新统一参数块；不因每分钟采样重传网格。24 × 12 球面及天体平面的属性与当前 Three 版本直接对照。
- 夜空运动只累计实际星空可见的时间，云和雨继续使用各自时钟；白天的云运动不应提前推进流星周期。

## 需要保留的绘制核对

1. **材质参数上限。** 固定的 Filament 1.56.0 在增加多个独立天空参数后报 `Too many parameters`。现在将梯度、天体偏移和角色标记打入一个 mat4。后续新增字段先核对现有参数块和引擎上限，不能让声明与实际 shader 含义分离。
2. **色调映射与后处理。** Three 在直接绘制时按材质的 `toneMapped` 选择 ACES；绘入离屏目标时先保留线性颜色，启用的 `LightingPostProcessor` 在最终合成执行 ACES。太阳和月亮 Sprite 明确为 `toneMapped: false`。原生已区分这两条路径：流畅／均衡在材质内编码，精致保留线性 RGBA8、半分辨率 bloom、0.32 强度及 2 倍采样。直接路径采用 4 倍 MSAA，对应本次实际源上下文的采样数。透明、裁切、不同曝光和最终调色已做源 Web／手机的内部像素对照；天体在完整场景中的颜色、边缘采样及跨 GPU 表现仍须分别核对，不能由这些点位推定全部画面一致。
3. **月相外观。** 正式 `renderer.ts` 尝试替换 Sprite shader 的 `<color_fragment>`，但当前 Three 的 Sprite 片元程序没有这个锚点；已有 P1 审查也记录了该事实。当前原生保留实际方形 Sprite，月相已参与照明和夜空抑制；没有把“计算了照明比例”写成“月盘外观已正确渲染”。是否修正这个既有问题，应按明确的产品改动处理并增加两端对照。
4. **实际视口。** 原生相机投影使用真实宽高，旧降水／动物镜头接口却仍传固定 0.75。已改为同一实际视口，新增宽视口 Surface 回归；固定比例的实验截图不能代替普通模式短世界窗口的覆盖检查。
5. **可见范围。** 山谷／海岸前轮固定取景未见近云，仍需完整镜头、近远景及大型聚落对照。天空 owner 存在、帧已提交或 CPU 参数正确，都不是它们实际可见的证明。
   精致档接离屏后，原生夜空暗部可见色带。应先与正式 RGBA8 离屏画面对照，再决定格式／抖动等改进；不能直接更换格式并仍称源路径等价。
6. **镜头雾距。** 正式 `updateFogDistances` 在镜头变化时按实际距离重算雾距。现已拆出 `NativeFogProjection`，`project` 和天气采用共用最新镜头距离；环境采样只提供天气种类、地形范围和雾色。共享运行纹理仍为两个 RGBA32F 像素，末三个通道保存 near／far／动态开关，原五个动画通道保留。缩放不遍历材质，也不重算天文。正式函数的 1,680 份范围对照已过；实际 shader 像素及采样／缩放采用顺序另见 P3 的本轮实机证据。
7. **雷电与补光。** 固定八段的实例几何使用现行 Three 的调度、落点和衰减，不把闪白全屏当作点光。Filament 点光通过 `setIntensityCandela` 更新；1.56.0 的 Java `getIntensity` 注释写 lumen，但固定版本的[内部 getter](https://github.com/google/filament/blob/v1.56.0/filament/src/components/LightManager.h)直接返回存储的 intensity，[实现](https://github.com/google/filament/blob/v1.56.0/filament/src/components/LightManager.cpp)在 candela 路径不作转换。设备读回验证按 candela 比较；首轮误按 lumen 断言的失败保留。云的 Lambert 贡献另按 Three 当前 shader 的衰减与法线计算，并用 `getUserWorldFromWorldMatrix` 还原应用坐标，避免镜头移动改变光源与云的相对位置。参数／读回检查仍不能代替完整画面验收。

## 后处理仍需一起收口的边界

`NativeColorPipeline` 沿用半分辨率 bloom、源采样数以及 ACES／sRGB 终端。`NativeEnvironment` 现按画质选择正式后处理，`NativeWorldView.updateGenerated` 不再拒绝后处理改变；以可回退的目标事务配合外层世界采用。颜色和 bloom 参数变化复用相同存储，尺寸／格式变化先准备新目标。

原 `resize` 先释放旧目标的流程已替换，构造中途失败也会清理已创建的资源。`RenderTargetState` 的绑定／回退反例先在 JVM 验证，实际对象构建、像素和宿主证据见当前 P3 记录。`NativeMaterialUniforms` 用现有 mat4 的空闲通道携带曝光和材质颜色策略，低档不再把透明合成后的整幅画面统一做 ACES；离屏路径继续保留线性混合和统一终端处理。独立环境采样若携带另一条颜色路径会被拒绝，不能只切材质而留下旧目标。

直接路径还有雾色的准备步骤。现行 Three 0.178.0 的 [refreshFogUniforms](../../artifacts/experiments/v3.0.0/p3-native-output-20261026/three-source/WebGLMaterials.js) 通过 [getUnlitUniformColorSpace](../../artifacts/experiments/v3.0.0/p3-native-output-20261026/three-source/UniformsUtils.js) 为默认帧缓冲编码雾色，离屏则保留线性颜色。只照抄 shader 中“编码后混雾”的次序、仍传线性雾色，会产生明显色差；首次实机对照已捕捉到这个错误，原生按该准备步骤补正。源 Web 使用实际 MeshBasic shader、正式 bloom 与调色组件，不用原生算式生成期望值。lit 材质另用纯发光、零外部照明隔离评估器与 alpha 路径；它不证明不同引擎的完整 BRDF 已一致。具体配置、误差和失败记录见 [P3](../versions/3.0.0-p3.md)。水、完整天体和大场景仍需按各自视觉范围检查。

连续真实帧的回退实验另捕捉到后端 `FTexture` 的 use-after-free。核对固定版本的 [Engine::prepare](https://github.com/google/filament/blob/v1.56.0/filament/src/details/Engine.cpp#L581) 可见，每帧会提交全部材质实例，不只绘制中的通道；[MaterialInstance::commit](https://github.com/google/filament/blob/v1.56.0/filament/src/details/MaterialInstance.cpp#L171) 随后提交描述符。切回无 bloom 时，模糊通道虽然不再绘制，采样器仍须改绑到有效源纹理。Java 的纹理参数为非空，所以采用当前源纹理，不以传 null 清空。关闭则先销毁材质实例再退役目标。失败与补正验证均保留在本轮 P3 记录，不用偶然单次通过替代连续回退验收。
