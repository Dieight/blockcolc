# v2.9.0 原生迁移三项小实验

日期：2026-10-18。状态：隔离原型，未采用正式迁移方案。关联：[NATIVE-01](../versions/2.9.0-development.md)。

## 要回答什么

不是把整个 App 换语言。先分开验证世界能否交给原生渲染、耗时计算能否保持输出一致、原生界面与输入要重做多少。三个目录均不接触正式数据、签名、私有模块或正式包名。本文保留最初的桌面／编译阶段；后来用户接机授权后的结果见[OnePlus 实验](2.9.0-native-oneplus.md)，不把编译成功当作实机验证。

## 渲染：Filament 与相同输入的 WebGL

Filament 支持 Android Vulkan 与 OpenGL ES；Java API 可用 `Engine.Backend.VULKAN` 明确选择后端。[官方后端列表](https://github.com/google/filament#backends)、[Engine API](https://github.com/google/filament/blob/v1.56.0/android/filament-android/src/main/java/com/google/android/filament/Engine.java)。

先试 Maven 1.77.3，其 AAR 要求 compile SDK 37，当前 SDK 35 的实验构建被正常拒绝。为隔离实验固定到可用的 1.56.0，不跳过 AAR 校验，不升级正式工程。它的[上游工具链](https://github.com/google/filament/blob/v1.56.0/android/build.gradle)仍支持本机条件；未来正式选型需再核对新版 SDK、驱动、16KB 页和目标设备。

[渲染样机](../../spikes/native-world-render/README.md)导出生产海岛 25 栋的冻结不透明顶点。Three 和 Filament 都使用相同二进制、相机、720×960 分辨率和一个合并网格，不把批次减少混称为 Vulkan 收益。第一版导出漏了多材质地形组及实例颜色，已修正并保留两份输入。最终包含 1,333,992 个顶点，约 35.6 MiB；它只是对照流，不是最终资源格式。

WebGL 的相同流已绘制与交互通过，只有 1 次 draw call，未发现页面／GL 错误，见[报告](../../artifacts/experiments/v2.9.0/native-reference-final-2/report.json)。正式纹理、透明、水面着色、云、阴影和动物没有移植，不能说视觉等价。原生包提供两种后端和 300 帧固定旋转采样，另记录实际提交／跳过帧数；材质运行时编译独立记录，正式方案应离线编译，避免用样机编译成本推算冷启。

下一步需要同机比较 WebGL／原生 GLES／原生 Vulkan，分别记录输入校验、材质准备、缓冲上传、首个有效帧、稳态帧分布和峰值内存。Choreographer／rAF 与 CPU 提交不是 GPU 时间；GPU 用设备工具另采。失败也保留，不能默默换后端。

## 计算：同一静态表面的五组缓冲

[计算对照](../../spikes/native-world-compute/README.md)使用实际生产蓝图与布局的 1／7／25 栋格点输入，TypeScript 调用当前 `staticVoxelSurface`；Java 独立实现相同面顺序、位置、法线、UV、索引及源体素索引。三种规模输出逐字节一致。

桌面 Windows、Node 26.1.0 与 JVM 21.0.10，各预热 3 次、记录 7 次；总时间含解码、组装和传输缓冲编码，取中位数：

| 建筑／格点数 | TypeScript | Java | 输出一致 |
| --- | ---: | ---: | --- |
| 1／482 | 0.68ms | 1.14ms | 是 |
| 7／3,374 | 4.44ms | 3.91ms | 是 |
| 25／12,050 | 22.08ms | 6.60ms | 是 |

[TypeScript 原报告](../../artifacts/experiments/v2.9.0/compute-first/typescript.json)、[JVM 原报告](../../artifacts/experiments/v2.9.0/compute-first/jvm.json)。小规模没有收益，较大规模值得继续；Java 同时改变预分配与整数索引，不能归因为只换语言。它也没覆盖完整地形、玻璃邻接、资源包造型、PNG 解码、缓存读取和 GPU 上传。下一步放入独立 Android 进程，与相同 WebView 控制对照，再决定是否迁移这个内核。

## 界面：Compose 输入与布局

[原生界面样机](../../spikes/native-ui/README.md)覆盖计时／任务／设置切页、极简布局、便签中间编辑、勾选、展开、双语、主题与玻璃透明度；背景是本轮冻结图片，不是实时 Filament 场景。使用 Foundation `TextFieldState` 持有文本、选区和组合态，不做异步字符串回写。[官方文本输入说明](https://developer.android.com/develop/ui/compose/text/user-input)。

编译成功只说明接线可行。输入法、200% 字号、键盘避让、系统返回、活动恢复需要手机；冻结图的模糊不能证明跨 Surface 的实时液态玻璃成立。正式计时恢复、备份、通知、权限和全部交互都还没迁移，不按样机行数估算整个工程工期。

## 暂时的判断

优先考虑 Kotlin／Compose 负责页面及 Android 生命周期，Filament 负责世界；C++／Rust 是否值得引入由热路径实测决定，不为了换语言增加桥接和构建成本。可复用领域规则、蓝图／材质数据、场景规划和测试用例，但现有 TypeScript 与 WebGL 着色器不能直接成为原生运行代码。正式方案尚未确认。

房屋移动首先取决于布局状态、地形支撑、占用和动物导航，不取决于 Vulkan。原生渲染也不会自动解决这些约束；若把建筑作为独立可变换根节点并设计占地与落地更新，两种技术栈都能先做不重建全世界的移动。

## 证据与限制

原始输入、报告和各次构建失败保留在 `artifacts/experiments/v2.9.0/`。渲染首轮的 SDK 失败、Java 调用 Kotlin object 的初始化修复，以及 UI 首轮 Windows Gradle 变换缓存冲突和一次 PowerShell 参数解析失败均保留；未跳过校验。串行构建与正确引号后再收最终产物，不把旧失败当作通过。

初始阶段只编译独立 debug 实验包，未安装、未操作手机、未跑发布全量，也没有正式或私人测试包交付；后续设备采样和限制统一见前述 OnePlus 记录。正式画面等价性尚未完成。

最终[渲染构建](../../artifacts/experiments/v2.9.0/native-render-build-final-2.log)与[UI 构建](../../artifacts/experiments/v2.9.0/native-ui-build-final.log)均退出 0；实际 APK manifest 为两个独立包名，渲染包内 scene.bin 摘要与最终输入一致，UI 只带冻结截图、不带约 36MiB 的场景流。身份、摘要与边界见[检查结果](../../artifacts/experiments/v2.9.0/packaging-final.json)。
