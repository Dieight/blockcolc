# 像素画质：首版接入与待完成事项

日期：2026-11-24。关联：[界面审查返修](3.0.0-ui-review-v3-revisions.md)、[纸雕世界](3.0.0-paper-world.md)。

## 来由

界面审查 Demo 用 2D 像素场景代替世界。用户希望把这种画面做成世界画质选项。Demo 的观感由四部分组成：平涂色块、约 4dp 一格的大像素、按时段收窄的调色板，以及侧视构图。前三项属于画质，侧视构图属于镜头，另行讨论。

在真实渲染截图上做过模拟：带纹理的档位按 4dp 点采样后仍可辨认，但统一量化颜色时草地会变成噪点，夜景接近全黑。因此像素档以纸雕的平涂色块为底，调色板按时段分别取色，而不是对现有纹理档位做后期滤镜。

## 本 PR 已完成

- 设置“光影质量”在纸雕之后新增“像素”，附说明。偏好接受 `pixel`，未知值仍回落默认档。
- 世界准备把 `pixel` 视同 `paper`（`nativeSceneQuality`），共用纸雕静态包与缓存。纸雕与像素互切只改渲染配置，不重建世界；设置的“正在建造世界”提示按同一份场景判断就绪。
- `NativeColorPipeline` 新增渲染期开关 `pixelated()`：场景尺寸按每 4dp 一格计算（`SceneRenderSize.forPixels`，常量 `PIXEL_CELL_DP`），终端 pass 与同帧玻璃合成用最近邻采样放大，玻璃模糊仍用线性采样。诊断输出增加 `pixel`。
- `NativeWorldView.pixelated()` 在渲染线程切换，并同步栅格尺寸。新建视图时沿用当前选择。
- 云同步：纸雕和像素都只保存在设备上，上传时按“流畅”传输；回传值为“流畅”时保留本机选择，其他设备的真实改动照常采用。
- 测试：`SceneRenderSizeTest`（各密度下 4dp 一格）、`NativeQualitySelectionTest`（场景映射、云端往返、自动档不选像素）、`PreferencesControllerTest`（各档位重载）。
- `PresentationOracleTest`：网页偏好不认识纸雕和像素，预言数据把 `lightingQuality:pixel` 归回“精致”。这两档只在设备上保存，所以比对时保留原生取值，其他字段仍与网页逐项一致。

本 PR 没有改动材质文件，当前环境也没有 `matc`；未在模拟器或真机上看过画面。

## 交给维护者完成

1. **真机定格宽。** 4dp 取自 Demo。请在 OnePlus 和 Redmi 上比较 3／4／5dp 下建筑的可辨程度，以及动物、花草和施工轮廓是否保留。调整常量 `SceneRenderSize.PIXEL_CELL_DP` 即可。
2. **镜头运动时的像素爬行。** 低分辨率画面在旋转和缩放时会闪动。纸雕已经使用正交相机，可以把相机平移按场景像素取整，旋转结束后吸附到固定角度。如果仍明显，再评估拖动时临时改用较小格宽、停下后恢复。
3. **格宽一致。** 输出宽度通常不是格宽的整数倍，最近邻放大后相邻格会相差 1 个物理像素。可以把终端视口扩展到整数格，同时调整相机宽高比；改动集中在 `NativeColorPipeline` 与投影。
4. **分时调色（需要 `matc`）。** 在 `paper.mat.in` 或终端 pass 按 `nightFactor` 与天气，在白天、黄昏、夜间三组调色板之间取色：天空分段、黄昏偏暖、夜间深蓝，每组保持单一色相的明度阶梯。不要对整幅画面做统一量化。
5. **灯光与天体。** 夜间窗户和灯需要发光色；纸雕目前只有 `nightFill`。另外需要像素化的日、月和星，在天空 pass 中绘制。天空和夜空等非纸雕材质按栅格像素接收 `viewportSize`（`PacketRenderer.resize`），像素档下一个星点会放大成整格，请在夜景中核对。
6. **玻璃上的文字。** 像素档下玻璃背后是大块平涂色，请核对普通、极简、专注三处面板上文字的可读性。
7. **性能对照。** 与纸雕在同一存档、同一镜头和拖动输入下比较 PSS、旋转 CPU 和呈现间隔 P95。场景片元约为纸雕的 1/30，预期不会更慢。
8. **画面与仪器测试。** 在设置中选择像素，在普通与极简之间往返，再在纸雕与像素之间互切，确认生成代次不变、诊断中 `colorPipeline.pixel` 随之切换；截图存档。
