# 原生计时／结算规则与无位图玻璃

日期：2026-10-19。承接[原生切片](2.9.0-native-slice.md)。本轮仍在隔离包 `com.blockcolc.experiments.ui`，正式 App、备份和私有同步没有迁移。

## 本轮边界

上一轮的小状态机只证明界面、世界和保存能接起来。这轮开始迁入正式规则，重点是极简／马拉松的延后结算：先记录每轮事实，最后给普通小任务／习惯任务分配，或明确不分配。普通计时的开始／结束／逐轮汇报部分也进入命令对照，但没有在新页面上提供完整普通计时流程。

移植代码、生成脚本和实验入口在 [native-ui](../../spikes/native-ui/README.md)：

- `FocusContract`：Kotlin 的不可变事实和命令执行器，覆盖开始、自然结束、提前完成、中断、普通进度汇报，以及延后结算的显式／旧共享分配、习惯轮次和纪念建筑边界。
- `FocusSchedules`：正式结束时间、短末轮、终末休息、固定轮次与剩余时长的纯函数。不是照抄上轮样机的统一长轮规则。
- `NativeFocusFlow`：计划和领域事实作为一次事务更新。按冻结的绝对时间补齐已授权的自然轮次；手动中断／提前完成停在待确认态；等待超过所选截止时刻不补造手动轮次。中断记录不进入可分配池，重复汇报不重复消费轮次。
- `NativeFocusRepository`／`Controller`：实验文件在串行 IO 线程读取、写入和同步，保存成功后才向 Compose 发布。计划、历史、分配及汇报幂等标记在一个原子文件里，避免两个存储间的预留／提交裂缝。Activity 重建前后的控制器共用进程内队列；同一文件的读改写加锁，明确操作带版本检查，旧界面不能覆盖较新的事实。读坏文件会显示错误，不当作首次启动覆盖。此格式名为 `blockcolc-native-focus-lab`，不读写正式备份；不是多进程数据库方案。
- `NativeFlowActivity`：活动世界上的流程页面。三份合成任务、两轮／短末轮／终末休息、可选自动续轮、手动提前／中止、分配与恢复均可实际操作。短秒数是实验时间；建筑仍为冻结输入，不因这里的实验进度更新几何。

没有移植腐败修复、专注完整性／退出记录、每日／节日／生日奖励、所有时区和原生后台通知。本轮日期对照使用 UTC。普通模式 UI、用户输入、全面状态校验、正式 schema／备份转换与导入后自动授权撤销仍未完成。不能把这个投影格式当成已经兼容整个领域或正式用户数据。

## 用正式执行结果核对

`export-focus-contracts.ts` 直接运行当前 TypeScript 领域执行器和计划函数，不手写一套“期望原生通过”的答案。输出包括：

- 20 条场景、129 个命令步骤，每一步核对成功／错误码及任务、会话、进度、分配和习惯建筑事实；每一步也检查输入没有被修改，并经过 JSON 往返。
- 497 组计划推导，包括短末轮、25+2 分钟的终末休息、零休息、24 轮上限与无效设置。
- 54 组剩余／当轮时长，以及 4 组固定轮次时长，共 555 组计划／时长对照。

Oracle 记录正式源码和导出脚本的 SHA-256。Gradle 每次执行 JVM 测试前都复核，源码变动后旧 Oracle 会报错，而不是继续假绿。

第一份导出曾用两轮习惯作为小夹具，被正式执行器正确拒绝：习惯建筑目标是 10—30 轮。保留[失败日志](../../artifacts/experiments/v2.9.0/native-focus-contract-export.log)，修正为真实目标与十轮完成事实后重新生成，未放宽正式校验。[Oracle](../../artifacts/experiments/v2.9.0/native-focus-contracts-final/oracle.json)、[生成记录](../../artifacts/experiments/v2.9.0/native-focus-contract-export-retry.log)。

14 项 JVM 测试通过：上述两项矩阵测试、七项原生协调与恢复反例、原有五项样机测试。[最终构建和测试](../../artifacts/experiments/v2.9.0/native-focus-atomic-build.log)。协调层额外检查延迟取消不会留下没有计划的活跃会话、写入前后不重复计轮，以及手动等待后不追补。

## 改变玻璃的取景方式

上一轮面板逐帧 `PixelCopy` 并生成不可变副本，十余秒会分配几十 MiB。直接循环复用正在显示的位图有并发修改风险，因此本轮没有用不安全的池掩盖分配量。

新增受 App 管理的底部浮动窗口，尝试系统 `setBackgroundBlurRadius`。只模糊窗口范围，不启用整屏 blur-behind；世界仍在同一原生 Surface 里连续旋转。支持时由系统合成背景，不生成逐帧位图；不支持或运行时被系统关闭时提高底色不透明度。保留受控的 `flat`、`pixelcopy`、`system` 三种入口作对照。省电模式等限制由系统决定，实验不改变系统策略。

这不是完整液态玻璃的折射／高光移植，两条模糊内核和观感也不完全相同。新页面的两个窗口如何与正式导航、IME、无障碍及更多弹页共存，还需要继续验证，不能以这次能显示就批准全面采用。实验诊断的复制事件数组也已加上限，避免长时交互因探针自身一直增长；这项改动并不能解释或消除位图副本本身的成本。

## 手机验证

最终同一份隔离 APK 在 OnePlus PJX110／Android 16 上通过九项 Android 测试，包含原有五项，另加：

1. 自然专注／休息中重建 Activity，恢复第二轮后通过真实分配按钮分别给普通／习惯各一轮，再重建确认记录和实际时长保留。
2. 零休息＋自动续轮下手动提前结束，等待超过一轮仍停在待确认态；确认后再进入下一轮。应用内部的强制无模糊入口用于验证底色回退，没有更改手机省电／模糊策略。
3. 原子提交前注入 IO 失败，重读仍为完整旧信封；随后成功保存和坏文件拒绝均检查。
4. 两代仓库读取同一旧版本后，旧操作被拒绝；另一实例补齐两轮后，前一实例重读能看到完整新事实，重复补齐不增加版本或轮次。

[最终设备测试](../../artifacts/experiments/v2.9.0/native-focus-atomic-device-tests.log)。安装是覆盖升级隔离包，保留正式 App；没有再用会卸载实验包的 Gradle connected 工具。初次八项测试和修正前的重复对照分别保留在 [原测试](../../artifacts/experiments/v2.9.0/native-focus-port-device-tests-first.log)与[原汇总](../../artifacts/experiments/v2.9.0/native-focus-port-summary/report.json)，不与最终包混作同一组结果。后一轮审计补上了跨 Activity 的队列和版本保护，重新构建后复跑完整设备对照。

三方式预检完成，并实际审看三张手机图：OnePlus 返回系统模糊可用，模糊只覆盖底部窗口，世界没有停住。预检数据[另存](../../artifacts/experiments/v2.9.0/native-focus-port-smoke/index.json)，不和主重复对照混在一起。

### 同包重复对照

最终 18 份报告均完成，零失焦、零测量窗口复制失败。每份核对同一场景几何摘要、两轮实际时长、已结算标记和仅一份普通进度汇报。两场景各轮换三种玻璃方式，每种重复三轮；引擎和缓冲固定 GLES、720×1584，先预热三秒，再取十秒旋转窗口。下表是三轮中位数，P95 列为各轮 P95 的中位数。

| 场景／25 栋 | 面板方式 | 世界实际呈现（次/秒） | 呈现间隔 P95 | 结束后 PSS | 预热及采样内的位图副本分配 |
| --- | --- | ---: | ---: | ---: | ---: |
| 海岛 | 纯底色 | 40.8 | 41.72ms | 364.2 MiB | 0 |
| 海岛 | 20Hz 位图取景 | 42.1 | 41.72ms | 432.2 MiB | 107.1 MiB |
| 海岛 | 系统合成模糊 | 49.6 | 33.38ms | 364.4 MiB | 0 |
| 海岸 | 纯底色 | 37.7 | 41.72ms | 507.5 MiB | 0 |
| 海岸 | 20Hz 位图取景 | 40.4 | 41.72ms | 587.9 MiB | 105.8 MiB |
| 海岸 | 系统合成模糊 | 54.2 | 33.38ms | 506.8 MiB | 0 |

系统路径相对位图取景少约 68／81 MiB PSS，也确实不再产生约 106—107 MiB 的逐帧副本。副本数字是累计分配，不是同时常驻量；系统合成自身仍有成本。两种模糊的内核、强度和观感不同，不能只根据呈现次数把它称作同画质引擎提速，更不能推导整套 App 的帧率或冷启动收益。各轮开始电池温度为 30.7—33.0°C，三轮仍不足以证明长时功耗、泄漏或低端设备表现。

开始、自然交接和汇报的入队至 Compose 绘制时间包含 IO 保存及主线程投递，各组三轮中的最大值约 82—109ms；不包含真实触摸分发或硬件呈现，不能拿上一轮不含写盘的约 64ms 直接判断退步。把首次加载也计入时，各组最大值约 222—242ms，不是正式 App 冷启动。完整逐轮数据见[主索引](../../artifacts/experiments/v2.9.0/native-focus-atomic-main/index.json)与[汇总](../../artifacts/experiments/v2.9.0/native-focus-atomic-summary/report.json)。

已实际审看最终海岛／海岸的系统与位图四张完成图，及进程恢复后的汇报图：系统背景只在底部窗口模糊，窗口上方世界保持清楚；两种方式的模糊差异明显。没有把实验默认控件当成新的正式 UI，也没有验收完整液态玻璃效果。

### 进程终止恢复及包身份

另做了一组独立实验：第一轮已保存后只强停隔离包，等待九秒，再以相同实验 ID 启动。恢复后精确补齐两轮共 6 秒专注及中间 1 秒休息；再次终止和恢复，事实保持相同，没有重复计轮。这里证明的是绝对时间恢复，**不是后台服务按时持续运行或 OEM 通知已迁好**。[恢复结果](../../artifacts/experiments/v2.9.0/native-focus-atomic-recovery/result.json)及同目录前后原始数据保留。

- [Android Window 背景模糊](https://developer.android.com/reference/android/view/Window#setBackgroundBlurRadius(int))：只覆盖窗口范围，要求透明和浮动窗口。
