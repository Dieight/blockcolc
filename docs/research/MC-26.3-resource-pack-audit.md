# Minecraft Java 26.3 资源包兼容审计

更新：2026-09-24。目标是已发布的 Java 26.3（资源包格式 `97.1`）。此文区分“已走到材质/模型渲染路径”和“与 Minecraft 客户端逐像素一致”；两者不能混称。

## 输入与复现

审计使用用户本机合法持有的 26.3 客户端 JAR（SHA-1 `e877b6a07acd633fb3bb475002175cec036e7b87`）和对应服务端 DataGen `reports/blocks.json`（SHA-256 `7a0de8aaf7b04d00c40b8ffdc4cfe75184cff2e821d336a020573201867105a4`）。脚本 `tools/audit-mc263-coverage.ts` 会校验两个哈希后遍历真实方块注册表的每个状态，并调用生产用纹理、几何、实体特例与流体规划器。示例：

```text
npx vite-node --script tools/audit-mc263-coverage.ts <26.3-client.jar> <reports/blocks.json> <report.json>
```

报告只包含 ID、状态属性、路由和计数；原版 JAR、PNG、模型及 DataGen 原始文件不进入仓库或 APK。用户导入后解析出的资源只保存在本地资源包存储中，不成为应用预置资源。

## 结果

| 层级 | 已测结果 |
| --- | ---: |
| 注册表 | 1,286 种方块，35,723 个精确状态 |
| 原版资源解析 | 1,288 个 blockstate、2,883 个模型、1,300 张方块纹理；解析问题 0 |
| 图集 | 3 页、1,300 个 tile，其中 54 个动画 tile |
| 通用运行时规划 | 2,845 个纹理立方体状态、31,501 个模型几何状态 |
| 通用规划器未处理 | 1,374 个状态；以下续路由再次核算 |
| 后续路由 | 1,226 个实体/特殊渲染、34 个流体、102 个应为空的状态、12 个依赖方块实体数据的 moving_piston、0 个未分类 |

后续路由的 1,226 个状态细分为 portal 2、banner/pot/conduit 338、chest/shulker 350、skull/golem 536。计数是互斥的，真实渲染顺序与 `renderer.ts` 一致，特殊路径只有在得到实际 mesh/texture 时才算覆盖。另有 3 个 air 状态在通用规划前即有意跳过。

这张互斥表只复核通用规划器的 fallback。官方注册表另有 505 种方块、13,325 个 `waterlogged=true` 状态，属于“宿主模型之外再叠加液体”的正交效果，不能被 `unresolved: 0` 误解为先前已经画出水。独立审计将全部 13,325 个状态分 53 批送入生产水浸规划器，13,325 个生成图集水层计划、0 个程序化回退、0 个遗漏；这只证明隔离状态下的规划覆盖，真实场景中是否可见仍受宿主模型深度/透明度与邻接影响。水层保留宿主模型，按 8/9 源水高度、上下/水平邻接与导入水贴图绘制；无贴图时退回程序水材质，实例批次按 4,096 个拆分而不丢格。普通水/熔岩及水浸水层的可见动画 tile 均登记到 atlas 动画控制器。

底包、叠加包、blockstate/模型解析、atlas、染色、非立方体几何和场景采用已经接通。四个用户提供的旧版样例（Ashen 16x、Bare Bones、Plastic、Stay True）分别叠加 26.3 底包导入并在移动端 Chromium 逐一启用；六项资源包 E2E 全部通过。旧版样例本身没有声明所有 26.3 方块；叠加后缺失资源由用户持有的 26.3 底包补齐，不意味着旧版 ZIP 独立具备全量覆盖。

## 仍有明确边界

- `moving_piston` 的 12 个状态需要方块实体中的被推动状态/朝向；当前 Litematic 导入、蓝图与备份已保留受限的姿态数据，静态显示按该数据规划。没有实体数据时仍不画假立方体；活塞运动动画并未复刻。
- 告示牌前后文字、颜色与发光标记以及营火四个物品槽已能从受限方块实体数据导入、保存并静态显示。告示牌文字使用本机字体和近似牌面，营火物品只用稳定的简化标记，不能称为原版字体、物品模型或动画等价。
- banner 图案、饰纹陶罐各面的陶片、玩家自定义皮肤、箱子开合、conduit 激活与特殊动画需要 NBT、实体状态或 Minecraft 客户端渲染器。现有静态形态读取用户导入的实体纹理，但不声称动态或 NBT 完整等价。
- 流体使用静态高度、角点权重、流动斜面/UV、still/flow 贴图和动画 metadata；水浸水层靠宿主模型深度/alpha 遮挡来露出空隙，不是 Minecraft 的精确 face-occlusion shape。相邻动态状态、投影式传送门及原版特殊着色/后处理并未逐像素复刻。
- 原版含 15,140 个 tint face；14,756 个进入已映射染色路径。剩余 384 个来自七类方块，本机 26.3 `BlockColors.createDefault` 没有为它们注册颜色 provider，故按白色因子保留原贴图色；0 个因不支持 tint 而阻断渲染。当前聚落以固定气候采样，未与 Minecraft 全生物群系颜色逐一比对。
- 普通资源包导入只接收受限、安全的 PNG、模型及资源包 metadata；已增加 128/256px 混合图集预算校验、按方块位置稳定选择加权模型和真实样例包的未覆盖项清单。自定义 Java 客户端代码、shader/OptiFine 扩展（例如样例包中的 CTM、随机实体、CIT）和任意超预算高分辨率资源不在此格式范围。对无效条目做隔离并保留可解析部分。

因此“35,723 个状态均有确定处理结果”是自动化路由事实，不是所有特殊方块颜色、纹理、造型和动画均与 Minecraft 逐像素相同的承诺。测试 APK 仍需用户对实际蓝图、四包切换、设备 GPU 与耗电进行人工验收。
