# OriginOS 原子通知接入更新

2026-10-11。参考用户指定的 [folio-17](https://github.com/GYPp1us/folio-17)，核对 `codex/skill` 分支提交 `330299f789eb4b1a2b65975c718fbd03cd962749`，不是把上游样例的设备结果当成本应用验收。

## 核对的协议

- `getSceneStatus(pkg, scene, switchType)` 的第三项是能力开关：0 为原子通知，1 为助手，2 为两者；不是用户 ID。旧固件两参数查询默认原子通知。
- 普通应用可查询自己的资格，但不能自行写系统场景/包白名单。blockcolc 仅在系统授权后附加模板，其余保持普通通知；没有加入 shell、ADB 注册或 Binder 绕过。
- 模板按官方演示补 baseInfos、infos、shortInfos、capsule 与 island。CREATE/UPDATE/END 操作为 0/1/2；较新固件的 END 仍校验 scene 与 template，不能把它们省略。
- 系统可能把通知 tag 改为 `VIVO_SUPERX_TAG`。本应用同时核对业务 update key，发送 END 后取消实际身份，不误删其他通知。

这些约束已用于 `OriginOsTimerSurface` 与现有通知适配器。通知图标只将原镂空番茄钟改成阶梯像素，不改变它的外形与语义。
