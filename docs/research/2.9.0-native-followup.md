# 迁移补充实验：资产布局、实际呈现与真实调用

2026-10-19，接续[复杂场景实验](2.9.0-native-complex.md)。本轮只改隔离实验，不修改正式 App 行为，不构建或发布新的私人测试包。

## 为什么要补

上一轮的原生 CPU 提交较快，但主动跳过了不少回调；那个数字不能代表屏幕实际更新次数。表面计算虽然使用真实蓝图，正式渲染目前主要在海岸珊瑚使用这条内核，不能把内核倍数直接当作建房或启动倍数。冻结 glTF 又展开了实例，资产体积和生产批次不同。因此分别检查呈现、资产复用，以及实际世界里的内核占比。

## 同一快照的三种资产

从生产场景冻结一次对象树，再分别导出；每个场景的三种布局保持三角形总数和包围盒不变。

覆盖复核：准备阶段两种场景的动物诊断均为 0／未就绪；本轮展开 GLB 也均没有 `animal-cuboids` 节点，因此不计动物负载。旧复杂实验只有海岛 GLB 带该节点，海岸没有。导出结束后的诊断已变成就绪，不能倒推导出前的几何库存。后续完整动态实验要在冻结前明确等待就绪，并同时核对实体数量和实际批次；不能再只等固定的 2.5 秒。

| 场景 | 展开几何 | 共享几何的普通节点 | 32 格分片合并不透明面 |
| --- | ---: | ---: | ---: |
| 海岛 25 栋 | 189.72 MB | 33.89 MB | 182.03 MB |
| 海岸 25 栋 | 270.57 MB | 88.26 MB | 261.41 MB |

这里 MB 为十进制。共享布局分别只有 659／692 份不同几何，但产生了约 10.1 万／12.2 万节点。它复用顶点缓冲，不代表已经实现 GPU 实例化。合批保持透明对象的原排序单元与投影标记，不合并材质或阴影状态不同的面。

[固定输入](../../artifacts/experiments/v2.9.0/complex-layout-inputs/manifest.json)、[源代码](../../spikes/native-world-complex/shared-scene.ts)、[合批](../../spikes/native-world-complex/merge-scene.ts)。共享 Web 场景已显示，但最初的固定 300 回调采样超过三分钟，没有完成报告；[失败记录](../../artifacts/experiments/v2.9.0/layout-device-variants-first/index.json)保留，不计为通过或给它填写完整帧率。后续改成同速、固定时长的旋转，避免慢路线还没预热完就耗尽采样期限。

离线审计还发现可复用的静态资源：海岸 1,345 个 glTF 材质定义中有 150 种去掉标签后、贴图字节和采样状态完全相同的定义；361 个纹理定义对应 49 种等价状态、48 份不同编码图片。海岛为 755→128 种材质。见[只读资产审计](../../artifacts/experiments/v2.9.0/layout-asset-audit/report.json)。这只证明冻结副本有重复；正式材质带有天气、腐败、发光等可变状态，不能据此把所有克隆强行共用。

固定十秒补测中，共享普通节点的 Web 与 GLES 分别完成 16／34 次提交，目标 Surface 为 1.6／3.4 次更新每秒，均不适合作为优化。Vulkan 未完成报告：实验进程先出现 `pthread_create (4112KB stack) failed`，调用栈在 OEM Choreographer／ScrollOptimizer，随后 ART GC 线程中止。见[未完整的一轮](../../artifacts/experiments/v2.9.0/layout-timed-matrix-first/index.json)及[限定该进程的日志](../../artifacts/experiments/v2.9.0/layout-timed-matrix-first/shared-vulkan-process.log)。这不是正常通过，也不足以单次归因为 Vulkan 驱动；未更改系统策略或扩大 Java 堆。此路线不再重复压力测试，后续完整对照采用展开几何与分片合批。

## 实际呈现的测法

设备的 FrameTimeline 里，当前原生 SurfaceView 主要出现窗口事务，而不是完整世界缓冲。Web 控制的覆盖也不足，不能用这些轨迹宣称无卡顿或 60 FPS。原始轨迹保留。

本机 `SurfaceFlinger --latency` 仍提供目标 Surface 的 desired／actual／ready 三列时间。脚本只读当前实验 Surface，约每秒收集、去重，过滤无效 fence 与预热／排空区间；不清系统统计，不改全局刷新率。CLOCK_MONOTONIC 与 Perfetto BOOTTIME 分开记录和筛选。预检中确实读到显示更新时间，而不是回调计数。

最终采用显示首帧之后至少三秒预热、十秒一整圈的同速旋转，再另列三十次同步排空。CPU 提交只统计引擎真正接受的帧；显示列来自同一 Surface 的呈现时间。低帧率路线的样本数和区间单列，不能因为只有少数帧，就给 P95 赋予稳定统计意义。周期性读取也有测量开销，各路线保持一致；不将这些数字当作无探针正式包或整套 App 的帧率。

## 真实表面计算

`profile-plugin.ts` 只在隔离 Vite 构筑中包裹正式 `staticVoxelSurface`，并允许 typed index。当前算法与两遍 typed-buffer 原型共用正式的邻居遮挡字段，包含其他材质邻居；不拿独立基准中的局部占用表替代它。五个输出缓冲有反例检查，桌面四张真实场景已审看。

25 栋海岛没有进入此函数；海岸调用六次，共 140,806 个珊瑚／海床体素。桌面检查的图形库存一致，时间不作为手机收益。手机实验重新创建生产 renderer，不接正式数据库，也不提供持久化缓存端口，分别记录初始化、两帧让出后、GPU 排空和该函数的累计时间。这不是正式 App 冷启动测量。

## 固定时长对照结果

展开／分片合批、两种场景、三个后端各三轮，共 36 份完成报告；轮换布局与后端顺序。下表取三轮实际 Surface 更新频率的中位数，不是回调频率。阴影与透明材质均启用；原生明确关闭 FXAA／时间抖动，缓冲 720×960。与上一轮一样，仍是冻结的 PBR 子集，光照、透明／水面和正式着色器不等价，不能据此判定整个引擎或 App 的性能排名。

| 场景 | 后端 | 展开几何（次/秒） | 分片合批（次/秒） |
| --- | --- | ---: | ---: |
| 海岛 25 栋 | WebView WebGL | 57.3 | 45.6 |
| 海岛 25 栋 | Filament GLES | 37.3 | 40.0 |
| 海岛 25 栋 | Filament Vulkan | 31.1 | 37.2 |
| 海岸 25 栋 | WebView WebGL | 48.2 | 50.5 |
| 海岸 25 栋 | Filament GLES | 36.4 | 37.2 |
| 海岸 25 栋 | Filament Vulkan | 27.7 | 32.1 |

合批使最终同角度的 Web 绘制调用从海岛 1,720→1,252、海岸 1,924→1,450，CPU 也较低，但不是稳定的显示收益。海岛 Web 三轮都变慢；其呈现间隔最大约 50ms、测量区间两端有样本，没有秒级采集空洞，不能把降速解释为漏收了一大段时间。分组、剔除与绘制顺序改变了，本轮未用 GPU 捕获进一步定位具体原因。

主对照的起始电池温度约 33.2—36.5°C，设备在充电。已保留逐轮温度和顺序，不能把不同阶段的温度变化当作后端收益，也没有据此计算耗电。原生较快的 CPU 提交和较小的加载准备时间仍成立，但本轮没有拿到整套迁移会更流畅的证据。

[主对照](../../artifacts/experiments/v2.9.0/layout-timed-main/index.json)、[汇总与完整数组](../../artifacts/experiments/v2.9.0/native-followup-summary/report.json)。已审看两种场景的展开／合批 Web 以及合批 GLES／Vulkan，共八张完成截图；另看共享路线两张完成图及失败图。未把原生的亮度、阴影和透明差异视为视觉通过。

## 真实加载中的计算收益

手机每种场景、每种算法各三轮，合计 12 份完整生产 renderer 报告。这组实际缓冲为 1440×1920、cinematic，保留正式 renderer 的画面流程；与 720×960 的冻结 glTF 控制是两个实验族，不能横向作 App 启动比较。海岸六次调用、140,806 个体素在每轮都一致。当前函数累计中位数 393.6→255.6ms，下降约 35%；但初始化中位数只有 10,873.2→10,782.2ms，约 0.8%，且原算法三轮范围 10,140.4—11,329.6ms，区间重叠，不能认定整体稳定提速。GPU 排空后的时刻也约 10.94→10.85s，没有改变判断。

海岛是负控制：两种算法都零调用，初始化仍在约 6—7s 变化。这里显式没有持久缓存端口、使用 25 栋复杂补充建筑；这些秒数不代表用户当前 App 冷启动，也不能与已有缓存的正式 App 直接比较。

阶段记录显示，海岸当前自然装饰阶段约 5.6—6.0s、建筑约 1.7—1.9s；该表面函数只是其中一部分。阶段是墙钟，包含分帧等待，不等于纯 CPU 热点采样。后续应先继续拆自然装饰、AO／造型与对象创建，再选择适合搬到 worker／原生计算的部分，不能只将独立表面基准的倍数外推。[生产 renderer 设备报告](../../artifacts/experiments/v2.9.0/production-surface-device/index.json)。本轮没有将 typed 原型接进正式 App。

## 帧调度补充

先做关闭该 frame-pacing 配置入口的 12 份控制，未见明显改善，但它排在较后、温度不同，因此不单独用来解释跳帧原因。[原控制](../../artifacts/experiments/v2.9.0/layout-pacing-off/index.json)。随后补了紧邻、顺序交替的海岸 A/B，共 12 份；每对电池温度相差不超过 0.1°C，整体 35.0—35.4°C。两组分开汇总，没有强拼为同温度样本。

| 后端 | 默认三轮（次/秒） | refreshRate=0 三轮（次/秒） |
| --- | --- | --- |
| GLES | 34.5 / 35.2 / 31.0 | 36.4 / 33.0 / 35.3 |
| Vulkan | 27.6 / 28.9 / 27.3 | 27.6 / 27.2 / 27.7 |

GLES 有涨有跌，Vulkan 中位数不变，呈现间隔 P95 都约 50ms，`beginFrame` 仍有跳过。该入口设置不足以解决现象；不能据此认为所有帧调度都被关闭，或已查明全部 GPU／驱动原因。后续还需要真正的 GPU 队列和提交取证。[配对数据](../../artifacts/experiments/v2.9.0/pacing-paired-summary/report.json)。

## 验证与产物

- 导出／布局／真实遮挡字段共 7 项纯测试、呈现统计 2 项测试及实验类型检查通过；独立 Web／Android 构筑通过。四张桌面生产原型实景已审看，原／typed 三角形库存一致。
- 60 份主渲染、顺序调度及真实 renderer 报告，加 12 份相邻调度 A/B 完成；汇总器校验零失焦、输入摘要、实际提交计数、尺寸、时钟和呈现窗口。失败轮次保留在独立列表，不计入完整组中位数。已补看手机生产 renderer 的原／typed 两张海岸完成图；这不是 App 布局验收。
- 最终[独立实验 APK](../../artifacts/experiments/v2.9.0/layout-package-timed/blockcolc-layout-debug.apk)摘要 `e00b75abbf170d048351cc9ca19ff42385c6d57ccf9a613a551c3026432c9d90`，与完成索引和[手机已安装包](../../artifacts/experiments/v2.9.0/layout-package-timed/device-package-verified.txt)一致。实验包已停止、手机回到桌面。正式 App、用户数据库和系统电池／刷新／锁屏设置均未修改。无发布全量、正式测试包或上传。
- 原始失败还包括导出时 Vite 新依赖预构建导致页面重载、Perfetto 配置目录权限、ADB 空参数导致错误 URL。分别保留失败目录和日志；修正后重新采集，没有将缺报告或错误页计为通过。

## 之后最值得做的实验

后续已先接通原生界面、活动世界、取景玻璃和合成计时流程，见[纵向切片](2.9.0-native-slice.md)。以下保留本轮结束时的优先项；不把后续组合测试当作动态天气／动物和正式业务已迁完。

1. 真正的实例绘制与静态材质池。先解决大批相同方块的提交，不把十万普通节点当优化；比较当前 Java 入口、自定义实例材质或薄 C++ 绑定的工作量，并补不同固定 Filament 版本的对照。本轮只代表 1.56.0 配置，不替其他版本下结论。
2. 实时世界与原生界面的组合：原创／外部材质、水／玻璃、天气、确实已就绪的动物，以及液态玻璃是否能持续取到世界背景。静止图片上的 Compose 面板不能覆盖这项风险。
3. 局部更新：单栋推进、移位及道路／地基／动物障碍同步，比较需要更新的范围与操作到有效帧的延迟。
4. 持续运行后的帧时间、温度和功耗；再补后台计时、通知、进程重建及数据迁移。前者决定长期体验，后者决定能否可靠替换现有 App。

## 方法参考

- [Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline)：区分 app／SurfaceFlinger 与层的覆盖，不拿窗口事务替代 SurfaceView 渲染。
- [AOSP FrameTracker](https://android.googlesource.com/platform/frameworks/native/+/refs/heads/main/services/surfaceflinger/FrameTracker.cpp)：呈现 fence、三列顺序及无效值。
- [Filament 1.56 Renderer](https://raw.githubusercontent.com/google/filament/v1.56.0/android/filament-android/src/main/java/com/google/android/filament/Renderer.java)：beginFrame 的跳过策略和 frame-pacing 设置。
- [Filament 1.56 C++ Engine](https://raw.githubusercontent.com/google/filament/v1.56.0/filament/include/filament/Engine.h)、[Java Engine](https://raw.githubusercontent.com/google/filament/v1.56.0/android/filament-android/src/main/java/com/google/android/filament/Engine.java)：API 层的差别；不假定复用一个 glTF mesh 就会自动合成一次 GPU 实例绘制。
