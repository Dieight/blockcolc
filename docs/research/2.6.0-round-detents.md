# 整轮次选时的停顿

2026-10-07。用户希望连续滑动经过完整轮次时能明显停住 0.5–1 秒，而不是只多拖一点距离。

Android 为离散滑杆提供 `SEGMENT_TICK`、`SEGMENT_FREQUENT_TICK` 等触觉类型；Apple 也建议刻度、选择变化使用合适的选择反馈。两者均未规定「完整轮次必须停顿多少毫秒」。因此采用 650ms 是本项目的交互选择，不冒充平台标准。

- [Android HapticFeedbackConstants](https://developer.android.com/reference/android/view/HapticFeedbackConstants.html)
- [Apple Playing haptics](https://developer.apple.com/design/human-interface-guidelines/playing-haptics)

实现共用现有选时组件，不另建时间控件。快拖跨过多个轮次也先停在第一个边界；第一轮只算专注，之后包含休息。650ms 内继续前拖不积攒位移，反拖立即释放，轻触觉只是补充。计时器、背景渲染和其他按钮照常运行，不用阻塞等待制造卡顿。键盘五分钟步进不加停顿，取消和后台均清理等待。

原先按阈值增加拖动距离的抵抗逻辑已撤下。验证同时覆盖极简时钟与调整页的实际 Pointer 操作，分别检查 649ms、650ms、第二轮的休息时长和反拖；结果放在本版开发记录。
