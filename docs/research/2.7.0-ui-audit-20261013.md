# v2.7.0 Web / APP UI 审计与 Demo

日期：2026-10-13。状态：审计完成；新布局为待体验提案。关联：[项目审计](2.7.0-project-audit-20261013.md)、[本轮实施记录](../versions/2.7.0-audit-followup-20261013.md)。

## 范围和证据

审查四个主页面、组件样式归属、字体、主题、玻璃、导航／转场及安全区实现。Web 和 Android 共享 React 页面，因此共享层的问题同时影响两端；本轮没有构建 APK 或做 Android 原生截图，不能据此确认 OEM 字号、系统栏、中文键盘、触觉和设备帧率。

现状使用独立 Chromium 上下文和合成项目，拍摄手机计时／任务／统计／设置、深色设置、桌面计时／设置以及 360px + 根字号 200% 设置，共 8 个状态，无页面异常。原始截图、计算字号和命中区测量在 `C:\Codex\artifacts\blockcolc-fixes-ui-20261013\`，脚本为 `capture-current-ui.ts`，数据为 `ui-measurements.json`。设置长页截图反映完整内容，深色和桌面截图保留当时滚动位置。

判断依据是当前 [DESIGN](../../DESIGN.md) 及真实计算样式；没有把早期圆角 CSS、视觉偏好或原生未测项目当成已经复现的产品故障。

## 发现与方案

| ID / 优先级 | 当前证据 | 改善方向与 Demo |
| --- | --- | --- |
| UI01 / P2 | 手机与桌面的重置地图、重置视角实际为 40×40；手机“调整本次计划”高 40；统计前三个档位按钮约 42.9×44。与现有 44px 规则不一致 | 保留图标视觉大小，扩大真实命中区；Demo 独立操作均不小于 44×44，密集日历单独验证连续选择与键盘路径 |
| UI02 / P2 | 页面标题任务 22px、统计／设置 24px；设置分区 18px，任务分区 17px；200% 根字号下设置分区变 36px，但页面标题仍 24px，材质／备份标题仍 18px | 采用共同的可缩放字号角色；修正固定容器，长名称允许换行。Demo 使用 rem，并检查全部四页 200% 文本 |
| UI03 / P2 | `followup.css` 的蓝图元数据与声音说明、`tasks-stats.css` 的日历标签等有 11px 声明；具体覆盖与可见状态需随正式迁移核对 | 元数据统一不低于现有规则 12px，字号不能作为高密度页面的挤压手段 |
| UI04 / 体验 | 任务页“我的任务”选择器和下一张卡片再次出现项目标题；今日目标与项目卡占据前段，施工清单位置偏后 | 当前项目摘要只保留一份；清单成为主操作区；今日目标收为次级摘要。桌面采用项目／清单两列，手机顺序展开 |
| UI05 / 体验 | 设置有 12 个可见一级分区，桌面沿用窄单列，查找需要较长滚动 | 提案按专注节奏、世界与外观、数据与设备三组归类，桌面提供索引，手机提供分组锚点；常用项可见，进阶项折叠 |
| UI06 / 体验 | 世界、项目标题、小任务、计划、时钟各自有层级，但页面之间间距与桌面留白分配不一致 | 桌面给世界和工作台稳定比例；手机压缩重复装饰，世界、任务、时钟和开始按钮连贯排列。360×800 和 412×915 默认字号均保持开始按钮完整位于导航上方 |
| UI07 / 维护 | `index.css` 导入多份历史样式；基础／设置样式中的圆角和颜色被 `pixel-trial.css` 等后续选择器覆盖。当前直角表现正确，但定义归属难以追踪 | 在 DESIGN 明确 token、组件、主题和动效的维护入口；新增修改回到原规则，不再在末尾叠同职责覆盖。生产 CSS 的全面合并属于后续采用方案时的迁移 |
| UI08 / 动效 | 900ms 导航、1000ms 门框 / 500ms 揭幕、物理滑杆和 2 秒汇报反馈已有产品语义，不应为了统一速度而全盘替换 | 保留这些表达；提案新增控件按压 120ms、底片 180ms、弹页 280ms，数字和主要操作位置稳定。减少动态直接显示终态，减少透明度独立控制 |

测量中世界色彩滑杆的原生输入宽 1px 是实现代理，实际手势由 `PhysicalSlider` 宿主承担，未将其误报成 1px 触控缺陷。日历为高密度连续选区，也未用普通独立按钮的抽样规则代替完整手势审查。

## 已经值得保留的部分

- 方块世界、品牌番茄、统一像素图标和直角轮廓具有一致身份；字体具备离线许可和系统字体回退。
- 固定功能玻璃与用户可调计时玻璃分工明确，深浅主题和减少透明度已有独立语义。
- 物理滑杆、设置数值列、平移选中底片、方块进度、细分隔档案有可复用的组件形态。
- 统计的固定 26 周、四档真实时长、团簇上下标签，以及导航图标自身动效已有清晰批准依据。
- 单个主要操作、保存失败保留草稿、真实提交后再反馈、按需渲染与后台暂停等规则应继续保留。

这些共同原则已整理进 [DESIGN 的组件与样式维护](../../DESIGN.md#组件与样式维护)，验证入口补入 [TESTING](../TESTING.md)。新色板、设置重组、额外文案与布局仍以本 Demo 供用户审看，没有改成生产默认。

## Demo：林间工坊

[打开本地 HTML](ui-demo-20261013/index.html) · [运行与素材说明](ui-demo-20261013/README.md)。纯 HTML / CSS / JavaScript，无新增应用依赖，独立于 Web 构建入口与 APK。

包含四页导航、计划轮次调整、真实按墙钟计算的示例倒计时、汇报成功反馈、任务选择、新建示例任务、日期点按／拖选／键盘选区、四档高亮、浅深主题、像素／系统字体、减少动态／透明度、设置展开及示例偏好下载。全部状态只在当前页面内，刷新后重置。设置中的普通任务 25 分钟是示例数据，不是将产品默认 45 分钟改为 25。

体素背景来自当前真实渲染器中合成的 75% 项目，固定为 2026-10-13 中午拍摄；它是静帧，不声称演示了新 3D 相机或天气。建筑记忆浮层只展示信息排版，正式产品仍遵守原工作台内阅读表面的规则。完整资源库、按结束时间选时、沉浸门户、原生通知及实际持久化未在此原型重新实现。

### 验证结果

`check-demo.mjs` 完成 27 个状态截图：四页 × 五档视口，加手机计划面板、深色统计／设置及四页 200% 文字。最终检查无页面异常、无横向溢出、无独立控件小于 44px；连续日历细格单独保留键盘和拖选交互，不包含在普通命中区抽样内。另验证弹页 Escape 与焦点返回、下载、输入、任务切换及本地 `file://` 直接打开。最终记录为 `demo-check3.log` 与 `demo-measurements.json`。

实际审看截图后修正两类问题：手机开始按钮初版低于首屏；200% 文字初版固定页眉高度与选项宽度导致拥挤。最终开始按钮在手机两档均完整处于导航上方，大字页眉和选项通过换行获得空间。全页截图中的底栏出现在第一视口底部属于固定导航截图方式，另需以视口和滚动可达性判断，不把长截图中部的底栏当成重复导航。

收尾又用 `check-demo-final.mjs` 从文件协议打开最终文件，验证真实鼠标拖选、键盘日期选择、200% 页眉无重叠，以及滚动后的底部导出操作不被导航遮盖；日历采用具名按钮组和按下状态表达选区。`demo-final-check.json` 保存结果，`demo-preview-desktop.png`、`demo-preview-360.png`、`demo-preview-412.png` 是最终视口截图。

尚待体验决定：三组设置是否符合使用习惯；任务页的信息密度是否舒服；新色板与留白是否采用。完整 Android 系统栏、字体放大、软键盘、触摸与性能验证应在方案采用并落入真实组件后进行。
