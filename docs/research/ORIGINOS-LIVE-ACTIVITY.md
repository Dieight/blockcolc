# iQOO / OriginOS 原子岛接入边界

> 2026-09-05；V27 ORIGINOS-27-01。状态：可行性与前置条件研究，不是已经适配。

## 已确认的公开资料

[阿里云官方 vivo 原子岛接入指南](https://help.aliyun.com/zh/document_detail/3030718.html)提供客户端本地 Android 通知示例，并说明先申请厂商场景接入权限。当地进程活跃时，可使用原生通知 API 创建/更新/结束；远程推送是另一路径，不是方块钟本地功能的必选依赖。指南还列出单活动刷新频率、无更新清理和最长展示时限，不能用逐秒重发当倒计时。

指南指向 vivo 官方的[接入指导](https://dev.vivo.com.cn/documentCenter/doc/894)与[核心参数/Demo](https://dev.vivo.com.cn/documentCenter/doc/896)。文本抓取未展开正文，随后浏览器已读取 896 技术规范（页面更新 2025-09-03）：本地创建/更新/结束使用 notification.superx.operation 的 0/1/2；scene 为必填，包名或场景未准入会被拒绝。不能把挂号示例当成本产品获准的专注场景。

[vivo 官方原子岛简介](https://www.vivo.com.cn/service/questions/all?categoryId=170&questionId=1751)说明该功能始于 OriginOS 5。用户确认没有真机，兼容目标先取这个最低系统族，不要求 Android 16；系统版本不代表所有机型或场景可用。

896 提供按包名/场景调用 getSceneStatus、isSupportCustomFun 的能力查询与 OS5 左右模板。左侧内容支持计时器文本，但 Demo 的具体编码尚未核验，不据此推断息屏会自动读取标准 chronometer。结束活动需要处理厂商通知 tag；这些是后续插件边界，不是已经实现的能力。

## 方块钟的实现决定与待办

1. 继续保留 NotificationPort → Capacitor → 本地原生插件的结构，业务时间使用既有 endsAt。不引入账号、云推送 SDK、后台轮询或新增领域状态。
2. 按 OriginOS 5 起的能力检测处理兼容；用户暂无真机，机型矩阵待验。仍需确认 vivo 是否批准包名 com.blockcolc.app 的计时/专注场景。准入申请、提交签名/资料或联系厂商需要用户另行授权；本轮没有执行。
3. 获得完整官方计时契约后，在原生适配层隔离场景能力探测与参数构造。没有证据不写猜测字段、不伪装挂号/外卖，也不把 Build 品牌判断当成支持检测。
4. 一个活动复用同一通知身份；重返前台不取消重发。若厂商增强不可用，继续普通持续倒计时，Android 16 标准 promoted ongoing 由系统实际权限决定。不重复发布第二条相同内容通知。
5. 折叠态只保留状态和系统支持的剩余时间；展开态区分专注/休息、任务/轮次及返回/跳过休息。系统没有自绘倒计时时不以伪实时文字替代，不承诺分钟/秒固定分居摄像头两侧。
