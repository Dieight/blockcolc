# blockcolc 验证与交付

先运行覆盖受影响行为的现有验证，再按风险扩大范围。现有覆盖无法发现具体回归时补充相应测试；交回时说明未验证或未覆盖的部分。命令以 `package.json` 和现有工具为准。

## 选择验证范围

| 改动 | 入口 |
| --- | --- |
| 文档、模板 | 引用、格式、内容归属；涉及工具读取时检查工具兼容 |
| 单一业务、交互或渲染行为 | 相关纯测试、原生测试或浏览器 spec，必要的类型检查 |
| 多模块集成 | `npm run test:fast`；主要用户路径变化时补 `npm run test:web:smoke` |
| 共享计时、恢复、存储或渲染逻辑 | 相关稳定回归：`npm run test:e2e -w @blockcolc/web`，按影响扩大 |
| 用户明确要求全量检查（如全量测试包） | 完整门禁；常规工具入口 `tools/Prepare-Release.ps1` |
| 测试 runner、fixture、构建或发布工具 | 工具测试和受影响的上层验证 |

定点示例：`npm run test:e2e -w @blockcolc/web -- tests/resource-pack.spec.ts --project=mobile-chromium --workers=1`。

扩展检查按需使用 `npm run test:extended`、`npm run test:web:diagnostics`、`npm run test:diagnostics -w @blockcolc/voxel`。`npm run test:web:release` 使用优化的 test-mode 构建，先跑计时、恢复、输入及手势，再跑缓存、动物、阴影和相机等渲染约定，之后执行其余业务、布局、地形、天气和世界交互。当前本机软件 WebGL 下各批单 worker，避免页面争抢渲染资源；渲染按职责拆批，避免一大批尚未跑完就触及总期限。顺序、归属和并发由 manifest 持有，工具核对每份 spec 只归属一次及完整用例总数，正式 APK 不含测试探针。

## 回归和实际操作

从用户遇到的操作建立反例，保留必要的模式、数据和环境条件。检查失败后还能否恢复。产品决定变化时再改旧预期；改过的断言要重新执行，不放宽断言或阈值换通过。

- UI：走入口、操作、退出和返回。手势测正反方向、轻微斜向、越界和取消，检查与滚动、双击、纵向选时的竞争。
- 输入与布局：检查受影响的长中英文、IME 组合、中间编辑、焦点、键盘、安全区、大字号和窄屏。主题或玻璃变化补浅深主题、滑杆端点、减少透明度，以及明亮和夜间背景。
- 世界：固定必要的时间和随机条件，等当前场景有效帧后检查主体、遮挡、阴影、材质和构图，再实际拖动、缩放。比较阴影等图像时，另确认异步装饰已就绪、比较期间姿态不变，不能只等首帧。主世界和小预览分别检查。动画退出后仍能操作，提示次数和业务事件一致。
- 导入：检查文件、解析、校验、保存、恢复及实际渲染。兼容测试使用确切的上游版本，分别说明正常处理、回退和外观对应。
- 计时与存储：检查模式归属、时长和轮次、跨日、中断、旧数据、重复恢复及保存失败。
- 服务与原生：检查请求、响应、解码、桥接、显示和回退。控制台成功不能代替应用结果；浏览器结果不代表 OEM 表现。设备场景见 `docs/ANDROID-RECOVERY-MATRIX.md`。
- 性能：同机同数据比较操作到反馈，测出保存、重建和绘帧成本。拆文件或减少代码本身不算提速证据。

截图要实际审看，并结合交互结果说明未检查的状态。临时诊断与正式回归分开，仍有效的旧测试继续保留。

浏览器里不足一秒的功能状态，在真实页面就绪后暂停测试时钟、分段推进并断言；性能测量仍使用真实时钟。

场景准备和待测操作分别限时，失败报告标明卡在哪一步。独立行为尽量拆成独立用例，避免一个旧入口挡住后面的无关检查。偶发失败先留原 trace、判断是产品竞态、测试时序还是环境争用，再检查同类用例；不靠增加重试次数隐藏问题。前置高风险检查只缩短返修反馈时间，不能代替完整覆盖。

原生世界交互可用 `apps/native-android/tools/Test-P3CoreDevice.ps1 -SkipCore -Pages -PageCase world-interaction` 单独验收，另传设备序列号和新的证据目录。检查真实触点、单指／双指、选择轴与两种复位、记忆关闭／继续、奖励及习惯档案；结束后由工具恢复原预览环境。建筑底部的投影点可能被前方建筑挡住，不把它当作指定建筑必然命中的坐标。CPU 命中规则另对照现行 Three.js，单次耗时不算整机性能提升。

静态方块实体用同一工具的 `-SkipCore -GeneratedWorld -GeneratedWorldCase entities` 单独验收。参考从现行 TS／Three.js 导出几何、朝向、材质和全局预算，字体栅格化另在 Android 实测；参考中的 Canvas 替身不能证明真实字形正确。手机检查四种告示牌、正反面与染色发光文字、营火状态和物品标记，修改文字时核对地形及另一建筑未替换。这项验收不等于外部资源包、完整物品模型或动态火焰通过。

动物使用 `-SkipCore -GeneratedWorld -GeneratedWorldCase animals`，共两项：四聚落实际绘制、移动／点击／暂停和施工局部更新；真实驱动上的 GPU 暂存失败与碰撞原子采用。CPU 参考另核对实际出生、形状碰撞、模型几何、像素和逐帧行为。连续切换聚落需保持原有堆限制，记录内存，不能通过扩大堆或分开启动掩盖峰值。`GeneratedWorldCase all` 共 20 项，包含静态实体、动物、图集 GPU、外部模型和地形；保留截图、确切两包摘要及恢复结果。

资源读取使用同一工具的 `-SkipCore -ResourceAssets`，共两项，验证 Android 上的归档、PNG 像素和动画元数据。参考由当前正式解析器导出，仅进入测试包；真实大文件的 JVM 对照另用 `:world-core:archiveIntegrationTest` 和 `:world-core:textureIntegrationTest`，分别显式传入本地 oracle 及结果路径。原始材质包和客户端 JAR 不进入主包，也不因测试缺失而自动下载。CPU 结果不能代替模型路由、GPU 画面或导入 UI 验收。

模型解析用 `-SkipCore -ResourceModels` 单独检查，包含合成归档、位置随机、multipart 及 UV 旋转。`:world-core:blockIntegrationTest` 另对照真实归档的全部规范化模型／状态，以及每个方块首、中、末变体或一组 multipart 状态；传入 `resourceBlockFilesOracle`／`resourceBlockResults`。报告写清抽样范围，不能称为遍历全部状态，也不把与源实现一致的回退称为成功绘制。

底包叠加、特殊贴图和色图用 `-SkipCore -ResourceStack`，检查确切原件归属、像素及聚合预算；真实包另用 `:world-core:stackIntegrationTest`，传入 `resourceStackFilesOracle`／`resourceStackResults`。目录与摘要、像素、模型解析和最终绘制分别验，不能仅凭条目数量增加认定材质已生效。

图集用 `-SkipCore -ResourceAtlas`，核对页面像素摘要、原分辨率排布、动画帧和 UV／透明映射，以及分配前预算；可与前三个资源开关组合为五项 CPU 资源回归。真实整包另用 `:world-core:atlasIntegrationTest`，传入 `resourceAtlasFilesOracle`／`resourceAtlasResults`。图集准备不证明 GPU 已使用这些像素，实际呈现仍需单独检查。

图集 GPU 用 `-SkipCore -GeneratedWorld -GeneratedWorldCase atlas`，共三项：Android 非预乘 RGBA 和安全 mip 逐字节往返、实际画面动画及暂停／恢复、真实驱动上的 owner 替换／失败回退。保留连续截图、纹理／几何创建计数及各 owner 时间线摘要。此夹具不代替完整模型、实际世界或大包性能验收；原始材质包、MC JAR 和参考导出器不得进入主 APK。

外部模型采用用 `-SkipCore -GeneratedWorld -GeneratedWorldCase models`，共两项：Android 全部合成模型／染色／回退对照，以及正常世界编译器上的模型采用与移除恢复。源参考逐顶点核对，声明浮点容差；实际绘制另留原创、采用后、移除后三张画面并审看。合成模型画廊不代替整个客户端和用户包的覆盖或视觉验收。

真实整包模型另用 `:world-core:geometryIntegrationTest`，传入 `resourceGeometryFilesOracle`／`resourceGeometryResults`；参考由 `export-native-resource-geometry-files.mjs` 从本机客户端及四种叠加包生成，留在实验目录。核对选定状态的全部顶点、索引、群系色板及回退原因，并列明状态抽样范围。原件不进入应用，宿主 JVM 的大参考文件堆限不当作手机内存策略。

地形贴图使用 `-SkipCore -GeneratedWorld -GeneratedWorldCase terrain-materials`，共两项：Android 裁切像素／采样对照，以及四聚落的原创、外部贴图、恢复原创连续绘制。只返验后者可用 `terrain-materials-visible`。比较只保留键与回执，不能让夹具同时持有全部历史场景；回调结束及时解除引用，仍保留正常 GPU 事务替换，不强制 GC 或扩大堆。合成色条用于识别路由，不代表真实大包外观。

原件库及 Android 索引用 `-SkipCore -ResourceLibrary`，共三项，使用独立临时目录。检查实际 AtomicFile 的中文名／引号、重开、底包叠加、去重与选择清除，真实提交后抛错时的原件保留／重试、坏索引不覆盖，以及缺失原件的重新导入和失败状态保留。流式限额、中断、取消、变化内容和索引失败另由 JVM 检查；这组不代替系统文件选择器、世界采用或完整导入 UI。

资源包实际导入用 `-SkipCore -Pages -PageCase resource-picker-import`，通过系统 OpenDocument 取消及导入自有 ZIP，设置中启用、返回世界采用，再从设置删除并恢复原创。检查隐藏世界未改、真实 GPU 采用和新可见帧，截图另等加载遮罩退出；材质按实际页面／透明类型分组，不能把模型数量当材质数量。原始、采用后、移除后的截图均需审看，并恢复索引／本地原件、删除测试创建的外部文件。页面用例数量由当前脚本与仪器结果核对；此项不代替真实大包或完整提供器矩阵。

UI 方案和公共组件交回前，按 DESIGN 的五档视口核对受影响页面，并记录浅深主题、像素／系统字体、200% 文字、减少动态和减少透明度。测量实际命中区及横向溢出，截图检查标题、数字、主要动作与导航是否被遮挡；模拟器或浏览器内的 CSS 放大不等于 Android 系统字号验收。固定导航和弹页应另看视口截图，不能只凭全页长截图判定遮挡。Demo 使用独立合成数据，明确可交互部分与静帧，不能访问正式数据库；实际业务不接入的按钮应说明其演示范围。

实机性能测量先取得关闭并重开本应用的授权。成对构建时显式传 `-PerformanceDiagnostics`，用 `tools/Measure-AndroidStartup.ps1 -Serial <设备> -Apk <已安装探针包> -OutputPath <新报告>`；摘要、前台、解锁、温度和空闲状态检查通过后才允许重启。测量只收阶段、数量和帧间隔，不记录任务正文、位置或密钥；不清全局日志、不改全局息屏。临时亮屏随后台、停止或四分钟上限释放。`-Zoom` 经真实缩放处理函数发送有界滚轮事件，不算原生双指手势验收。

最终包重新关闭诊断开关。原生采集器和 Web 采集模块不进入普通构筑，最终核对 manifest 开关、桥接标识和包内资产；探针包不能作为交付或发布候选。得到用户明确授权后，全量结束只核对最终包身份与安装摘要，不重复实机体验。

## 结果与复用

必要验证记录命令、输入、退出码和原报告，注明失败、跳过和重试。小定点无需另建报告系统；完整门禁的输入指纹、计数和摘要由工具报告持有，工作包给链接。

长任务等完成结果。用户明确要求全量时，首轮跑完全部可执行的门禁和用例，集中收集问题；全部返修后，后续全量遇错即停，修好再从头跑，直到完整通过。首轮使用 `tools/Prepare-Release.ps1 -CollectFailures`；后续不加此参数。单独首轮 Web 全量使用 `npm run test:web:release -- --collect-all-failures`。定点验证仍默认遇错即停。

跑大型测试时，直接等待测试自然结束或遇错退出；中途不反复查看日志，也不输出等待消息，退出后再集中检查和处理。

首轮的失败也必须记录，不能因继续执行而算作通过。环境无法继续、超时、中断或缺最终报告记为未完成；单例重跑用于诊断，不能拼成完整门禁。先分清失败来自产品、测试还是环境。已通过的全量仅卡在构建或交付时，按下一段复用证据，不重新收集一轮。

首轮中断后先列出未覆盖项，集中补测并审查同类夹具和断言，再返修、冻结并进入下一轮完整门禁；补测结果不与旧报告拼成全量通过。

全量已通过，仅构建或交付工具失败时，检查应用源码、依赖、配置和生成资产的差异，补受影响工具及构建验证，核对最终包内资产，复用未受影响的原报告。应用输入改变则重验相关范围；正式候选是否重跑全量，按冻结输入和影响判断。已经改变的应用内容需要新的用户确认。

原始失败记录保留。日志使用合成数据，排除凭据、任务正文和完整敏感响应；整理方法见 [工作区维护](WORKSPACE-MAINTENANCE.md)。

原生迁移的设备定点用隔离预览身份，测试结束或超时都要核对原 APK、库指针和数据恢复。长 CPU／文件检查可用不读业务库、不绘制世界的 debug 前台宿主，避免把后台调度混进功能验收；这种通过不等于真实冷启动、后台或画面通过。等待生成交付超时时附目标工作线程栈，设备命令另设总期限，超过后结束隔离测试并恢复；不靠无期限等待或反复看日志替代退出结果。测试宿主不进入 release 构筑。

原生设备检查前用 `:app:assembleP3DebugPair` 构建主包和测试包，并记录两包摘要及当前源码输入。单独 `assembleDebugAndroidTest` 不保证主 APK 已更新。`Test-P3CoreDevice.ps1` 在接触手机前核对成对记录；源码或任一 APK 不匹配就停止。此前失败及恢复证据保留，不能只重写摘要绕过构建。

模拟器检查显式指定 serial，并核对 `ro.kernel.qemu` 和 AVD 名称，避免把新接入的 USB 手机当作目标。保存实际 API、ABI、屏幕、GPU 和 ART 堆配置；配置文件的期望值不能代替运行时值。功能、布局和算法可在模拟器验证，模拟器耗时单独列出；OEM 通知、电池策略和真实手机的性能仍用对应真机证据。

容量夹具覆盖真实大文件：分别检查长历史、大型蓝图／资源混合，以及压缩引用展开。记录输入字节数、展开数量、设备堆限制和导入／导出／回滚结果；不能用填充字符、提高堆上限或只验证拒绝超限来代替合法大文件往返。获准使用的真实备份只进入私有测试目录与独立数据库，不封装进 APK，也不替换原库。

备份导入还要检查文件读完后的待确认状态：普通前台／权限／存档刷新不能取消确认；坏文件的错误保持可见并可关闭或重新选取。真实恢复后核对领域记录与弹页关闭，世界准备另记状态，不把核心界面可用称作完整世界已呈现。账户联网测试使用隔离控制器与合成账户，禁止普通账户在诊断库启用期间上传测试内容。

性能采样按 trace 自身记录的实际区间解释。取得必要的结束截图、内存和帧数据后，停止采样及隔离预览的负载，再传输大文件和分析；错误退出也执行收尾。温度与受限状态随样本保存；长组由脚本在样本边界自动检查阈值，发热时停止后续采集，保留已经取得的样本及其条件，不靠代理中途反复查看。

提交确认、GPU 完成和屏幕呈现分别记录。SurfaceFlinger 旧接口返回空白或全零时，该批帧率无效；改用可核对同一 Surface／frame number 的实际呈现事件。跨时钟先记录换算及误差；若只能测得更新后的下一帧，就写明保守上界，不称作首帧精确耗时。

已获授权的 MIUI 隔离界面检查可显式加 `-AllowMiuiBackgroundUi`：只临时修改预览包的后台界面启动权限，在安装测试包后应用，恢复原包后还原原值并核对。它不修改全局或其他 App，也不作为默认后台能力的证据。界面方法等待较久时，仪器至多记录一次有界线程栈和截图；主代理仍等进程自然结束，不反复查看进度。

原生 APK 构建前运行 `checkAndroidJsonAbi`：检查 JVM 核心实际字节码调用是否存在于本次 Android SDK 的 `org.json`，并先运行检查器自身的反例。桌面 JSON 库的重载不能当作系统 API；数字跨平台时使用两端共有的签名。这项接口检查不代替最低系统版本或真实 Android 的行为验证。

`Test-P3CoreDevice.ps1 -GeneratedPackets` 在空前台宿主里做真实 GLES 资源上传、owner 替换与释放检查。没有实际显示帧的资源检查不得写成世界画面、冷启动、帧率或省电通过；正式世界仍需另验呈现与交互。

`-GeneratedWorld` 才在上述 debug 宿主显式打开真实生成场景及 SurfaceView，不访问业务库。检查当前场景的 GPU 完成与回调身份，截图另等显示稳定并拒绝空白画面；截图等待不计入性能。非空像素不代表材质、布局或动态效果正确，仍要审图。设备报告保存本轮标签、精确 APK 摘要与恢复结果，场景报告及截图一起回收；若仅回收失败而原文件仍在，可单独补收并记录摘要与来源，不重复已通过的执行，也不覆盖首次失败报告。

`-Weather` 检查实际权限拒绝、私有缓存清除／取消及受控设置状态，不联网；`-Weather -WeatherCase live -SkipCore` 单独检查系统定位弹窗和真实请求，`settings-live` 改从真实设置入口启用、查看成功归因并关闭。两种联网范围不与其他检查混跑。预览用自身签名，服务拒绝时明确记录安全原因；有界失败通过不能写成服务成功。测试前在 Android 私有目录保留坐标缓存原件，外部只核对摘要；结束后恢复原 APK、库指针、缓存和权限。系统拒绝 Shell 授权时走正常的一次性授权弹窗，不改全局安全设置。实际定位失败后的缓存回退、服务成功及完整 UI 按各轮报告分别判断。

工厂场景通过后，还要在默认 Compose 页面等实际世界解除加载，检查导航／主题前后的绘制实例、GPU 身份和镜头；有视图节点不代表有 Surface 或显示帧。可向状态回调注入错误验证重试和旧回执隔离，但要标为回调注入，不称作驱动故障实验。仅补验未变核心之外的页面／绘制时可显式用 `-SkipCore`，报告须记录范围；原包和数据恢复检查不能跳过。

## 测试包

统一客户端的过渡：用户于 2026-11-15 确认账户服务上线后合并公开／私人版本，原私人上传改为服务端转发。以下双通道工具继续用于尚未切换的旧实现；新原生候选使用一个包含可选账户模块的用户 APK，不接客户端私有上传。包内身份须为 `accountBased=true`、`privateRelay=false`。旧安装的正式身份切换和真实来源交接留在 P4/P5，不能拿隔离预览覆盖证明迁移完成。主包与 Android 仪器测试包的成对源码／摘要核对照常保留。

日常测试包用于体验和继续修改，完成受影响的定点验证后直接构建，不默认跑全量。只有用户明确要求全量检查（如「全量测试包」）时，才运行完整门禁。已定点修好的问题不因出测试包重复检查；中途停止的全量记录为未完成，不能当作发布证据。

1. 验证后冻结应用源码、依赖、配置和资产。新交付轮的 versionCode 高于任一通道已交付或发布的版本；日常编辑不递增，同摘要再次交付仍是原轮。
2. 同轮顺序构建标准 APK 与含好友服务器模块的私有 APK。标准用 `tools/Build-Verification-Apk.ps1 -ArtifactOnly -DeliveryRoundId <本轮ID>`；私有工作区用 `tools/Build-IntegratedVerification.ps1 -RepositoryRoot <主工作树> -DeliveryRoundId <同一ID>`。尖括号参数要替换。
3. 两包共用冻结核心、版本、包名、签名和非空 DeliveryRoundId，各留 manifest 与 SHA-256。标准最终产物检查私有实现和配置隔离；同 code 的另一通道交付仍经过版本预检。
4. 私人包默认本地保留。安装、上传和部署按本轮授权；测试仓库只上传授权 APK，保留旧包。交付后回读并比较摘要。
5. 获准安装时覆盖升级，保留应用数据。设备忙就等待，用户明确允许后才用 `-AllowBusyDevice`。核对包身份和设备摘要后交用户体验；专项设备诊断另按请求执行。

补充蓝图从工作区 `packages/voxel/src/local-blueprints/` 构建。新增或更新时显式运行 `npm run package:local-builtins -w @blockcolc/litematic -- <输入目录>`，核对稳定 ID、普通/奖励类别和摘要；保留原件，两通道用同一份资产。

## Beta 发布

从 v3.0.0 起，面向用户的预览统一从 [blockcolc 的 GitHub Releases](https://github.com/Dieight/blockcolc/releases) 交付。预发布标签按 `v3.0.0-beta.1`、`v3.0.0-beta.2` 递增，下一条正式版本线从 `beta.1` 开始。Android `versionCode` 跨 Beta 与正式版递增，取大于已交付同包名 APK 的整数。内部诊断与隔离预览使用各自的构建号。

1. 核对 GitHub 已发标签、现有正式版和已交付的本地同包名构筑。完成本轮定点，明确要求全量时再跑完整门禁。
2. 审查待公开的提交与文件。将本轮源码交付提交推至 `codex/native-beta`。签名文件、凭据、诊断日志和 APK 留在 Git 提交之外。
3. 从该提交按[原生构建说明](../apps/native-android/README.md#beta-通道)签名并记录候选。核对产物包名 `com.blockcolc.app`、版本、正式证书和 SHA-256；涉及旧版数据迁移时，用隔离设备覆盖安装代表性的已发布 APK 并核对数据。
4. 用经验证的提交建立并推送同名 `vX.Y.Z-beta.N` 标签。Release 设为 **Pre-release**，上传 `Blockcolc-vX.Y.Z-beta.N.apk`，附发布说明。先核对草稿资产及提交，再公开预发布。`main` 和正式发行的 Latest 入口按正式发布流程推进。
5. 从公开下载地址回下载，核对摘要与标签提交，确认正式 Latest 入口指向原正式版。交付链接和版本码，保留验证回执。已发布的 Beta 留作对应版本记录，返修发下一号。

## 发布

按当前用户授权发布。已批准的常用路径是：完整冻结门禁、同轮标准和私人包、用户体验私人包并接受、发布对应标准候选。沿用这一轮的结果，不重复全量、第二次标准包体验或重建已接受候选。

准备发布时先核对已有完整门禁是否仍有效。缺少证据就说明缺项，由用户决定是否开始全量，不因「出包」或「发布」自行扩大验证范围。

这条路径用 `tools/Publish-PairedRelease.ps1`：传入成对核对记录和发布说明，明确确认用户验收与发布授权。工具重新核对两包身份、核心摘要、应用输入和私有隔离，等发布提交的 CI 通过后上传原标准候选，不查询或安装手机。

用户明确说“改完、全量通过后直接发布”时，用同一工具的 `-ConfirmPublishAfterFullGate` 记录这项授权，不要求再体验一轮。它与 `-ConfirmUserAcceptance` 二选一；记录注明最终包未人工体验，完整门禁、配对隔离和提交 CI 仍须通过。

用户要求标准候选设备验收时，使用 Prepare → Install → Accept → Publish。记录实际走过的流程；工具不支持的路径先修工具，不填写虚假的阶段或安装记录。

发布前关联原报告、两包核心和配置关系、精确标准候选摘要及用户确认。标准候选保留正式用途和来源记录，不能只给验证 APK 改名。应用内容变化后重新验证并取得确认；构建工具修复按前述范围复用证据。

核对发布提交的 CI、tag、Release/Latest、授权标准资产、实际下载摘要、包身份和私有隔离。网络命令失败先查远端结果再重试。发布后另记关闭情况，保留原 tag、APK 和原始验证记录。


### 原生用户预览与诊断构筑

`apps/native-android` 默认构建用户预览：` :app:recordUserPreview -PmatcPath=<Filament matc>`。该入口交付 `release/app-release.apk`，关闭 debuggable 并启用 R8 优化；隔离预览继续使用原预览签名，不能用 Debug 包代表用户实际性能。不传 `worldInputs` 或 `constructionInputs`；合法内置蓝图、原创材质、字体、音频和运行时 shader 仍由正常模块生成。此构筑选择 `src/userPreview`，R8 保留可读类名并删除实验／仪器入口；交付前 `verifyUserPreviewPackage` 核验实际 APK 的 manifest、DEX class definitions、实验资产排除及 47 份蓝图和必要资源。Kotlin 元数据对已删除类型的名字不是实际类实现，检查不能仅以子串代替 DEX 类定义。

仪器构筑必须明确传 `-PnativeDiagnostics=true`，再运行 `:app:assembleP3DebugPair`，并按所测实验提供 `worldInputs`／`constructionInputs` 和 matc。诊断 Activity、参考 WebView、P1／P2 固定场景、性能观测和测试提供器只在该配置接入；正常启动仍进入同一 `NativeApp`。测量专用的 `P2OperationCostTest` 位于 `src/diagnosticTest`，也使用该配置。不要把普通 debug 构筑当成已包含探针的包。性能归因可使用非 debuggable 的 benchmark 构筑，不能将带采样开销的结果直接当作用户响应时间。

手机已安装较高构建号的用户包时，诊断构筑显式传 `-PnativePreviewVersionCode=<当前构建号>`，以原签名覆盖；不用卸载或清数据绕过版本限制。结束后恢复原库指针、偏好和本轮指定的用户包，设备脚本的基线要求仍须真实满足。`-PnativeLargeHeap=true` 仅用于明确的容量对照，默认关闭；同时记录 APK 实际 flags 和设备堆配置，不能把放宽上限算作减少内存。

`am profile --sampling` 的间隔单位是微秒，10 ms 应传 `10000`。检查原始 trace 的溢出标记、实际覆盖时间和调用栈配对；溢出的文件只能作局部归因证据。启动耗时和帧率另用无采样记录，不能用带采样开销的时间替代。

`preview-apk-pair.mjs` 分别记录 `p3-user-preview.json`（一个 APK）、`p3-diagnostic-pair.json`（主包／instrumentation 两 APK）与 `p3-benchmark-preview.json`（测量 APK），schema 2 记录实际包内 mode、privateRelay、applicationId 及源码／产物摘要。` :app:recordBenchmarkPreview` 使用 Release 优化和 shell profiling，单独记录测量输入，不作用户交付。统一客户端不包含旧好友服务的地址或上传凭据。设备脚本在任何 ADB 调用之前核对 diagnostic 身份和探针实现；没有探针的用户包直接拒绝。构筑和本地门禁不等于手机启动、GPU 画面或行为验收。

账户定点使用独立数据库、合成账号及独立偏好；结束后恢复原指针和执行许可。服务端先验证身份隔离、逐字段权限、同项冲突、接管代次、单份每日根、损坏恢复和转发失败隔离，再补 Android 实际写入队列与页面。大蓝图必须经过实际传输、校验、采用和数据库重开，不用小占位 JSON 代替。SSH 实验隧道只改变传输路径，仍验证服务证书与主机名；它的通过不等于公网端口可达。合成账号不得绑定真实旧好友上传身份。

外部只读好友先用合成接口验证字段白名单、时区、日总量去重、会话过期、同源重定向、读取限额及失败后的停止展示，再用真实访客 API 验证兼容。Android 定点用合成读取账号添加正式只读来源，检查中英文展示、没有对外分享控件，以及移除／退出。只读来源不允许登录或作为旧服务的上传身份。检查旧上传令牌时使用鉴权后必定校验失败的空帧，不提交虚构专注、不重置来源；原邀请链接和已登录 Cookie 分开判断，日志不记录令牌、Cookie 或任务正文。

原生主页面切换的定点要实际滚动到中部或底部、展开子项并输入未提交草稿，再通过导航和左右滑动离开、返回；另外重建 Activity，核对位置、展开项、草稿和选区。世界旋转、热力图和滑杆保留各自手势，短横拖取消、纵拖不换页，首末页不循环。后台恢复世界时，除逻辑相机外，还核对实际 GPU 视口与离屏目标尺寸；显示缓冲、渲染目标和投影窗口不是同一个尺寸。模拟器帧指标仅作同环境诊断比较，不能当作 OnePlus 的发布帧率。

### 首次正式原生升级与回退

原生正式版的电脑端门禁在 `apps/native-android` 中运行 `:nativeReleaseHostChecks`，使用与正式候选相同的 Gradle 参数。它覆盖各模块单元测试、Android lint 和 JSON ABI。首轮全量加 `--continue` 收集各任务的失败，返修后去掉该参数，遇错即停。设备矩阵和同签名往返演练另有实际安装与恢复回执；旧 Capacitor 的 `Prepare-Release.ps1` 留给旧实现。

原生候选从 `apps/native-android` 工程构建。正式版和同签名演练使用正式签名环境执行 `-PnativeUpgradeCandidate=true -PnativeReleaseVersionCode=CODE :app:recordUpgradeCandidate`，正式版的 `CODE` 须高于所有已交付的同包名 APK，含 Beta。保留冻结源码、APK 摘要、版本、签名及 16 KiB 对齐证据。先在隔离 Android 实例验证标准和私人旧包的覆盖安装，核对 UID、首次安装时间、用户记录、本地素材及进行中轮次。让暂存和资源采用各发生一次可重试的失败，确认重新打开使用同一份旧数据。

回退前在原生端结算正在进行的计划并导出备份。恢复包沿用正式包名和证书，构建号高于已安装原生版。覆盖后先验证旧库可读，再从旧界面导入原生导出的备份，核对新产生的记录和旧端重新导出的摘要。再次升级时先在回退端导出最新备份，在原生端用备份恢复入口替换，并核对保留的本机回滚点。正式切换前按最终构建号走一遍完整往返，记录采用的备份和实际安装摘要。
