# Blockcolc 验证与交付策略

## 验证选择

验证按改动影响范围选择，不按版本大小或代理人数选择。

| 层级 | 使用场景 | 入口 |
|---|---|---|
| L0 定点 | 单一行为或清晰边界 | 受影响 Vitest 文件、Playwright spec、原生测试 |
| L1 快速 | 集成与提交前基础检查 | `npm run test:fast` |
| L2 Smoke | 主要用户路径受影响 | `npm run test:web:smoke` |
| L3 稳定回归 | 共享计时、恢复、存储或渲染契约变化 | `npm run test:e2e -w @blockcolc/web` |
| L4 正式门禁 | 范围冻结后的正式候选 | `tools/Prepare-Release.ps1` |

文档和 skill 修改验证引用、结构与一致性，不构建应用。修改 runner、共享 fixture 或发布脚本时，验证相应上层工具契约。

## 修复验证

- 从用户原始操作建立反例，可自动复现时先确认旧实现失败。
- 保留模式、数据量、主题、设备和输入条件，不只测理想路径。
- 同时覆盖失败方向与恢复方向，不只检查入口成功。
- 修改测试后运行该测试；旧结果不覆盖新断言。
- 产品明确改变时修改旧预期，没有新决定不能迁就实现。
- 编译、截图存在和函数测试通过分别只是证据的一部分。

## 高频风险边界

- 手势：正反方向、轻微斜向、越界、取消、滚动竞争和键盘等价。使用实际浏览器触控路径，不只调用处理函数。
- 页面：入口卡片及弹层、打开及关闭、返回路径、浅深主题、长文本与受影响的字号/安全区。
- 渲染：等待当前场景有效帧，固定必要时间与随机条件；图片不同或画布非空不能单独证明建筑、材质、装饰正确。
- 天气/同步：覆盖原生传输、实际响应格式、桥接、UI 和回退；区分定位、HTTP、解码、业务数据、鉴权和桥接失败。控制台成功调用不代替应用有效结果。
- 导入：文件入口、解压/解析、领域校验、保存、恢复、预览与正式世界；用边界规模合成数据及合法本地样例，不只加常量。
- 性能：同机同数据比较操作到反馈；记录持久化、世界重建和帧成本，不从重构推导速度提升。
- 计时/统计：模式归属、守恒、实际时长、跨日、中断、旧备份、重复恢复与写入失败。
- 原生恢复/通知：按 `docs/ANDROID-RECOVERY-MATRIX.md` 记录，真机性能可用 `tools/Measure-AndroidStartup.ps1`；OEM 结果不能由浏览器模拟替代。

用户文件与第三方资源只留本机，日志不输出密钥、任务正文或完整外部响应。

## 执行与证据

- 运行前明确源码范围、输出目录和运行者；共享 dist、Android 输出和报告不得被并发替换。
- 每次运行有独立标识，记录命令、源码指纹、最终退出码、报告路径、失败/跳过/重试。
- 长测试等待完成事件后集中检查，不按固定分钟反复查看；需要输入、提前失败或异常时及时处理。
- 子代理每 20 分钟仅检查异常停滞，正常执行不反复打断。
- 失败先判断产品、测试或环境原因；单例重跑用于诊断，不能替代要求完整运行的门禁。
- 超时、中断、缺最终退出码或源码中途变化不能记通过，不合并不同树的局部结果。
- skipped/flaky 不算 passed；记录理由、替代验证与是否阻断交付。
- 正式证据索引实际报告并保存摘要，不另人工抄一份汇总。

## 验证 APK

- 完成本轮受影响验证后，通过现有验证构建入口出包。
- 每轮应用测试包必须同时构建标准版与私有版：标准版 `tools/Build-Verification-Apk.ps1`；私有同步版使用私有工作区 `tools/Build-IntegratedVerification.ps1`。不能只交其中一个作为完整测试包轮次。
- 两次构建使用同一冻结源码、版本名、versionCode 和非空 `DeliveryRoundId`，分别写入标准/私有证据；先后构建不得改动源码。普通代码编辑不因此递增构建号。
- 迭代测试包默认使用 `-ArtifactOnly`，它会跳过设备发现和安装；同一轮顺序运行示例：`$round = 'v2.1.0-<唯一标识>'; .\tools\Build-Verification-Apk.ps1 -ArtifactOnly -DeliveryRoundId $round`，然后 `C:\Codex\blockcolc-relay-private\tools\Build-IntegratedVerification.ps1 -RepositoryRoot $PWD -DeliveryRoundId $round`。两份证据的 `DeliveryRoundId` 必须相同且非空；如需安装，走单独的获准流程。
- 新测试交付轮 versionCode 高于此前同包已交付/已发布轮，保持包名与签名；普通代码编辑不加构建号。相同已校验 APK 的重复交付不形成新轮。
- 同轮标准/私有包分别标记构筑类型和摘要，不将两个不同 APK 混成同一产物。私有 APK 默认仅保存在私有工作区；构建不自动授权安装、上传或服务部署。
- 两通道共用升级身份，新交付不能低于任一通道的已交付版本。同 code 的另一通道必须显式使用相同 `-DeliveryRoundId` 并分别写入证据；已交付的同摘要原包可重复交付。不同 worktree 构筑由私有脚本显式 `-RepositoryRoot` 选择，不扫描猜测邻居目录。
- 记录构筑类型、源码指纹、包名、版本、签名与 SHA-256；复制/上传/回读/安装均实际比较。
- 手机连接且安装已授权时覆盖安装，不清数据；忙碌时等待，只有明确允许才用 `-AllowBusyDevice`。
- 手机未连接且当前授权允许时，上传既有私有测试仓库，仅交付授权 APK、保留旧包，上传后回读比较。
- 验证包不得直接改名或提升为正式发布包。
- 安装后核对身份及设备 APK 摘要，不默认手机 UI 巡检；用户人工体验，专项诊断另行安排。

## 正式候选

1. 冻结范围、代码、依赖、构建配置和生成资产，沿用 `docs/versions/V<versionCode>.md` 工具契约。
2. Prepare 完成同一源码完整门禁并生成候选，不安装手机。
3. Install 安装并校验该候选；设备忙只暂停安装，不使同树门禁失效。
4. 用户验收精确候选后 Accept 绑定确认，不提前代签。
5. 用户明确授权后 Publish，不重新构建已验收候选。
6. 核对远端 Release、CI、回读摘要与设备安装证据。
7. 同步发布状态，关闭工作包，归档历史入口。

阶段 A 增量结果不抵扣阶段 B 全量。候选输入改变使原确认失效。发布后状态整理是独立文档变更，不修改原 tag、验收绑定、发布证据或 APK，不因此重建应用。

## 测试维护与操作入口

- 新测试按能力命名，不按版本复制流程；旧版本文件在能力修改时逐步合并或改名。
- `playwright.config.ts` 保留产品回归；`playwright.diagnostics.config.ts` 收集诊断；`*.extended.test.ts` 收集穷举。
- `npm run test:web:release` 生成生产优化 test-mode 构建，按 core/visual/renderer 分组，renderer 单 worker。正式 APK 不含 test-mode 探针。
- 单 spec 示例：`npm run test:e2e -w @blockcolc/web -- tests/resource-pack.spec.ts --project=mobile-chromium --workers=1`。
- 诊断入口：`npm run test:web:diagnostics`；Voxel：`npm run test:diagnostics -w @blockcolc/voxel`。
- 保留有实际断言的回归，不因文件名带版本就删除；临时 probe/截图工具无引用时归档或删除。
- 类型、工作包、资产清单及命名检查使用现行工具；资产重新生成与校验不得更新批准状态。
- `npm run test:tools` 是跨平台的工具反例检查，随 L1 运行；本机发布契约使用 `tools/Test-ReleaseWorkflow.ps1`，只运行合成数据，不碰手机或发布。
- 报告与截图按 `docs/WORKSPACE-MAINTENANCE.md` 整理，保留正式证据、历史 APK 和必要复现材料。
- 测试数量与耗时由报告生成，不写成架构/设计的长期常数。
