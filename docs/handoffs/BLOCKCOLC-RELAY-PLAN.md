## 2. 建议架构

本体共享领域投影 → 提交成功后的原生只读缓存 → Android ContentProvider → 私有 Kotlin 伴侣 → HTTPS → 单进程服务 + SQLite + 静态网页。

本体不开放原始 IndexedDB、文件路径或完整 DomainState。ContentProvider 只查询严格固定的快照/日汇总路径，拒绝 insert/update/delete/call 写操作；读取不能启动 WebView、推进领域状态或触发网络。

身份校验采用 signature 级自定义权限，加调用 UID 所属包和签名证书校验；签名密钥只在本机构建环境使用，不能写进源码或 APK。首版用可信同签名伴侣即可；若实际签名不同，在核心安全任务中明确证书白名单方案，禁止退化成只检查包名。未安装匹配伴侣时不运行额外导出调度；联网权限和上传责任只在伴侣中。发布本体的通用桥不包含任何私人域名或密钥。

伴侣在独立的非公开目录开发（建议 `C:/Codex/blockcolc-relay-private`，实施时创建），不放入公开 monorepo，不建立远程仓库或发布 Release。私有服务和网页也置于该目录。主仓仅保留通用只读桥及无凭据设计文档。

服务首选熟悉的 Node.js/TypeScript 单进程与 SQLite；网页输出 HTML/CSS/少量 JS。不用 SSR、React 运行时、Redis、队列服务、3D、图表库、远程字体或图片。构建期工具不进入运行容器。未来可将伴侣传输与协议提取为模块，但这不是双向云同步：账号、好友授权、冲突合并和删除传播另立项目。

## 3. 数据语义与需要冻结的协议草案

五项业务字段建议为 `currentName`、`startedAt`、`estimatedElapsedMs`、`estimatedEndsAt`、`todayActualFocusMs`。时间使用 UTC instant，日键固定按 UTC+8，不跟随手机当前时区。另设最小传输信封 `schemaVersion/sourceEpoch/revision/capturedAt`，它们是校验/去重元数据，不增加个人业务内容。服务接收时间由服务生成，不能把请求重试时间当成新采样时间。

- 名称直接取当前运行状态的严格投影，不发送任务 ID 或上级项目名。普通习惯没有小任务时如何命名，必须在协议冻结时明确，不擅自上传习惯标题作为替代。
- 当前起止和预计已持续时间统一描述当前专注轮次/休息段，不混用整场马拉松与单轮；若用户期望整场时长，冻结前确认并统一三者语义。
- 已结束记录以 `actualDurationMs` 为依据，包含正常、提前结束和中断的实际专注部分，排除休息。跨午夜按实际区间与 UTC+8 半开日区间求交，不按完成日期把整段塞到一天；这是独立导出投影，不改本体原统计规则。
- 当前未结算轮次的估计值不写入最终历史；今日已确认值可以暂时落后当前计时。界面使用“今日已确认”，当前大数字标注“预计已持续”。异常时钟、历史缺失或不完整缓存不能算成零。
- 网页收到状态后以时间锚点本地估算，每秒重算显示而非累计 tick；隐藏/恢复不累积定时器误差。始终显示“预计”以及“手机状态更新于 X 分 Y 秒前”。达到预计结束点即停止增长并显示“等待新状态”，不自动声称完成、开始休息或写入实际日总量。新状态可纠正此前估算（包含变小）。停止/空闲通知立即清除名称。
- 撤销原 90 秒新鲜度阈值：事件驱动下长期无新状态不等于断线。分别展示浏览器与服务器连接状态、手机最近状态采样年龄；SSE 保活、同版本响应、重连和日汇总补传都不能刷新手机状态时间。活动名称缓存建议到该段预计结束时清除（只留“等待同步”），并设绝对上限作为异常防线；具体上限在 C01 按合法最大段长冻结。断线期间在该边界内继续明确标注的本地估算，不保留任务历史或向存储写推算值。

### 午夜离线问题：不能只靠今天快照准确补昨天

服务器每天 UTC+8 00:00 关闭上一天为待确认状态，收到本体权威日汇总后确认或校正。同一日期 upsert，不累加重复上传。23:50–00:10 的 20 分钟应分为两天各 10 分钟；手机整夜离线时不得伪造“零点精确结算完成”。定时器之外，在服务启动和读取时补做日期推进，不依赖进程恰好在零点存活。

2026-09-07 用户已确认允许五字段之外的只读日汇总补传：仅日期、实际毫秒数和必要修订元数据，无历史任务名/逐轮明细，用于离线后校正日结算。首次是否补全本体已有历史、备份恢复后是否覆盖旧日值，仍随合同冻结；默认只补接入后缺失/修订日，不自动上传接入前历史全量或覆盖旧来源，避免扩展范围。

服务业务持久化仅 `date + actualFocusMs`，附最小确认/版本元数据。来源 epoch 改变须显式对账，不按设备时间先后覆盖已确认记录；权威修正可变小，不能用 max 永远吞掉修正。实时五字段只放内存，有 TTL，不写数据库、队列、磁盘缓存或请求日志；进程重启显示待同步。伴侣也只保留一个覆盖式最新快照，不排队存任务历史；日汇总可以持久化待重试。

## 4. 传输、安全与资源预算

- 事件驱动发送状态变化；失败退避并合并旧实时快照。Android WorkManager 仅作延迟补传兜底，不作为秒级心跳（周期任务最短 15 分钟）。Doze 会推迟网络，不承诺锁屏/强制停止后持续实时。先测 OnePlus 的事件送达与耗电，再决定是否需要用户可见的前台服务；不开隐藏常驻或逐秒网络唤醒。
- 浏览器首选 SSE/EventSource 单向推送：建立同源鉴权连接时原子订阅并发送当前完整快照；手机新状态到达且通过修订校验后广播最新快照，日汇总变化仅推对应版本通知。无需每秒或每 5 秒查库/查手机，热力图按日期/版本变化加载。初始订阅与取快照不能漏掉中间变化；重连直接给当前完整快照，不保留历史任务事件用于 replay。
- SSE 用 text/event-stream、no-store、X-Accel-Buffering: no 并及时 flush，流路由不压缩；约每 25 秒发送无业务数据的注释保活，以适配部署说明的 60 秒 Nginx 读取空闲超时。保活不是查询或手机同步，不刷新 UI 的手机状态年龄。宿主可能忽略关闭缓冲头，必须实际验证事件延迟与长连接，不能仅凭配置推定可用。
- 推送不可用/连续失败则关闭 EventSource，退到前台每 5 分钟一次查询（约 12 次/小时）；不同时运行 SSE、自动重连循环和轮询。首次打开/回前台/网络恢复可立即获取一次，做去重和节流；隐藏页关闭流并停轮询，恢复后取当前状态，不补播旧任务。降级期间 SSE 探测也不高于五分钟一次；认证失效停止自动重试，待重新鉴权。
- 每页至多一条 SSE，设置每身份与总连接上限、慢客户端缓冲上限和背压断开；撤销凭据关闭现有流，不只拒绝新连接。注意 Nginx 每 IP 最多 10 连接，多标签/同一 NAT 需纳入验收；超限降级五分钟查询，不擅改宿主配置。
- SSE 常态是一条打开的响应流，加状态变化消息与每小时约 144 条小保活；连接并非零成本，但不产生周期业务查询/数据库读取，具体 RSS/流量待实测。降级查询按每次含头约 1 KiB 粗估约 12 KiB/小时，每天 8 小时、30 天约 2.8 MiB/月/查看者（不含初始资源、TLS、重连与上传）。SQLite 每年仅 365/366 行业务历史，实际磁盘以数据库页/WAL/日志为主。
- 现有朋友容器配额：0.5 CPU、256 MiB、128 进程，非 root/只读根目录，`/data` 约 958 MiB，`/tmp` 32 MiB，共享 3 Mbps；8080 提供 `/healthz`，45 秒内成功；linux/amd64 无压缩 Docker TAR ≤200 MiB、展开 ≤512 MiB、≤50,000 条目、不声明 VOLUME。以上来自用户提供的部署说明，不是实测余量。
- 目标而非已通过指标：常态 RSS <160 MiB，在实际 256 MiB/0.5 CPU 限制下跑启动、并发、午夜、WAL checkpoint 和恢复测试；静态首屏压缩传输 ≤60 KiB；不得在运行容器安装依赖或编译。Node 镜像不达标时先量测缩减，再考虑 Go，不同时维护两套后端。
- HTTPS 不等于公开可读。上传 token 与查看凭据分离、可撤销；延续私密分享方案。查看邀请可用 fragment 一次性交换 HttpOnly/Secure/SameSite cookie，再清除 fragment；不把 token 放查询参数，不把 bearer 写入日志或静态资源。公开静态壳可以缓存，鉴权 JSON `no-store`。
- 对请求体、字段、批量日数和频率加应用级上限，校验时间/时长/名称长度；按文本渲染任务名，禁止 innerHTML。禁止 CORS 任意来源读私有数据，状态变化有 CSRF 防护，限制登录尝试，不开启请求体/认证头调试日志。错误信息不回显原文。
- SQLite 单写者、事务去重；在线备份用 SQLite backup API 或受控 checkpoint/停写，不只复制活跃主 DB 文件。镜像回滚不等于数据库回滚；迁移应兼容上一镜像并在迁移前备份。
- 不将用户的部署说明/SSH 私钥复制进仓库、构建上下文、APK 或交接文件。部署凭据据说明在 2026-09-14 00:00 UTC+8 到期；实施时先确认可用窗口，不为赶期限跳过验证。本轮不执行 SSH 或部署。

## 5. 核心视觉方向：一张专注公报，不做产品落地页

采用 Swiss 的网格、左对齐、强字号层级与 Brutalism 的直角、粗线、明确分区。不是拼贴海报，也不靠图片制造风格。

- 纸白 `#F4F4F0` / 墨黑 `#111111`，朱红 `#E33B2E` 为唯一强调色；红色主要做色块/标记，小字用黑色，最终审查实测对比度。
- 系统无衬线中文字体；计时器系统等宽与 tabular-nums；无外部字体下载。最大层级留给当前名称和预计持续时间，不加介绍文案或装饰 hero。
- 桌面 12 栏：左 8 栏当前专注，右 4 栏今日已确认；下方全宽年度热力图。手机依次显示名称、计时、今日、日历，16–20px 边距；主分隔线 3px，内分隔线 1px，方角，无阴影/玻璃/渐变/持续动画。
- 顶栏只含 BLOCKCOLC / UTC+8 / 同步状态；名称长文本换行，禁止撑破网格。开始/预计结束用次级两列数字。
- 热力图用 CSS grid，不用 canvas/图表库。桌面按周列；手机改月历与月份切换，不把全年 365 格缩成难点按的小格。交互日期真实目标 ≥44px（桌面年度小格只作概览，详细查询使用可访问的月历/日期控件）。键盘与触屏可查日期和时长，不只 hover。
- 固定分档建议：0、1–29、30–59、60–119、≥120 分钟，使用同一红色的浅深序列；图例写明阈值，不按年度最大值偷偷变色。缺数据用纹理/问号，零值空白，今天加描边、待确认加文字状态。颜色不是唯一信息。
