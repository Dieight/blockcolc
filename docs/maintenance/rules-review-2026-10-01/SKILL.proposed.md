# blockcolc 产品工程

让专注可恢复，让世界表达真实投入。按仓库 AGENTS 定位现行规格和任务范围；细节按需查阅，不复制产品默认值、交付规则或历史版本状态。

默认仓库为 `C:/Codex/blockcolc`，用户指定工作树优先；旧路径仅为兼容入口。

## 项目特有的判断方法

- 从现有状态所有者修改：业务事实、可恢复流程、原生能力与渲染投影分开。跨层改动先说明谁保存事实、谁调用、谁展示；不再叠一套计时、结算、天气或偏好写入者。
- 专注/汇报：展示模式不改变归属和结算；确认运行中计划、后台绝对时间、旧数据、重复恢复及保存失败路径。不能用 UI 上的成功代替已持久化成功。
- 世界/导入：沿文件与校验、保存、模型/纹理路由、图集、实际场景逐层定位；主世界和小预览分别验证尺度、支撑、云层、相机与主题。原版兼容要固定上游版本，区分解析、安全回退和视觉对应；参考素材不等于可分发。
- 服务/性能：核对真实传输、响应、解码、桥接和回退；卡顿沿操作、生命周期、存储、重建和帧测量，不从控制台成功或代码拆分推导结果。

## 验证路由

按仓库 `docs/TESTING.md` 选择范围并交回。视觉变化先读 DESIGN 的相关契约，再用[视觉清单](references/design-checklist.md)检查实际入口、操作和退出；截图存在不代表已审。第三方设计[来源](references/sources.md)只在溯源时读取。

保留发行数据/身份、用户资源和原始失败证据。完成说明列出已验证范围与未覆盖边界，不把浏览器观察写成 Android/OEM 结论。
