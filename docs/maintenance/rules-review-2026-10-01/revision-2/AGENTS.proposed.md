# blockcolc 工作约定

Android 是主要发布平台，Web 共用业务和界面。项目使用 npm workspaces。

## 开始工作

- 按用户当前请求做事；接续时看 `docs/TODO.md`。历史记录只供查证。
- 由当前代理独立完成，不调用子代理。
- 修改前看工作树，保留已有改动。接续测试或构建时，再确认进程和产物；源码、端口、dist 和 Android 输出由一个执行者写入。
- 审查、诊断和草案按各自范围进行。推送、安装、上传、部署和发布按本轮授权执行。
- 多项需求按现有模块职责安排，替换旧流程。涉及业务变化时先确认归属、保存失败和恢复方式。
- 保留用户数据、原始素材、历史 APK 和验证记录。不清应用数据，不用卸载解决升级问题；凭据和私有实现留在私有工作区。

## 文档写在哪里

任何 AI 更新文档都按下表归类。不要把测试结果写进产品规则，也不要把已经采用的产品决定只留在版本日志里。同一内容在所属文件维护，其他位置用链接；放错的内容移回所属文件，历史记录保留原文。

| 文件 | 内容 |
| --- | --- |
| `AGENTS.md` | 工作方式、文档归属和常用入口 |
| `BLOCKCOLC.md` | 当前产品行为、默认值和功能范围 |
| `ARCHITECTURE.md` | 模块职责、状态、存储、恢复和接口约束 |
| `DESIGN.md` | 视觉、交互、输入、响应式和无障碍要求 |
| `docs/TESTING.md` | 验证、构建、安装和发布流程 |
| `docs/TODO.md` | 当前任务和工作包链接 |
| `docs/versions/` | 本版范围、实施进展和交付记录 |
| `docs/releases/` | 面向用户的发布说明 |
| `docs/research/` | 调研、方案比较和待确认设计 |
| `docs/assets/` | 素材来源、许可和派生记录 |
| `docs/WORKSPACE-MAINTENANCE.md` | 工作区整理、归档和恢复方法 |

只读本次任务需要的章节。文档和代码不一致时，核对最新用户决定再修改。写长期规范时直接更新原条目，不另加一段相反规则。

每版文档使用 [模板](docs/templates/README.md)。长期规范持续维护，版本记录按阶段创建；模板里的空项不是已完成事项。简单修改记在当前任务里即可。

## 验证与交回

- 按 `docs/TESTING.md` 选择验证范围。文档修改检查引用和一致性，不跑应用全量或出包。
- 常用入口是 `npm run test:fast` 和 `npm run test:web:smoke`，按需要使用。
- 长测试等完成后检查最终退出码和报告；提前失败或需要输入时及时处理。
- 交回时说清做了什么、测了什么、交付了什么、还等用户确认什么。未测、跳过和中断如实记录。
