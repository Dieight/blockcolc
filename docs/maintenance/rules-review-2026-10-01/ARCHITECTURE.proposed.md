本文说明当前代码的职责归属和不变量。版本历史、带日期的实施记录和单次验证结果应放在版本工作包或 [`docs/archive/v2.0.0/`](docs/archive/v2.0.0/) 中。

## 运行时边界

```text
apps/web
  路由、交互、展示、渲染器宿主
        |
packages/application
  用例、命令串行化、投影、平台端口
        |
packages/domain
  命令、事件、校验、状态转换、确定性事实
        |
packages/storage-indexeddb  packages/platform-capacitor  packages/voxel  packages/litematic
  状态/备份/CAS             原生生命周期与文件           渲染           本地 NBT 导入
```

- `packages/domain` 持有持久化产品真相，不导入浏览器、React、Capacitor、IndexedDB、Three.js 或展示代码。应用端口属于 `packages/application`；适配器负责实现这些端口。
- 展示偏好、可恢复的流程上下文、领域事实和原生能力结果彼此分离。渲染器或页面可以投影已保存事实，但不能暗中写入业务状态。
- Android 标准版与私有同步版共用应用源码。标准构建明确排除私有传输和配置；只有私有构建可以接收外部私有模块目录。私有传输保留在此公开仓库之外。私有同步失败不能改变本地计时或保存行为。

## 领域状态与时间

`packages/domain` 中的 `DomainState` 使用 schema 12。校验严格：除明确记录的旧数据迁移路径外，未知或格式错误的字段都会被拒绝。重要事实包括：

- 活跃、暂停、纪念和软删除的项目；稳定的聚落索引；有限小任务和独立完成的习惯建筑；
- 一个可选的活动专注会话，以及只追加的专注历史和进度汇报；
- 专注完整性策略，以及用于协调中断的生命周期事实；
- 每日目标、日历设置、状态/衰败策略、导入的项目蓝图、装饰资源和奖励。

进度与状态使用整数基点（`0..10000`）。领域时间戳为 ISO 8601 UTC 时刻；已完成的专注记录也保留本地完成日期。当前 Litematic 项目快照最多支持 `96 x 96` 占地、`256` 高和 `300,000` 个非空气方块。`packages/litematic` 另行执行解析器输入、NBT 遍历、调色板和文件大小限制。UI 显示当前 `64 MB` 文件限制。导入的装饰资源限制为 `12 x 12 x 16` 和 `2,000` 个非空气方块。

计时以持久化的绝对时间 `endsAt` 为准，专注不能暂停。到达或超过 `endsAt` 时完成优先于迟到的后台/中断信号。已完成或中断的专注保留实际耗时；中断不计为完整轮次或施工进度。习惯任务完成一次，恰好推进一轮建筑；有限任务的已完成专注等待进度汇报或马拉松统一结算。

其他持久化边界包括：同一时间最多一个活动项目；实体 ID 永不复用；每条已完成专注记录最多归属一次汇报；用户汇报进度不能倒退；状态衰败不改变该进度。习惯任务没有小任务；已完成的习惯建筑在源习惯被删除后仍作为独立历史保留，且不受衰败影响。存在活动会话或待汇报时，不能通过切换或创建项目绕过它们。

### 轮次计划上下文

未完成的轮次安排是可恢复的本地 UI 上下文，不是第二条领域记录，也不属于领域备份。活动专注会话及其当前阶段 `endsAt` 仍是领域真相。计划存储先写入，再采用变更后的安排；普通进程重启时保留上下文，只在明确取消或结算完成时清除。锁定计划中的宿主项目持有其展示和命令归属，即使用户切换了所选项目也不改变。

极简模式使用未绑定任务、延后结算的马拉松计划：保留宿主引用，`subtaskId` 为 null，并由 schema 12 显式标记 `deferredSettlement`。有限任务和习惯计划保留各自不同的结算行为。延后计划等待最终分配时，习惯轮次不能提前推进。迁移不会为旧记录推断 `deferredSettlement`。若可恢复的计划上下文丢失，仍可汇报已持久化的完成轮次，但恢复流程不得捏造剩余计划。

## 命令、存储与备份

- `ApplicationService` 校验并串行化接受的命令，按当前仓库版本保存，之后才公开已采用的状态和事件。`StateRepository` 使用 compare-and-swap：旧版本写入会失败，而不会覆盖较新的状态。
- `IndexedDbStateRepository` 在 `appState` 中保存一个经过校验的聚合；`rollbackBackups` 保存不可变恢复快照，元数据另行保存。导入先预览并校验，再在同一事务中保存回滚快照并替换数据。恢复也在同一事务中为当前状态创建快照。大型项目删除采用软删除，并原子记录回滚信息。
- 备份封套版本 1 携带规范化载荷与 SHA-256 校验和。载荷使用当前领域 schema 12。解析前先验证校验和；导入上限为 `100 MiB`，并执行严格的 schema 迁移。除已记录的迁移外，仍拒绝未知字段。自动回滚历史在事务中裁剪，只保留最新两份快照；用户导出的备份不参与裁剪。
- 持久化失败不能报告为已保存。除非适配器提供事务，否则跨存储步骤不具备原子性：按约定保留/协调可恢复草稿；不能只因之后的 UI 上下文保存失败而撤销已经提交的专注。
- 导入蓝图的身份和内容属于项目备份真相。内置目录新增内容和可选本地内容不能成为渲染已保存导入蓝图快照的前置条件。

## Web 职责与成就展示

- `App.tsx` 组合路由并持有应用服务生命周期。`command-runner.ts` 分发单条应用命令，将实际结果映射为普通命令反馈，刷新界面并保留异常；它不是成就展示队列，也不是第二个持久化所有者。
- `ApplicationService.achievementsProjection()` 是从保留的专注、进度和建筑事实生成的确定性只读投影。它不保存事实、不授予奖励、不新增 schema 字段。`unlocked` 与可空的 `unlockedAt` 相互独立；未知的历史日期仍保持未知。
- `StatsScreen` 仅在统计路由 `active` 时对账成就投影与本地展示 receipt：尚未展示项合并成一次对话框，关闭后写 receipt。写入失败仍允许本次关闭，并提示以后可能重播；已有 receipt 的项不重播。加载、导入、恢复和普通命令反馈不另建成就展示入口或基线。
- 计时流程持有当前平台端口的交互；轮次计划存储持有计划恢复；渲染器宿主持有世界展示。展示改动不得复制偏好写入者、创建第二个时钟或造成不必要的世界重建。
- 极简汇报沿用 `FocusReports` 的同一草稿、轮次分配、重复提交保护和命令路径，仅选择 minimal 展示分支；延后结算报告仍在极简表面，普通任务报告不因此改变身份。保存失败保留草稿，成功后才退出。玻璃边缘订阅世界已完成帧，窄带采样世界背景而非前景 DOM，不持有业务状态；不可用时回退原 CSS 玻璃，不阻断世界帧。

## Android 生命周期与通知

- Android 原生 `AttentionStateMachine` 是唯一将 activity、窗口焦点、多窗口和 OEM 小窗信号合并为前台/后台转换的权威来源。它只快照一次实际后台时长、电源/锁屏/系统 UI 上下文。`appStateChange` 不是第二个 Android 离开计数器。Web/PWA 可见性仍是尽力而为。
- 应用/领域协调逻辑根据持久化事实应用已保存的离开阈值与豁免条件，并优先检查 `endsAt`。App/bootstrap 边界在刷新之前持久化一次性提示；常驻世界页面显示现有的短暂离开提示浮层。普通命令反馈使用全局消息通道。
- 通知是适配器，不是计时真相。活动专注和轮间休息使用绝对结束时间及互斥的单一常驻表面；生命周期刷新保持稳定身份，真正的新计时器使用新身份。完成提醒使用独立 ID。Android 渲染计时器；WebView 不运行后台逐秒计时器。
- 仅在平台报告资格时请求 Android 16 promoted-ongoing；提升被权限、AppOp 或 OEM 拒绝时，保留可用的标准常驻计时器并说明限制。OEM 的锁屏/AOD/Fluid Cloud 布局不是计时真相，不能用后台逐秒重发通知补偿；具体设备观察归恢复矩阵和原始报告。
- 天气是可选展示数据。仅在启用且世界可见时由 Web hook 请求。Android 持有定位权限、签名身份请求元数据、有界 HTTPS 解码，以及 app 私有 no-backup 存储中的最近有效坐标缓存。只有仍有授权时才可复用缓存坐标；关闭现实天气会清除缓存。失败时回退本地确定性天气，且不改变专注或备份事实。

## 世界与资源职责

- `WorldCanvasV7` 持有常驻渲染器、世界 HUD、建筑记忆展示和相机控制。`world-projection.ts` 适配只读应用快照。`voxel-runtime.ts` 在世界与预览之间共享惰性初始化。
- `packages/voxel` 持有地形、几何、图集、shader 和方块排序。`packages/litematic` 持有有界的本地 NBT 解析和规范化蓝图导入。渲染器不持有任务进度或状态。
- 导入资产先在本地校验，再采用。资源包文件、归档展开、条目数量、图像/图集和几何预算仍在解析器/渲染器边界执行；见 [`MINECRAFT-VISUAL-COMPATIBILITY.md`](MINECRAFT-VISUAL-COMPATIBILITY.md) 与 [`docs/research/MC-26.3-resource-pack-audit.md`](docs/research/MC-26.3-resource-pack-audit.md)。解析成功不代表与原版完全视觉等价。不要打包上游受版权保护的纹理、模型、JAR 或样例资源包。
- 图集页数与动画序列受配置的 GPU 纹理尺寸和页数预算限制。方块按整体解析：缺失或不安全的面、模型或图集页会使整个方块回退，避免绘制误导性的局部方块。当前数值解析器和图集限制由代码/配置持有；不要在此文档重复维护另一份独立常量。
- 地形、道路、建筑、装饰和定向光共用一个可旋转世界根节点。渲染器按需请求帧，并在隐藏/后台时停止。UI 浮层、坐标、统计和计时文字不会触发地形重建。世界适配依据聚落内容边界；裁剪覆盖完整可见地形。海洋建筑、道路、支撑和路灯共用四格居住基准面。
- `scenery.ts` 只规划背景群系与地点，读取当前渲染地表的真实顶面、道路和任务/奖励保护区。沿共用静态方块路由生成自写结构，无伪任务或伪奖励；主世界默认启用，小预览不生成。树木合批为单格方块，结构按自身投屏大小与迟滞选择细节，保留屋顶、街巷和船体/桅杆轮廓。背景扩展可见性和阴影边界，不扩展任务的相机适配边界；装饰更新不隐式改变旧地形、水系、任务布局或持久化身份。
- 降水在现有 `FrameRequestScheduler` 的单一帧请求中更新 GPU 时间 uniform；实例矩阵只在场生成/相机覆盖变化时上传，不在每个粒子每帧重写。降水可见且未减少动态时按需继续请求运动帧，实际拖动不暂停雨雪；隐藏和减少动态冻结同一时钟，恢复不追补。云等低频环境更新仍沿原自适应节奏，不建立第二套渲染循环。
- 天体展示保留真实太阳/月亮位置。现有单一定向光与阴影贴图投影占主导的可见天体：日间太阳，夜间按地平线可见性和月相投影月光。材质面明暗、阴影刷新角度和诊断射线共用此投影；无可见直接光时仅保留环境亮度，不从地平线下补太阳或另造影子。
- 缓存阴影的深度贴图和采样矩阵来自同一次深度绘制；普通光照更新不能单独改动采样矩阵。时间/天文跳变、动效终点、可见性和上下文恢复显式申请刷新，其他帧仍按原策略合并。光影切档先暂存新尺寸的独立目标，失败保留旧目标，提交后才释放；渲染器重建复用画布时重置 WebGL 交接状态，销毁时释放自己持有的阴影目标。
- 自适应画质区分稳定主帧与深度刷新帧的调用/三角预算：一次冷启动或切档深度绘制不被当作稳定主帧超限；持续的交互耗时仍可降级，不锁死用户请求档位或取消安全预算。
- 相机旋转、双指/滚轮缩放、视口适配及 `contentBounds`/`visibilityBounds` 各自独立。建筑记忆的显示/隐藏不清除相机聚焦；显式重置地图会清除聚焦并恢复完整聚落目标。
- 画质档位只改变视觉开销，不改变保存事实。Cinematic/high 后期处理可选且受限；balanced/low 的离屏目标缩至 `1 x 1`，自适应降级具有最终决定权。隐藏、减少动态或能力不足时暂停相关动画；性能验证归 TESTING。
