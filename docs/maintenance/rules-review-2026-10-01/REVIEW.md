## 先看结论

真正要减掉的是“每次都要读、每处都要写、每次都要重跑”，而不是把有价值的产品边界删成口号。

- AGENTS 只保存项目执行约定、少量风险边界与按需入口；不重写模型系统提示词。
- 专属 skill 保留 blockcolc 特有的状态所有权与问题定位方法；不复制交付程序和全部规范目录。
- 测试范围、门禁复用、成对包和发布路径只在 TESTING 维护完整流程。
- TODO 只容纳当前范围、待决项与历史入口；旧版本流水账原文保留，不持续加载。
- 产品、架构、设计分别说明“做什么”“谁负责”“怎样呈现”；只移走重复流程，不删已批准的视觉与数据契约。
- 长期规范不反复写正式版本/验收状态。BLOCKCOLC 保留正式基线，TODO 保留执行入口，其余按需引用。

## 当前文件的具体问题

1. AGENTS 与 skill 都要求先读完整产品文档；改一个单位、注释或局部样式也会付出同样读取成本。
2. 成对包、版本号、签名、摘要、私人留存和发布例外在 AGENTS、BLOCKCOLC、TESTING、私有 AGENTS 中多处维护，容易只改其中一份。
3. TODO 虽已标注历史，仍保留长段 v2.1.0 计数、包摘要和“最新”阶段文本；接续入口本身过重。
4. ARCHITECTURE 与 DESIGN 顶部仍写 v2.1.0 基线和“v2.2.0 候选/未验收”；与已发布事实不一致。
5. DESIGN 夹带成就 receipt 等持久化细节，导入上限又与 ARCHITECTURE 重复；它们不是视觉规格的所有者。
6. 有些单次设备观察和阶段性记录仍混在长期契约里。应留下通用边界，原始观察归恢复矩阵/版本记录。
7. TESTING 的验证层级容易被读成每次逐级必跑清单；长段交付细节中关键例外不够显眼。

## 需要和规则一起考虑的工具对齐

这部分仅提出方案，未改代码，也不以文档宣称工具已支持。

- `Publish-Release.ps1:23` 只接受传统 `accepted` 阶段，`:67–76` 还强制要求标准包设备记录和在线设备；`Release-Common.ps1:370–375` 也有相同要求。它们和已批准的“同轮私人包核心验收”路径不一致。
- 建议让发布工具显式区分“标准候选设备验收”与“成对核心验收”。后者必须校验原始完成报告/限域复用证据、两包核心和配置关系、标准隔离、升级身份、DeliveryRoundId、精确摘要与用户确认；不添加假的安装记录，不使用跳过全部检查的通用开关。
- 成对构建时同步登记标准正式候选及来源，沿用该轮原始标准输出；“禁止只改名就发布”保留，但不能演变成验收后再做一次相同构建。正式/验证用途的记录与实际字节身份分开。
- 新发布提交的 CI 通过后再公开资产。网络步骤采用可恢复、有限重试：先查远端 ref/Release/资产是否已经成功，再继续，不反复创建或覆盖。
- 工具测试以合成 manifest/报告/版本记录覆盖两条路径和拒绝条件；不碰手机或实际发布。本轮只核对了现行代码，不执行此改造。

建议你先审规则正文，再明确是否一并批准上述工具改造。未批准前不改脚本、不绕过现行检查。

## 应用方式与保全

批准后按八个目标分别替换，不额外增加一套全局或厂商专属规则。保留专属 skill 名称、现有 UI metadata、调用策略、视觉清单与来源文件。

旧 TODO 全文保存为同目录 `docs/TODO.history-2026-10-01.md`，维持原相对链接；新 TODO 只给当前状态与历史入口。其他原文件已有 Git 基线可追溯；私有规则和工作区 skill 在替换前留各自的本地原文快照。

协议、资源兼容清单、Android 恢复矩阵、资产来源、已发布 APK 和原始报告不属于本轮压缩/清理对象。同步协议没有逐条改写，本稿不据此声称服务器契约已重新验证。

只验引用、草案结构、原文件保全与 skill 格式；若随后获准改工具，再运行对应工具反例检查，不重跑应用全量。

## 静态场景推演

以下是逐条审查的预期，不是另一个模型或自动化 agent 的实跑评测：

| 真实请求场景 | 草案预期 |
| --- | --- |
| 只调整一个数字单位 | 定位所属 UI 和定点验证，不遍读全部规范、不出包 |
| 全量已过，仅打包入口故障 | 审差异、补工具与构建，证明应用输入不变，复用原报告 |
| 改了影响共享计时/恢复的行为 | 扩大受影响回归，不能沿用旧候选确认 |
| 用户要一轮测试包 | 新交付轮版本可升级，标准/私人同轮分别留证，默认不自动安装/上传 |
| 私人包测过后说“发吧” | 发布绑定的标准候选，不强迫第二次体验，不捏造设备验收 |
| 已结束版本后只说“继续” | 查当前入口，不复活旧代理任务、旧部署授权或未采用设计 |
| 用户要求审查规则草案 | 草案保持不生效，不改当前执行规则或应用功能 |
| 整理截图与输入资源 | 精确辨认并可恢复归档，不删历史 APK 或把用户原件当缓存 |
