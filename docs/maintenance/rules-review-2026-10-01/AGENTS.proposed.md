# blockcolc 执行约定

Android 为主、本地优先；Web 共用业务与界面。使用 npm workspaces。

## 范围与执行

- 以用户当前请求为范围；接续时查 `docs/TODO.md`。已关闭工作包、历史交接和旧授权不重新产生任务。
- 当前代理独立完成，不调用子代理，除非用户明确改变决定。
- 改动前核对工作树；继续构建/测试时再核对进程和产物。共享源码、端口、dist 和 Android 输出只由一个执行者写入。
- 审查或诊断不默认修代码；用户要求草案时只写草案。实施请求包含必要的本地编辑、合成测试和可回退提交，不需逐步确认；推送、安装、上传、部署和发布按当前授权执行。
- 多项需求按现有状态所有者和依赖组织。替换旧路径，不叠加同名流程；涉及业务语义先明确模式归属、保存失败和恢复行为。小改动不强制制作完整工作包。
- 保留用户改动、原始素材、历史 APK 和正式证据；不清应用数据，不用卸载绕过升级。凭据、私人实现及未获分发授权的第三方资产不进入公开仓库。

## 按需查阅

| 要解决的问题 | 权威入口 |
| --- | --- |
| 产品行为、默认值、模式区别 | `BLOCKCOLC.md` |
| 状态所有权、保存/恢复、原生与渲染边界 | `ARCHITECTURE.md` 与实际代码 |
| 视觉、材质、输入和响应式 | `DESIGN.md` |
| 验证、出包、安装与发布 | `docs/TESTING.md` |
| 当前范围、待决选择和阶段证据 | `docs/TODO.md` 指向的工作包 |

产品开发、排障和审查使用 `blockcolc-product-design` skill。只读取与任务有关的文档章节，不为文字或单点修改遍读全部规范。文档与代码冲突时核对最新用户决定，不擅自改产品含义；确认的决定更新其所属文档，不追加一层覆盖规则。

## 验证与交回

- 先验证受影响行为，再按风险扩大范围；文档/skill 不触发应用全量或 APK 构建。
- 常用入口：`npm run test:fast`、`npm run test:web:smoke`；正式门禁和成对测试包见 `docs/TESTING.md`。这些是可选入口，不是每次必跑的清单。
- 长测试等完成事件后集中核验最终退出码和原始报告；不定时轮询通过数量。故障和需要输入时及时处理。
- 完成说明区分实现、验证、交付和用户接受；未测、跳过与中断不冒称通过。证据保存在报告/工作包，不重复抄进长期规范。
