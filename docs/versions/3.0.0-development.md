## P2 第一工作包：完整存档与写入边界

2026-10-22，用户同意进入 P2。本轮先替换旧实验不完整的持久化起点，不扩展独立 App，不修改正式版本或操作手机。

- 新增 `domain-core`，按当前正式 `parseDomainState` 接 schema 15 全部字段、引用与时间关系，以及领域 schema 1—14 的转换。保留招牌、篝火物品、移动活塞、体素属性、习惯封存、奖励、生日和便签；不把旧实验的计时摘要称为完整存档。严格 JSON 拒绝重复键、坏 UTF-8、非有限数值、尾随内容和孤立代理码；预算采用 100 MiB 文件／512 MiB 展开常量，不继承 8／32 MiB 的实验上限。这些常量尚不等于最大容量端到端已验收。
- 新增 `state-store` 和 `state-store-android`。任务、会话、汇报、奖励等按实体行保存，完整蓝图按内容摘要去重；领域数据、本地计划、自动授权、revision、替换代次和幂等回执同事务提交。正常保存不动替换代次，内部替换清掉旧控制状态；同会话 ID 不能让旧授权复活。双连接竞争通过数据库 CAS 拒绝旧写，不靠单个对象的内存锁假设全局只有一人。
- 仍以完整领域格式作为转换和验证边界，而非直接搬旧样机原子文件；目前完整读取／校验仍有成本，没有把它说成计时热路径或存储已更快。尚未接好备份根前不裁剪无引用蓝图，不虚报已实现空间配额。
- Android 适配采用系统 SQLite。六张小表和共享 SQL 在 JVM 的真实 SQLite 上检查，Android 侧另有绑定参数／事务／重开测试入口；避免此阶段另外引入一套 Room／KSP 生成层。[Room 官方介绍](https://developer.android.com/training/data-storage/room)、[SQLite 事务 API](https://developer.android.com/reference/android/database/sqlite/SQLiteDatabase)和[OpenHelper 的错误处理入口](https://developer.android.com/reference/android/database/sqlite/SQLiteOpenHelper)用于核对取舍。不是认定直接 SQLite 比 Room 更快。
- 测试 Oracle 直接执行当前正式 TS，比较完整规范化输出；生成器、领域源码、锁文件和历法依赖都有摘要检查。农历计算采用同一上游的 Java 版，许可随模块保留。发现正式目录在公历 100／999 年因内部日期未补齐而报错，记录原结果并保持奖励校验拒绝，不在迁移时悄悄改变历史行为。

### 验证与下一步

最终定点通过，见[冻结检查点](../../artifacts/experiments/v3.0.0/p2-data-foundation-checkpoint.json)。996 份实际正式解析结果含 295 份接收／完整输出对照和 701 份拒绝；接收项还逐一通过真实 SQLite 往返。另核对 500 组正式节日日期，以及时区别名、固定偏移、跨日和夏令时；不是把这些循环项另称为 1,496 项独立测试。JVM 共 18 项用例通过（领域 6、存储 12），Android 库、测试 APK 编译和 lint 通过，进程退出 0。10 MiB 严格 JSON 字符串能通过输入层，100／512 MiB 的完整备份端到端仍待后续容量测试。

事务用例涵盖重开、蓝图去重、四个写入阶段的失败回滚、双连接 CAS、重复请求、替换撤权、坏存档及终态计划；同一请求的重放也不能绕过损坏检查。完整定点最初于 `p2-state-fourth.log` 通过，补本地控制和终态反例后再通过；最后扩展时区检查发现 GMT+0、ROC 等 JS／Java 识别差异，已按实际正式结果补齐，不靠删预期换通过。最终报告、Oracle、XML、lint、库／测试 APK 及双方源码副本保存在同名检查点目录，不依赖后续会覆盖的 build 输出。

原始失败仍保留：`p2-domain-first.log`（旧年历生成器未捕获异常）、`p2-state-second.log`（缺字段异常未统一）、`p2-state-third.log`（指纹根目录差一级）、`p2-zone-alias-first.log`／`p2-state-final-second.log`／`p2-zone-alias-second.log`（补充时区兼容反例）。最终使用 `p2-state-final-third.log` 对应的源码和结果，不拼接旧报告当作新通过，也没有重跑发布全量。

本包还没有迁移领域命令执行器，也没有连接日常页面、后台通知或真实用户数据。内部 `replace` 只有事务语义，未接完整备份封套和回滚快照前不作为用户导入功能。接下来依次完成：封套 1／2 和回滚／每日合并根；完整命令对照与绝对时间计划；同一预览中的日常闭环及原生通知；最后才做 P2 集成净收益测量并决定是否接 P3。Android 测试 APK 编译不等于已做实机验证；当前手机上的 P1 包不冒称已含 P2。

## P2 第二工作包：备份、业务执行与日常闭环（当轮记录）

- 完成条件：封套和所有业务命令与当前 TS 核对；导入、恢复、每日合并与失败回退通过；普通／习惯、极简／马拉松在活动世界上完成保存、汇报、统计和恢复；最后补实机后台与集成成本，不以编译成功收口。

封套 1／2 已接完整 schema 15，使用原标识、摘要、100 MiB 文件和 512 MiB 展开预算；原生导出与正式导出逐字比较规范化文本和摘要。SQL 布局升级到 2，增加独立内容块、快照根与引用，普通存档仍逐项保存。操作回滚最近两份，每日只保留最新一个独立可恢复根；坏根、超预算、跨日／时钟回退和注入失败的反例保留。`p2-backup-first.log` 的首轮定点及 Android 库 lint 退出 0，后续增强仍随集成重验，不据此宣称最大容量已在手机验证。

业务执行器已覆盖当前 37 种命令。正式 Oracle 每步保存前态、输入、时间、成功／失败码、事件和完整后态；642 步对照通过，之后又接入正式统计归属投影逐步比较。`focus-core` 将自然完成、休息、等待、自动续轮和手动结束合成一个事务，不复制旧 UI 计划与领域事实分开写的窗口。第一轮计划定点包含三轮后台补齐、重复／旧票据、手动提前结束与零休息、短末轮和尾段休息；正在补齐导入后的手动入口、取消原因与 Android 实际交接。

建筑更新采用明确有界的 P2 输入：为海岛／海岸 25 栋中的第一座工坊，按正式建造器的全部体素施工阈值生成候选，保留每次新暴露的面、材质和碰撞，而非复用 P1 的固定 60% 对照。它是受控输入的派生几何缓存，不等于通用地形／蓝图建造器已经迁成 Kotlin；不把离线准备从启动成本中藏掉。完整通用世界迁移与最终冷启动收益仍须后续阶段验证。

当前集成尚未收口。`p2-commands-first.log` 保留生成器把暂停任务直接当活动任务的反例，修正正常流程后 `p2-commands-second.log` 通过；`p2-focus-first/second.log` 保留 Kotlin 空值跨模块和测试源目录的编译失败，`p2-focus-third.log` 通过。第一次 Activity 编译发现 Compose 接收器歧义，第二次构建已出 APK，但 lint 发现精确闹钟权限声明的误判及适配警告；按官方特殊权限入口做局部说明、补旧系统入口和广播 action 校验后继续重验，不将该失败版本安装或冒称通过。

### 实机发现与修正

坐标行为核对固定版本的[顶点入口](https://raw.githubusercontent.com/google/filament/v1.56.0/shaders/src/main.vs)与[访问器](https://raw.githubusercontent.com/google/filament/v1.56.0/shaders/src/getters.vs)。

初稿部分旋转建筑与云缺失。关闭裁剪没有改善；Filament 的 `material.worldPosition` 已含相机原点偏移，直接左乘实例矩阵会把偏移一起旋转。改为 `getWorldFromModelMatrix() * transform * getPosition()`，补矩阵顺序反例后，建筑群与云回到相应位置。实体有独立变换组件，相机采用源视野，阴影范围有界；阴影正式表现仍待开关对照。

自定义 AO、天气、夜空／水反射和动画不能由普通 PBR 代替。只有显式 `projectionOnly=true` 才能查看几何诊断，普通入口拒绝未迁移程序。偏亮颜色、阴影／AO、反射和透明差异未算通过；快照也不能证明全图可见性，地形生成和动物 AI 尚未迁成 Kotlin。

## P1 第二工作包：完整输入与局部替换

- 问题：当前快照可能丢失被源镜头裁剪的实例、非标准顶点／实例属性和自定义程序的实际参数；纯代次测试也不能证明 GPU 只更新一栋建筑。
- 范围：只改原生预览工程、导出工具及其定点测试。先保留完整来源数据和显式缺项，再接所有者范围的资源替换，不改正式世界生成或产品行为。
- 完成条件：转动源镜头不会改变静态库存；不同自定义程序／闭包参数不被合并；特殊属性有可验证的保留或明确拒绝；建筑替换实际提交到 GPU，过期／失败更新不损坏原场景，其他所有者资源不变。
- 回退：旧输入和 APK 保留，格式变更显式版本化；未迁移的表现继续拒绝进入正式效果入口。此包不代替天气／动物、反射和同画质呈现关卡，不因局部通过进入 P2。

### 本轮实现

导出器使用源场景保存的完整树林矩阵／颜色，而不是镜头裁剪后压紧的可见段；排除独立深度副本，只取一份规范近景细节。不会改动正式生成器或源缓冲。海岛／海岸在同一缩放的四个方向均核对静态缓冲摘要；生成前后另核对生产输入和导出工具摘要。规范近景数据有意不继承当前镜头选择，原生 LOD 仍须按生产规则接上才能做同画质比较。

### 实机返修及证据边界

首轮资源报告超过 Node 默认输出缓冲，读取失败；原目录保留，读取有界提高至 16MiB。接着资源检查虽通过，人工审看发现世界空白，未据此过关。原因是直接照搬了 Three 的深度比较：Filament 采用反向深度，普通 less/less-equal 必须映成 greater/greater-equal。对照固定版本的 [MaterialInstance](https://raw.githubusercontent.com/google/filament/v1.56.0/android/filament-android/src/main/java/com/google/android/filament/MaterialInstance.java) 后修正，补全部比较规则的正反深度反例。设备脚本也增加实际 Surface 区域的空白、可见更新和旋转检查，不再只看状态文字或整张 PNG 摘要。

修复后两场景已审看实际更新前后图片，树、建筑和阴影可见，替换后仍可旋转。这不是生产色彩、AO、水／玻璃或日夜天气的视觉等价验收。更新所记毫秒只含校验和上传提交，不是显示延迟，更不是完整汇报或 App 启动收益。

### 阴影条纹与色彩返修

首轮 OnePlus 单变量开关证明操作确实生效，但人工审看发现地面有大面积阴影条纹，未算阴影表现通过。核对源 shader 和固定版 [Filament ShadowOptions](https://raw.githubusercontent.com/google/filament/v1.56.0/android/filament-android/src/main/java/com/google/android/filament/LightManager.java) 后，发现两边偏移量单位不同：Three 对正交深度用归一化 bias，Filament 的 constantBias 用世界单位。按实际 near／far 将 `-bias × (far-near)` 转换，海岛约 0.657、海岸约 1.090，替换此前 0.001 的默认值；其余条件不变。两场景重新开关对照，已审看条纹消除、建筑／树的投影仍保留。[首轮](../../artifacts/experiments/v3.0.0/p1-light-surface-device-first/report.json)、[偏移修复](../../artifacts/experiments/v3.0.0/p1-shadow-bias-device-first/report.json)。滤波、接触关系与更多太阳角度仍须继续验收，不能把“有变化”当作正确。

两套引擎的 ACES 也不是同一公式，原生内置 ACES 的画面仍偏暗。改为线性 HDR 渲染目标＋源 Three ACES fit／sRGB 终端 pass，保留相应 MIT 许可；不靠再加一个经验亮度系数掩盖差异。OnePlus 上 64 块 HDR 色卡确实经过原生目标和终端材质，与当前 Three shader 的结果比较，8 位 RGB 最大误差为 1，平均最大通道差约 0.203；正常退出后目标／pass 和引擎释放。[实际色彩检查](../../artifacts/experiments/v3.0.0/p1-color-device-second/report.json)。这不是整个世界、夜间反射或源 bloom 已等价。

- [容量四项](../../artifacts/experiments/v3.0.0/p2-finish-20261023/capacity-owned-first/report.json)实际处理 17,273,745 bytes、20,024 条历史记录，完成导入、完整导出、每日合并与回滚；整条大数据检查约 146.6 秒，不能说大存档已足够快。另验证 100 MiB+1 输入、引用展开超 512 MiB 被拒绝且原状态保留，以及重复／旧截止票据。边界拒绝通过不代表任意有效最大存档都能放进该机 256 MiB Java 堆。
- 容量返验确实暴露了两处实现问题：`CursorWindow` 无法容纳较大的单行文本；拼回完整文档时又做了不必要的整树复制。前者在同一 SQLite 事务里改走标量读取，不截断、不提高系统窗口；4.5 MB Unicode 文本、空值、长整数、浮点、别名与顺序已实测。后者让解码器交出独占的新树，仍完整校验并只保留不可变规范文本；同时不为超预算存档先建立一份必然会丢弃的缓存证明。没有减小两万条样本、提高堆上限或主动 GC 换通过。原 `capacity-second`、`capacity-scalar-first` 等失败保留。
- 校验复用以事务内读到的真实行、资产、恢复字段和元数据为依据，不只相信 revision。证明与规范文档各限 1M 字符，大输入不驻留；同连接篡改、另一连接写入、回滚及恢复块损坏均有反例。它没有把数据损坏变成首次创建任务。
