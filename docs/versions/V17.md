# V17 Work Packet

Status: released as `v1.3.1` (`versionCode 17`) on 2026-08-14; release gates and published-artifact verification passed.

V17 strengthens the daily work loop around the existing local-first settlement: returning to the next useful action should be immediate, the world should remember what a building represents, and statistics should explain rhythm without turning focus into a score. Resource-pack importing must remain bounded while accepting current 16x pack layouts on Android.

## Data and compatibility

- No domain schema change is required for V17. Continuity uses the existing process-local round-plan draft and persisted active focus session; building memory and statistics are projections.
- Resource-pack manifests and backups remain schema-compatible. Native chunk files live only in the app cache and are released after import; they are never backup data.
- Existing task deletion, habit-building retention, focus timing, and notification best-effort contracts remain authoritative.

## Non-goals

- Do not add cloud sync, accounts, social comparisons, streak punishment, manual building journals, or a second timer state machine.
- Do not replace the Three.js renderer or introduce a permanent render loop for the building memory view.
- Do not raise resource-pack limits without a measured memory budget; a larger file count is not permission to accept unbounded ZIP expansion or arbitrary file sizes.
- Do not bump the public version or publish a Release during ordinary V17 implementation. The accumulated V17 scope was explicitly approved and released as `v1.3.1`.

## Acceptance

- A navigation/lifecycle round trip returns to the same unfinished focus context, while explicit cancellation and process death clear the draft.
- Building memory is readable in a single compact panel, names the blueprint and current construction stage, and remains correct for finite, habit, paused, and monument projects.
- Statistics make effective minutes and recent rhythm scannable on narrow and tall screens without replacing the heatmap or introducing shame-oriented language.
- Resource-pack imports report precise size/file-count errors; the two reported Android packs pass the parser/bridge path on the signed candidate without clearing existing user data.
- Fast checks run once at the completed feature checkpoint. Device installation is blocked unless the candidate SHA-256 matches at every boundary.

## Risks

- More statistics can make the screen feel like a dashboard; the first viewport must keep the heatmap and a small number of explanatory metrics primary.
- Cache-backed chunk transport adds an asynchronous native round trip per 256 KiB; the bound prevents bridge stack overflow while keeping worst-case bridge calls bounded.
- Derived building memory may expose stale or deleted-task states; it must use the same validated projections as the world and never resurrect deleted tasks.
