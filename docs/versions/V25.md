# V25 / 开发工作包

> 状态：已于 2026-09-02 正式发布为 `v1.10.0`；提交 `5117364b7ff435a51b090ff07f601e3326998a28`，最终结果以 GitHub Release 和 `artifacts/release/v1.10.0/release-evidence.json` 为准
> 建立日期：2026-08-31
> 版本号：`1.10.0` / versionCode `25`

## 已确认范围

- 修复并验证 V24 遗留 BUG。
- 修复海洋小岛周边的天空可见空洞/接缝，并补齐确定性几何回归。
- 修复普通大型任务创建、追加小任务和名称编辑中的中文 IME 组合文本丢失。
- 收敛 CSS，结束按版本向覆盖文件追加规则的维护方式。
- 拆分 `apps/web/src/App.tsx` 的主要功能组件。
- 落成“建筑记忆”，让聚落建筑成为返回任务的入口。
- 修复海洋主岛建筑融合、树木碰撞和矩形岸线，并补齐混合 LOD 侧面连续性。
- 把世界坐标诊断改为设置中的本地持久化开关。
- 建筑记忆移出世界裁切容器，适配竖屏、短横屏与桌面。
- 保留建筑记忆打开、关闭和任务切换前后的世界视角，把重置操作留给用户。
- 修正深色当前任务状态条、专注保护提示位置，并为习惯任务补齐隔离的按结束时间计划。
- 调研并接入 OnePlus/ColorOS 可承载的 Android 标准后台休息倒计时，同时保留厂商直连的准入边界。
- 根据 OnePlus 真机流体云结果收敛通知内容与生命周期更新，并把沉浸计时面板升级为可调通透度的单层自适应毛玻璃。

## 明确不做

- 不做 P3 Android 专项适配或全原生迁移。
- 不增加新的世界环境或 Shader；允许在既有海洋小岛环境中修正派生地形。
- 不增加账号、云同步、后端或新的持久化 schema。
- 不新增独立的首页“继续上次计划”浮层。
- 不实现需要厂商准入的 OPPO 流体云直连接口，也不承诺 OnePlus 胶囊的摄像头两侧精确排版；标准 Android Live Update 纳入 V25。
- 开发与验收阶段不发布、不改版本号、不创建 tag；用户已于 2026-09-02 明确授权本轮进入正式发布阶段。

## 需求与验收

### BUG-25-01：V24 遗留回归

- V24 马拉松结算只呈现当前计划产生的真实轮次，不出现虚空轮次或“自动推进”错误文案。
- 系统手势产生 `pointercancel`、`lostpointercapture` 或遗留指针时，世界交互状态必须恢复，云和环境动画不因交互标志卡死。
- V23/V24 已知专注回归能力测试保持通过；新发现的问题必须先形成稳定复现，再修改生产行为。

验收证据：能力级 Playwright 回归、相关单元测试、V25 最终稳定 Web 回归。

### BUG-25-02：海洋小岛无空洞

- 先用几何覆盖或渲染探针稳定复现，再修改海洋地形生成；不能把既有注释当成已修复证据。
- 主岛、卫星小岛及其与背景海面的格网边界不得出现天空可见漏面、未覆盖带或错位接缝。
- 修复不得破坏建筑/道路支撑、开放海峡、海洋包围范围和既有三角形预算的产品约束。
- 2/4/32 单位混合 LOD 的垂直侧面必须按实际发出网格逐段闭合；大聚落远坐标带也不得以按距离猜测邻居尺寸的方式生成侧面。

验收证据：确定性体素几何回归、海洋环境能力 E2E 和代表性视角截图复核。

### TERRAIN-25-01：主岛构图与建筑融合

- 主岛视觉由世界种子决定非对称岸线、偏置山脊、缓坡台地、岩质岬角和内凹海湾，不复制自然山谷外观，也不保留统一圆形/方形建筑平台。
- 自然山谷只提供建筑/道路支撑高度的融合机制；融合范围限于实际占地附近，树木不得进入建筑足迹。
- 海洋建筑不得以随机层数下沉到岛面以下；地基底面至少落在可居住台地基准，局部支撑再与周围坡面衔接。
- 主岛岸线不得进入会放大成方块的远海格网，也不得出现大块矩形外伸；岩石表现为外伸的受侵蚀岬角，沙滩表现为内凹海湾中的口袋沙滩，两者使用平滑、带种子扰动的过渡。
- 海峡、卫星岛数量、远海包围和三角形预算保持原产品约束。

验收证据：多种子与 9 栋建筑几何回归、白天/夜间海洋能力 E2E、五视口截图和真机旋转复核。

### WORLD-25-01：可关闭的世界坐标

- 设置提供“显示世界坐标”开关，开启后点按地形展示 `x / z / 高度`，关闭后立即停止显示并在刷新后保持。
- 旧偏好迁移时保持坐标开启，便于在同一正式候选上先定位问题、验收通过后再关闭；新用户默认关闭。
- 偏好只写入现有本地展示设置，不进入领域 schema、备份或版本迁移。

验收证据：坐标拾取设置能力 E2E、刷新持久化和真机开关复核。

### IME-25-01：任务文本提交完整性

- 新建普通大型任务并拆分小任务时，`中文+英文+中文`、`中文+空格+中文` 必须按输入原文保存。
- 已有大型任务追加中文小任务必须可提交并原样保存，不能只接受英文。
- 已有大型任务名称必须支持英文改中文、中文名称继续追加中文；勾选状态和最终持久化值都以原生输入框当前值为准。
- 同一输入边界覆盖小任务重命名；回车提交不得在输入法 composition 或 Android `keyCode=229` 期间误触发。
- 不新增持久化字段，不改领域命令语义；修复限定在输入捕获和提交边界。

验收证据：Android IME 事件序列能力 E2E、任务领域/持久化既有回归、手机输入与键盘复核。

### CSS-25-01：唯一来源与功能所有权

- `styles-overrides.css` 不再由应用入口加载，并从产品源中移除。
- 全局样式只负责 token、reset、应用外壳、安全区和跨功能基础规则；功能样式进入对应功能文件。
- 主题色优先通过语义 CSS 变量切换，不继续为每个版本复制成组暗色选择器。
- 新样式不使用版本号类名或版本号章节；除受控的浏览器兼容、降级和动画覆盖外不新增 `!important`。

验收证据：入口/选择器静态检查、Web 类型检查、能力级视觉 E2E 和构建。

### APP-25-01：`App.tsx` 拆分

- 应用外壳保留在 `App.tsx`；至少把统计、设置和世界/建筑记忆相关视图移出该文件。
- 拆分不改变 ApplicationService、领域命令、IndexedDB、计时恢复或 Capacitor 适配边界。
- 拆分后的组件使用显式 props，不读取新的隐式全局业务状态。

验收证据：类型检查、单元测试、核心导航与专注 smoke。

### MEMORY-25-01：建筑记忆

- 非专注状态下点击聚落建筑，打开可感知、可关闭的建筑记忆面板。
- 面板展示项目名称、任务状态、建筑蓝图、建造进度、施工阶段、保存状况、累计有效专注、有效完成轮次、最近一次有效专注和下一项未完成小任务（如适用）。
- 当前项目提供“继续专注”；可切换的暂停项目提供“继续这个任务”，成功后成为当前项目并回到正常工作台。
- 纪念建筑保持只读；正在专注、存在普通任务待汇报进度或领域拒绝切换时，不伪造成功，给出清晰反馈。
- 面板不遮挡主要安全区，移动端触控目标不少于 44px，不依赖 hover。
- 面板不得作为世界 `<figure>` 的后代：竖屏底边贴紧固定导航上沿，短横屏和桌面顶边贴紧标题栏下沿且右边贴屏幕；不得悬在无归属的中下区域、被世界裁切或横向越界。
- 点开建筑可以聚焦该建筑；关闭记忆、返回聚落或从面板继续其他任务时保留用户最后的目标点和缩放距离。只有用户主动点“重置视角”才恢复默认构图。

验收证据：组件/纯函数单测、建筑点选与切换能力 E2E、移动端和桌面截图检查。

### UI-25-01：工作台可读性与专注保护反馈

- 深色模式下当前小任务/习惯建筑左侧状态条使用深绿色按钮同色，与卡片背景保持清晰对比；浅色模式保持原绿色。
- 专注保护触发中断时只显示一个原因提示，不能与“开始专注”主按钮重叠，也不再叠加相同内容的全局 toast。

验收证据：深浅主题计算样式断言、专注保护中断布局 E2E。

### PLAN-25-01：习惯任务按结束时间安排

- 习惯任务的“调整”同时提供固定轮次和按结束时间，两者沿用同一时长/休息/截止时间计算口径。
- 习惯计划的每一轮正常完成或提前完成都直接推进当前习惯建筑；最后一轮结束后清理计划，不进入普通大型任务的统一进度汇报。
- 普通任务与习惯任务只共享时间计算和控件语义，不共享结算分支；不得把普通模式、马拉松汇报与习惯建筑推进耦合。
- 锁定计划后，工作台上下文、活动轮次和调整 Sheet 必须来自计划宿主，不得因当前项目切换、待汇报状态或习惯待选建筑而回显旧小任务。
- 每个按结束时间轮次都同时提供“中断本轮”和“提前完成本轮”：普通任务的提前完成只记录可供统一汇报的轮次，不自动推进任何小任务；习惯任务的提前完成推进当前习惯建筑并继续计划。

验收证据：Domain 正常/提前完成单测、轮次计划恢复单测、习惯按结束时间 E2E、既有普通马拉松回归。

### ANDROID-25-01：OnePlus/ColorOS 后台休息倒计时

- 首选路线是 Android 16 promoted ongoing live update：原生端以休息 `endsAt` 创建 ongoing countdown chronometer，系统负责后台逐秒刷新，WebView 不运行每秒定时器。
- Capacitor Local Notifications 继续负责休息结束的到点通知；新增边界清晰的 `BreakLiveUpdate` 原生插件表达 promoted ongoing、倒数 chronometer 和展开操作。可见 Live Update 使用 `42002`，到点提醒使用 `42003`：Capacitor 在排程同 ID 通知前会先移除可见通知，分离后才能避免生命周期刷新产生取消—重发闪烁；跳过或取消时仍同时清理两者。
- 紧凑态目标为系统可接受的 `mm:ss` 倒计时；摄像头左右分别固定分钟和秒不属于应用可控布局。展开态建议显示“休息中”、当前轮次/总轮次、下一任务、结束时刻和“跳过休息”。
- 流体云、状态栏 chip、锁屏和通知抽屉是同一条 promoted ongoing 通知在不同系统表面的呈现；不能保留流体云却隐藏其通知抽屉卡片。设置文案必须明确这一点，不能把它误报为两条重复通知。
- 对相同 `endsAt / 轮次 / 下一项` 的休息计划做幂等调度；应用切后台、上滑最近任务或重复生命周期事件不得主动取消并重发实时通知。
- OPPO/OnePlus 流体云直连是需要厂商支持列表或服务准入的增强路线，不能作为所有设备上的基础承诺；Android 标准能力作为可降级基线已经实现。
- 不能仅以 Android 版本判断 promotion 可用：原生插件读取通知格式资格、系统允许状态和最终 promotion flag；设置页在系统拒绝时显示降级原因并提供 Android 官方实时通知设置入口。

验收证据：Android 官方 Live Update/Notification API 与 ColorOS 官方流体云能力核对；TypeScript 适配测试、原生 Java 编译/JVM/Lint、debug APK、通知动作 E2E 已通过。OnePlus 已确认开启系统实时通知后胶囊和展开卡可见；去闪烁改动待下一候选真机复核。

调研来源：Android 官方 [Live Update 通知](https://developer.android.com/develop/ui/views/notifications/live-update?hl=zh-CN) 与 [Notification.Builder](https://developer.android.com/reference/android/app/Notification.Builder)，ColorOS 官方 [流体云能力说明](https://www.coloros.com/article/A00000075/)；OPPO 开放平台的厂商直连以实际应用准入结果为准。

### UI-25-02：沉浸计时自适应毛玻璃

- 沉浸计时只使用一层悬浮功能玻璃承载任务名、倒计时与结束操作；世界仍是内容层，不把每个内部控件再套一层玻璃。
- 浅色与深色主题分别使用半透明色调、背景模糊、饱和补偿、表面高光和环境投影；移除造成分层感的均匀亮描边与 inset 双高光。低透明度/高对比偏好下回退为更实的材料，保证文字可读。
- 设置“外观”提供 `0-100%` 的“沉浸计时毛玻璃”通透度滑杆，默认 `50%`，每 `5%` 一档并即时预览。`0%` 为 `0.96/0.94` 色调与 `30px` 扩散的 Frosted/Regular 端点，`100%` 为 `0.06/0.12` 色调与 `3px` 扩散的 Clear 端点；中间使用非线性曲线同时调整色调、扩散、饱和、亮度、高光与投影。值写入既有本地展示偏好，不进入领域 schema 或备份。
- 滑杆使用自绘 WebKit/Firefox 轨道与拇指，触摸按住时关闭 WebView 原生蓝色点击高亮、选中框与轨道换色，键盘 `focus-visible` 仍提供局部焦点提示。
- 毛玻璃只替换材料表现，不改变用户认可的原有几何：竖屏为贴住屏幕底边的全宽直边操作带，横屏为贴住屏幕右边的全高直边操作带；计时数字仍在面板中心，内容通过内边距避让安全区。
- 视觉审计后，世界 HUD、坐标/重置视角、建筑记忆、施工/完整性瞬时提示和 Toast 复用固定高可读性深色玻璃；普通任务卡、设置行、表单、顶栏和底部导航保持实底。固定玻璃不受沉浸面板滑杆影响，并响应系统减少透明度偏好。

验收证据：Apple 官方 Liquid Glass 材料/实现说明；Web 类型检查、33/33 单测、设置持久化/端点差异/滑杆按压态/沉浸样式能力 E2E，手机深色 `0/80/100%` 与浅色竖/横屏截图检查。Android WebView 真机触摸与视觉待新候选复核。

调研来源：Apple 官方 [Materials HIG](https://developer.apple.com/design/human-interface-guidelines/materials)、[Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/)、[Build a UIKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/284/) 与 [WWDC26 Platforms State of the Union](https://developer.apple.com/videos/play/wwdc2026/102/)；开源社区 [shuding/liquid-glass](https://github.com/shuding/liquid-glass)（MIT）用于实现审计。实现借鉴材质分层、低模糊 Clear 端点与平滑过渡原则，不声称 Web CSS 等同系统 `UIGlassEffect`；没有复制或分发该仓库源码，也没有新增运行时依赖。

## 数据与失败边界

- 建筑记忆是现有 `projects`、`focusHistory`、`worldProjection()` 和蓝图目录的只读派生，不写入新字段。
- 切换任务只调用现有 `SwitchActiveProject`；领域层继续裁决活动专注、待汇报轮次、纪念建筑和不存在项目等失败。
- 失败时保留当前项目和建筑选择，使用应用现有消息通道解释结果。
