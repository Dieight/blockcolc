# V26 / 开发工作包

> 状态：实现与真机反馈返修完成；用户已于 2026-09-05 授权正式发布，最终结果以 `v1.11.0` Git tag 与 `artifacts/release/v1.11.0/release-evidence.json` 为准
> 建立日期：2026-09-02
> 目标发布：`v1.11.0` / versionCode `26`；普通开发阶段不提前修改当前发布版本文件

## 版本主题

V26 只解决一个总问题：让“打开应用 → 回到世界 → 开始下一轮 → 安全恢复 → 交付新版本”更快、更确定。性能、测试和发布基础设施是主线；不为凑版本数量保留价值不足的新功能。

## 明确不做

- 不增加新的世界环境、Shader、光影档位或大规模视觉换肤。
- 不做账号、云同步、协作、截止日期、任务依赖或完整项目管理。
- 不做 Android 全原生迁移，不接入需要厂商准入的 ColorOS 私有流体云接口。
- 不扩大 Litematic、资源包或 Minecraft 方块兼容范围。
- 不把拆文件、提高 timeout 或减少测试数量本身当成性能/稳定性成果。

## 基线与目标

- 以 `v1.10.0` 和 PJX110 为用户设备基线，记录冷启动、首个非空世界帧、切回世界首绘、默认聚落重建、交互帧、PSS、温升和通知生命周期。
- 展示层切换的全屏加载反馈须在下一次浏览器绘制内出现；不允许源页面先卡住再显示加载页。
- 不改变世界快照、资源包、环境或渲染质量的展示操作不得增加世界重建计数。
- 参考发布机上 Web 完整门禁目标不高于 15 分钟，完整发布准备目标不高于 20 分钟；以连续三次完整运行无偶发失败为稳定证据。
- 生产首屏主入口 chunk 降到 500 kB 以下；Three.js 与主页面可保持独立 chunk，但计时、任务、统计和设置在冷启动时并行请求并完成挂载，避免每页第一次点击再次等待。

## 需求与验收

### PERF-26-01：启动、首帧与世界失效边界

- 在 Web 诊断和 Android 日志中记录 bootstrap、应用可操作、renderer 创建、首个非空帧与每次完整世界重建的时间戳/耗时。
- 建立稳定的 world-content key；只有世界投影、资源包、环境、地形版本或会改变网格/材质的质量设置变化时才重建。
- 打开设置、统计、建筑记忆、毛玻璃调节、坐标显示和瞬时提示不得重建地形。
- 冷启动并行加载主页面不得破坏离线运行、中文输入、返回路径或恢复中的活动专注。
- 四个主页面随冷启动完成初次模块加载和可用页面挂载；切换时只改变显示边界，不得重复执行页面级投影与挂载副作用。首屏、全部页面就绪和热切换分别计时。

验收：生产构建 chunk 报告、启动/重建诊断测试、五视口 smoke、PJX110 冷/热启动与返回世界测量。

### ARCH-26-01：可测试的渲染与地形边界

- 从 renderer 编排中提取指针所有权/陈旧释放与帧请求调度，使假时钟可验证 pointercancel、lost capture、长帧和无关 pointerId。
- 将海洋、自然山谷、经典空岛的生成参数与共享网格发射/LOD 邻接边界分离；环境切换不复制网格闭合算法。
- `App.tsx` 只继续承载应用壳和跨功能编排；提取必须以状态所有权清晰、单元测试可覆盖为依据。

验收：新增纯单元测试、现有地形扩展扫描、渲染能力 E2E 与诊断计数不回退。

### TEST-26-01：完整但更快的发布门禁

- 将稳定 Web 回归按核心业务、渲染/资源包、响应式视觉分类；核心业务可安全并行，持有软件 WebGL/设备所有权的流程保持单 worker。
- 不验证创建/导入本身的长流程允许使用严格校验的 IndexedDB 状态工厂；每个真实入口仍至少保留一条端到端契约。
- 发布脚本必须收集所有套件最终退出码、测试数量、跳过原因和耗时，任一套件失败或无最终报告即失败。
- 不允许用不同源码树、不同测试树或失败运行的局部结果拼接正式发布证据。

验收：连续三次完整 Web 门禁、合并机器报告、慢用例排行和完整发布准备计时。

### RELEASE-26-01：不可变候选与可恢复发布

- `Prepare-Release` 从冻结源码运行完整门禁并生成唯一正式候选、源码树指纹、测试指纹和 APK 元数据/签名/SHA-256。
- 真机安装是独立可恢复阶段；设备忙时在安装前停止，不丢弃同一树上已通过的门禁和候选。
- 用户确认必须绑定候选 SHA-256 与源码指纹；生产代码、依赖、构建配置或生成资产变化会自动使确认失效。
- `Publish-Release` 只允许上传已安装、已确认的同一候选，不重新构建；上传、重下载和最终安装逐边界比较哈希。
- 发布前自动检查当前工作包不存在未完成需求；最终提交、CI、Release URL 和哈希写入机器证据，工作包不再使用会在发布后漂移的临时状态措辞。

验收：PowerShell 脚本契约检查、忙碌设备恢复演练、篡改候选/源码负例以及一次完整候选演练。

### RECOVERY-26-01：Android 恢复与 Live Update 生命周期

- 覆盖前台、后台、锁屏、最近任务上滑、可恢复进程回收、休息跳过、通知点击和系统拒绝 promotion。
- 相同休息计划的重复生命周期事件不得取消并重发 Live Update；计划变化只更新已有通知，到点提醒继续使用独立 ID。
- 系统强制停止或 OEM 限制导致通知无法投递时不伪造成功；重新打开后按持久化 `endsAt` 恢复或结算。

验收：Capacitor/JVM 测试、ADB 通知与进程矩阵、PJX110 流体云/通知抽屉人工复核。

### TODAY-26-01：今日下一步（真机验收后撤回）

- 验收结论：与现有按结束时间的马拉松模式目标重叠，却要求额外挑选、排序并限制为三项；样式修补不能解决价值和步骤数量问题。
- 从 UI、应用命令、领域模型、备份真相和稳定测试清单中完整移除，不留下隐藏入口或僵尸数据写入。
- 已安装 V26 测试版可能写入 schema 10 的 `todayNextSteps`。读取时只定点剥离这个已知字段，保留任务、专注、进度、建筑和设置；其他未知字段仍严格拒绝。

验收：回滚后类型/领域/存储测试通过，兼容导入覆盖旧测试字段剥离，UI 与发布清单不存在入口。

### ACCEPT-26-02：真机反馈修复

- 建筑观察目标与记忆弹窗分离；关闭/继续不重置，用户可显式“重置地图”返回完整聚落。
- 海洋建筑、道路、支撑融合和路灯共用可居住台地高度，不能在抬高建筑后继续按旧地形高度开槽。
- 马拉松汇报的每个习惯任务默认 `0` 轮，展开卡片不得自动分配。

### ACCEPT-26-03：马拉松时间一致性与专注流体云

- 习惯任务的马拉松排程、启动倒计时、剩余总时长和说明统一使用普通任务专注分钟；固定习惯轮次仍使用习惯任务专注分钟。
- 取消或自然结束马拉松必须同时退出本地结束时间模式；计时页回到当前普通/习惯任务自己的默认一轮时长。
- 活动专注使用 Android 系统 chronometer 常驻剩余时间，折叠态统一使用短文案“专注中”，展开态再区分普通/马拉松并显示项目、当前工作和像素建造语义；公开计时器通知提供标准锁屏/息屏剩余时间字段，小图标使用纯白镂空番茄且禁止 OxygenOS 换回应用图标。同一计时器恢复不重发，新计时器采用新的通知 tag 以刷新 OEM 息屏缓存，专注与休息的清理互不误伤。PJX110 已确认通知栏倒计时、息屏新图标与专注/休息状态正确，但厂商息屏模板仍忽略标准 chronometer；记录为 OEM 降级，不在后台逐秒重发通知伪造倒计时。
- 原生层把 pause/resume、窗口焦点、多窗口和 OEM 小窗合并为一个注意力状态机；通知栏停留与真正后台往返都只记一次，且 foreground 不得重写 background 时间戳。结算新增有效离开时，由生命周期回执直接触发既有 V19 世界内五秒警示片“有效离开 X / Y 次”，不另加全局 Toast。

验收：普通/习惯分钟不同的 Playwright 回归、取消计划回退回归、应用/Capacitor/JVM 测试，以及 PJX110 前台、后台、息屏、展开卡和专注到休息切换人工复核。

## 数据与失败边界

- V26 不新增发布产品字段。schema 10 保留用于兼容已经安装的短期测试版；解析器会移除其中已撤回的 `todayNextSteps`，但不迁移或改写既有任务进度、专注历史、每日目标、建筑完成度或状况。
- 启动/性能诊断属于瞬时或机器证据，不进入用户备份。
- 发布候选确认属于本地发布证据，不进入应用运行时和用户数据。
- 任一引用无效、状态禁止切换或恢复数据不可信时保持当前任务/计划不变，并向用户说明可操作的恢复方式。

## 实施顺序

1. 关闭 V25 工作包，建立 V26 产品事实、工作包和 `v1.10.0` 性能/发布基线。
2. 重构发布证据状态机，使门禁、构建、安装、确认和上传可以在同一不可变候选上推进。
3. 分类 Web 稳定套件、引入合并报告和耗时排行，再优化状态工厂与安全并行。
4. 建立启动/重建诊断并处理主页面冷启动并行加载、世界 content key 和不必要重建。
5. 提取渲染输入/调度及地形边界，保持现有视觉结果和几何预算。
6. 完成 Android 恢复矩阵。
7. 根据真机反馈撤回“今日下一步”，修复热切换、建筑观察、海洋道路/光源和马拉松汇报，再生成受影响测试版；用户确认发布后才跑最新树完整门禁。

## 第三方候选审计

- Morphicons（MIT，审查 `38d2a7221633a453eeafebd872ee3649b9274b22`）可用于同一个图标控件在两个状态间的短促语义变化，并提供 React 绑定、共享 RAF 和 opt-in 的减少动态效果策略。
- V26 不接入：当前依赖是 `lucide-react` 组件，Morphicons 需要额外的 `lucide` 数据入口；现有展开/收起已用单个 Chevron 的 CSS 变换完成，其余图标不是同一控件的两个状态。约 8.5 kB gzip 的 React 运行时和逐帧 path 计算没有足够产品收益。
